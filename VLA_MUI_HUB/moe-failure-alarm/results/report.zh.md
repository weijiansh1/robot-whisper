# HB-MoE 失败报警器：全轨迹离线回放

## 结论

报警器已在全部 `36098` 条轨迹、`574717` 个 query 上完成逐步回放；主观察性评估含 `34560` 条轨迹和 `1403` 条物理失败。每个 query 只使用当前及历史 HB 路由。

在成功校准目标 5% 下，测试成功轨迹实际误报率为 `4.7%`（95% Wilson CI `4.5%`–`4.9%`），失败召回为 `27.3%`（CI `25.0%`–`29.7%`），precision 为 `19.7%`。episode 最大风险分数的 AUC 为 `0.821`。

只看轨迹是否超过同 run 成功时长阈值的同误报预算基线，误报率 `2.8%`、失败召回 `100.0%`、全局长度 AUC `0.950`。它之所以近乎完美，是因为 `1403/1403` 个自然失败都运行到各 source run 的最大 horizon，而成功只有 `127/33157` 到达该 horizon。

## 报警规则

固定使用五个低值风险信号：后层 L12–15 全动作 token 的相邻 query Top-4 churn、后层 T6–T10 churn、前层 L2–5 churn、后层动作 entropy、前层动作 entropy。前三个 query 做因果滚动均值，再在同 run、同初态、同绝对 query 的参考成功轨迹中转换为 lower-tail percentile，五项等权平均。风险连续两个 query 越线才报警。

每个测试 seed-fold 使用三个完全不同的 seed-fold 建参考分布、另一个 fold 的成功轨迹定阈值；失败标签不参与权重、参考分布或阈值拟合。若同初态参考成功少于 3 条，回退到同 run/同 query；少于 20 条则该 query 不报警。

各 run、各折的 5% MoE 阈值中位数为 `0.880`，10%–90% 范围 `0.767`–`0.967`。

## 报警时间

在被 MoE 捕获的失败中，首次报警 query 中位数为 `11.0`（当时约已执行 `110` 个动作），回看 episode 相位中位数 `0.429`，到记录终点尚余 query 中位数 `14.0`。全部失败中，在半程前报警 `18.9%`，四分之三程前报警 `26.4%`，至少提前 3 个 query 报警 `27.3%`。

同 run 时长警报捕获全部失败，但首报相位中位数为 `0.667`、尚余 query 中位数 `9.0`。MoE 在 `382` 条失败上更早触发，提前量中位数 `5.0` 个 query。因此合理部署是把 MoE 当作可恢复的早期黄色预警，把时长阈值当作较晚的红色警报。所有相位和剩余量只用于离线评价，不进入在线分数。

## 解释边界

- 这是对同一批发现数据的交叉回放，不是新采集任务上的独立外部验证；特征方向来自先前的 1442 条失败分析，因此性能仍可能乐观。
- 报警表示路由进入与历史失败相关的低变化/高集中状态，不等于已证明 MoE 导致物理失败，也不能区分停滞、摆动或周期。
- 全局失败率较低，因此即使误报约 5%，precision 也可能有限；线上使用应触发降速、额外观察或重规划，而不是直接中止任务。
- 该原型需要同任务/source run 的成功校准轨迹；新任务冷启动时不能直接套用这里的阈值。
- 不在成功参考轨迹支持范围内的 query 不会报警；这避免利用“成功都已结束”这一未来长度泄漏，但会降低末期召回。
- `pin-base`、`pin-on/off` 和 `pin-smoke` 全部做了离线回放，但不进入主自然轨迹指标。
