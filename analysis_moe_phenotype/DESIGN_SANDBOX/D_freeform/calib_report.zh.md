## 0. 四句话结论

0. **口径先行（本轮最重要的一条）**：加入平凡集长臂 **T**（一级信号 = 集内 query 序号 `q`
   本身，完全不读 MoE）后实测，在"**全集任意时刻**"口径下 T 拿到
   **loop 检出 1.000 / static 1.000 / 无事件失败 1.000，实测 FA 只有 0.106（main）/ 0.171（grid）**
   —— 它把每一个活到 q=39/40 的集全部报掉。**因此本报告不主张任何"全集任意时刻"的
   绝对检出率数字**。载荷口径改为两个把"钟"完全剥掉的口径：
   - **匹配视界 margin**（同一绝对 q 上比较存活集）：任何纯 q 报警器构造性地恒为 0。
     实测 T 在两个单位、六个 q 上**全部 = 0.000**；主臂 0.747/0.552、臂 P **0.811/0.738**、C 0.757/0.538。
   - **前缀口径**（只认 step ≤ 36 的报警）：T 检出 **0.000 / 0.000**（FA 也是 0.000），完全无信息；
     主臂/臂 P/C 在此窗内照常工作。
   我的 `q_hi=40` 弃权规则**没有**挡住钟（T 就在 q=39/40 处响），挡住钟的是上面这两个口径。
1. **主臂（只用 `rows.npz` 的 8 个表型信号）打不过消融臂 C（`mob1_w8`）。**
   在同一实测误报率、同一前缀窗下，两个单位上 loop 通道的配对差都不显著、grid 上还是负的；
   static 通道 C 明显更好（main16x32 前缀 36：主臂 −0.331/−0.218，p≈0）。
   **如实记录：这是本轮最大的负结果。**
2. **把 E5 的"偏离健康流形" `d_healthy` 加进 loop 模板（臂 P）之后局面翻转，且在两个口径下都成立**：
   loop 通道配对差 任意时刻 **+0.333 / +0.386**、前缀 36 **+0.333 / +0.404**（p=.004 / 2e-5），
   static 通道打平。匹配视界 margin 也是 P > C（0.811 vs 0.757；0.738 vs 0.538）。
   **loop 与 static 的判别力由两条**不同**的信号承载：loop = 离开流形（`d_healthy`），
   static = 停在流形上不动（`mob1_w8` / `min_mobk`）。** 两个 SCENE8 单位复现，是本方案最值得带走的东西。
3. **分型（宏平均/平衡准确率）**：主臂 0.765 / 0.733，臂 P 0.715 / **0.892**，
   消融臂 C 0.561 / 0.679，平凡臂 T **0.500**（构造性）。
   loop 一类的召回：主臂 .59/.47、P **.69/.80**、C 只有 .24/.39——因为 loop 与 static 事件的
   `mob1_w8` **同号**（两者 onset 前都发粘），单信号只能靠幅度分型，不能靠方向。
   （微平均具误导性：恒判 static 的常数分类器微平均就有 0.826/0.805，高于 C 的 0.795/0.840。）

## 7. 恢复性 vs 致败（"能否离开"）——**功效严重不足，只能描述**

## 9. 补充：相位通道的独立自查（`phase_probe.py` / `phase_probe.json`）

任务书要求"d_healthy 只在单单位成立，你要在两个 SCENE8 单位上自己验"。我用与主臂

|---|---|---|

| `v̂>0` 比例：失败 vs 慢成功 组内 AUC | 0.034（=失败远低） | 0.062 |

**读法（重要）**：E5 报的是"d_healthy 在 main 单单位、对**全部失败**、在固定时点 t=20/25/30"

**新的一点是把失败按事件类型拆开**：`d_healthy` 的判别力几乎全部集中在 **loop** 失败上
（0.984 / 0.963，两单位），在 static 失败上几乎没有（0.60 / 0.60）。
E5 把两类失败混在一起统计，所以这条腿被稀释成"单单位、勉强显著"。

它需要参照集的**总长** `n_q` 来做进度归一化，在线不可得，且会引入集长泄漏。

## 10. 失败模式清单（诚实条款）

1. **主臂打不过基线**（§3.2）。这是最大的负结果，已在 §0 与 SPEC §0.4 顶格写明。
2. **static 通道近乎同义反复**：static 事件的物理定义是"机器人不动"，`mob1_w8`/`min_mobk`
   是"表示不动"。任何结构在这条腿上的差异都被这个近同义关系压平（§5、§8）。
3. **static 报警锁事件不锁结局**：4/4 个"成功 + static 事件"的集被全部三个臂报警（§7）。
4. **q_hi=40 的覆盖天花板**：loop onset 中位 41/44 已在可评窗之外。留出集上
   goal/object/spatial 的集长中位只有 8–13，**可评窗可能整体为空**，届时检测器对整个任务弃权。
   这是必须先报覆盖率再报检出率的原因。
5. **臂 P 的构造有校准集内的结构选择**：`d_healthy` 的方向来自 E5（预先存在），
   但"只加进 loop 模板"是我看到 loop/static 分离之后决定的。留出集上必须当作**待验假设**读，
   不是预注册结论。
6. **恢复性 loop n=2/4**：任何"能区分暂时错误与真 Trap"的说法在本校准集上都没有功效（§7）。
7. **`persist` 与集长混杂**：可判率仅 40%，可判子集实为"慢成功 vs 失败"（§7）。
8. **组心化在失败富集组是保守偏差**：`delta` 用无标签中位，组内失败越多越难报警；
   成功集 <2 的组（main 1/16、grid ~10/50）直接不心化。
9. **阈值的自含偏差**：θ 由 R_g 集自身的分数分位算出（R_g 的中位里含这些集自己的行），
   偏差方向是把 θ 压低一点 ⇒ 实测 FA 略高于名义 α（main .144 vs .100）。
   **保守方向，如实报，不修正。**
10. **红旗任务**：AUDIT §7.1/§8.4 的 `KITCHEN_SCENE3` 与 `open_the_middle_drawer`
    loop 通道无效，留出集执行时须在评分侧剔除其 loop 判定（检测器自己不知道）。
11. **本方案未走 E7 任务流形通道**：E7 的判别结果覆盖留出集任务、不能作为调参依据；
    且它需要**跨任务**的成功集在线作参照（要同时持有 9 个别的任务的流形），
    在线可行性远差于只需同任务成功集的相位通道。
