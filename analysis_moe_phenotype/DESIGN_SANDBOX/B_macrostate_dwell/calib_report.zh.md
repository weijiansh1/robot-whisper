## 1. 可比性块（与方案 A 对齐；定义逐字按 CONSTRAINTS §必报指标）

- **每集误报率 FA** = **干净成功集**（`loop_onset_q<0` 且 `static_onset_q<0` 的成功集）中
  该通道**整集至少报一次**的比例。分母 main 291 / grid 257。
- **检出率** = 致败事件集（`success==0` 且该类 onset≥0，含双事件集）中该通道至少报一次的比例。
  分母 loop main 55 / grid 62；static main 143 / grid 69。
- **pre-onset 检出率** = 同分母，分子额外要求该通道**首次**报警 `step ≤ onset_q`。
- **提前量** = `首次报警 step − onset_q`，只在已报警集上统计，报 q25/中位/q75，**负=早**。
- **恢复性** = 成功集里的瞬态事件（loop：main 2 / grid 4；static：main 3 / grid 1）。
- 两语料**各自独立报**。组 = `scene`(=init_state)；旋钮 LOGO，组 = `corpus|scene`（66 折）。
- 通道判定用**完整 alarms 序列**中该通道的首条，两通道互不抑制
  （「先误发 loop、后正确发 static」的集在 static 通道上仍算检出）。

> **Δ 同时包含召回差与工作点差**。但方向对 B 不利：**B 的实际 FA 比 C 低 1.6–2.7 倍**
> （B 更严），因此 Δpre 在 B 这一侧是**保守**的；ΔFA 若被补齐只会让 Δpre 更大。

**读法**：`mob1_w8` 只有在机器人**真的停下来之后**才升，所以 C 几乎必然检出（94–97%）
但几乎从不在 onset 之前（1.4%–5.8%）。`inst=0 & cons=1` 在停之前就成立。
**B 的 static 通道把 25%–42% 的致败 static 集从「事后确认」变成「事前报警」，
而这些集 C 一个都没提前抓到（不一致对 37:1 / 33:4）。**
代价是 B 漏掉了 C 能抓到的一大批（Δdet −0.41 ~ −0.57）。
**两臂互补，不是一个替代另一个。**

### 5.4 E8 零结果的诊断：两条原因，都可定量

**原因 1（决定性）：E8 测的量不是「带驻留」。**
E8 的族是 32 态**自转移概率差** `P_fail(s→s) − P_succ(s→s)`，即「五轴宏状态一步不变」。
本报告的 `state5` 是它的集级对应量：主族 AUC **0.526 / 0.650**，main 的未校正 p 都到 0.487。
**E8 的零结果被原样重现，而且更彻底。**
把「不变」放宽成「留在同一条二轴带内」（态可以在 8 个态之间跳），AUC 升到 0.76 / 0.79（static）
与 0.72 / 0.69（loop）。**五轴合取太细，把同一条带内部的游走误判成「离开」。**

**原因 2（可量化）：maxT 族被小 n 格拖垮。**
我在自己的 6 格族里故意复刻了 E8 的结构缺陷——放进一格 `n_pairs=25 / 9` 的恢复性 loop 对比。
把这一格移出（其余 5 格、同 seed、同程序，严格匹配口径）：

| 格 | 6 格族 p_maxT（main / grid） | **5 格族 p_maxT（main / grid）** |
|---|---|---|
| `switch`：致败 loop vs 干净 | 0.071 / 0.060 | **0.0005 / 0.0045** |
| `flatten`：致败 static vs 干净 | 0.101 / 0.107 | **0.0010 / 0.0120** |
| `sticky`(C)：致败 static vs 干净 | 0.004 / 0.011 | 0.0005 / 0.0005 |
| `state5` | 0.853 / 0.595 | 0.637 / 0.369（**仍零**） |

**一格 n_pairs=9 的格，把同族其余所有格的 p 抬高一到两个数量级。**
E8 的族里有 `n_groups` 低到 2、3、4 的格与 `n_groups=56` 的格并列共用一个 maxT 阈值——
同样的机制会以同样的方式吞掉功效。E8 自己写过「这不是『失败不粘』，而是『组级驻留差
在本设计下没有功效』」，**本节给了这句话定量支持**。注意 `state5` 在 5 格族里**依然零**，
所以原因 1 和原因 2 是可分离的：族构成解释了「为什么连有信号的格也不显著」，
测错量解释了「为什么 E8 的那个量本来就没信号」。

**必须打的折**：我的检验和 E8 的检验**不是同一个检验**。E8 的置换单位是**组**
（组级 sign-flip，2–69 组）；我的是**集**（组内置换，400–512 集），功效高得多。
所以「E8 零结果 ≠ 无信号」这个结论里有一部分功劳属于置换单位的改变，不能全记在带定义头上。
要严格分离得在同一置换单位下重跑两种量——本轮没做。

### 5.5 带定义诊断（描述性；**没有据此改交付规格**）

曝光严格匹配子群的组内配对 AUC（致败 static vs 干净成功；`fig` 面板 F）：

| 带 | main | grid |
|---|---:|---:|
| `sticky = stick=1`（单轴 = 臂 C） | **0.861** | **0.853** |
| `cons=1`（单轴，高共识） | 0.834 | 0.838 |
| **`flatten = inst0 & cons1`（交付）** | 0.716 | 0.728 |
| `inst=0`（单轴，低波动） | 0.588 | 0.625 |
| `state5`（五轴同态） | 0.531 | 0.684 |

**两轴合取是净损失**：`cons=1` 单轴（0.834/0.838）明显强于 `flatten` 合取（0.716/0.728），
`inst=0` 那条腿在稀释信号。loop 侧同样：`state2`（inst×cons 象限同态）0.780/0.740 与
`inst=1` 单轴 0.697/0.753 都不输给 `switch` 0.736/0.753。
**按要求我没有把带换成 `cons=1`** —— 那是「为了好看重新划带」，明确禁止。
留给下一轮：若要改，必须重新在成功集上冻结并说明依据只来自成功集。

**驻留 vs 占用（曝光归一，截断口径）**：

| | 占用率 occ | 最大连续驻留 maxrun |
|---|---|---|
| `flatten`，致败 static vs 干净 | **0.856 / 0.881** | 0.761 / 0.794 |
| `switch`，致败 loop vs 干净 | 0.619 / 0.631 | **0.719 / 0.695** |

**「连续性」只在 loop 通道上有净贡献；在 static 通道上占用率比驻留还好。**
也就是说 static 通道其实可以退化成「带占用率阈值」，**「驻留」在那条通道上是多余的复杂度**——
而它唯一有价值的那条通道（loop）操作上不可用。这是本方案设计层面最尴尬的一条。

## 7. 恢复性 vs 致败（「能否离开」的直接兑现）

**loop（正面）**——6 个恢复性 loop 的曝光截断 `switch` 带最大连续驻留：

| 单位 | 恢复性 loop 的 maxrun_switch | 干净成功集 p50/p75/p90 | 致败 loop 中位 | **loop 通道报警** | 臂 C | 臂 T |
|---|---|---|---|---|---|---|
| main（n=2） | **5, 3** | 5 / 7 / 9 | 7 | **0/2** | 1/2 | 2/2 |
| grid（n=4） | **4, 3, 5, 6** | 5 / 6 / 9 | 8 | **0/4** | 1/4 | 3/4 |

6 个恢复性 loop 的最大连续驻留全部 ≤6，**离 `K_LOOP=11` 还差得远**，尽管它们的集长
（38–50 query）明显长于干净成功集（中位 39）——**曝光更多、驻留反而不长**。
这正是 E4/E8「差别在能否离开」的兑现：瞬态 loop 进带即出。

**但功效不足是硬的**：n=2+4=6。§5.1 那格 main AUC 0.900 (p=0.001, n_pairs=25)、
grid 0.722 (p=0.102, n_pairs=9)，**只有一个单位显著，按描述性对待**。
CONSTRAINTS 允许用 objaware 层同任务补充——SCENE8 两语料的事件层本来就是 `full`，
同任务没有 objaware 版本可补，**在不碰留出集的前提下无法增加样本**。

**static（负面）**——4 个成功集里的瞬态 static：`maxrun_flatten` = 10, 10, 9（main）/ 5（grid），
M=9 ⇒ **报警 3/4**（main 3/3、grid 0/1）。
**static 通道对「停住后能否恢复」没有判别力。** 这与 E8 §3.2(b)「stick 抬升锁事件不锁结局」
是同一个毛病，换轴没换掉。下游把 static 报警接到「重采 flow 噪声」，误干预一个本来会自己
恢复的集，代价大概率可接受；但**不能宣称 static 通道预测的是失败，它预测的是「停」**。

## 9. 弱点清单（按严重程度）

1. **loop 通道打不过只看集长的平凡臂 T**（§4）。本方案最大的失败。校准集里失败几乎等价
   于超时，任何在晚期才积满驻留的规则都被这条捷径覆盖。
2. **static 通道不是新信号**：在 grid 上对 `mob1_w8` 驻留做组内秩残差后 AUC 掉到 0.566
   （未校正 p=0.43，§5.3）。它相对臂 C 的**唯一净增量是时机**（§3.1），不是内容。
3. **static 的「提前量 −7」有一大半是标签自带的**：物理 static 规则 = 宽 2 滑窗 × 连续 7 窗、
   返回第 7 窗+2 ⇒ 标签比最早的物理停滞证据晚约 **8 个 query**。所以 −7 意味着报警落在
   「物理停滞刚开始后 1 步」，**不能宣称 MoE 比身体先知道**。
   （带**进入**时刻确实早，中位 onset−15/−16；但带进入本身在干净成功集上的占用率就有 42%，
   不可作为报警。loop onset 无此滞后，所以 loop 的 +2.5/+5 是真的晚。）
4. **P1 合规的代价是实打实的灵敏度**（§9.1 附录）：二分点从「组内成功集中位」换成
   「组内无标签中位」后，static 通道的检出从 0.734/0.812 掉到 0.378/0.565、
   pre-onset 从 0.615/0.739 掉到 0.266/0.478。无标签中位被失败行拉动（SCENE8 失败率 42%/35%）。
   **留出集里失败率更低的组会让同一套参数更敏感**，SCENE8 的数字对那些组是保守估计。
5. **「驻留」这个设计选择在 static 上是多余的**：占用率 AUC 0.856/0.881 > 驻留 0.761/0.794（§5.5）。
6. **两轴合取比单轴差**（§5.5），但按规则没有改带。
7. **分型串扰**：报警集上的分型正确率 loop 67%/71%、static 69%/80%（§2.1）。
8. **恢复性人群 n=6**，两格 n_pairs=25/9，只有一个单位显著；不能当结论。
9. **窗 q≥8 + K=11/M=9 ⇒ 最早报警 q=18/16**。短套件（queries 中位 8–13）上预期近乎全零检出，
   属设计域外。
10. **五轴里只有 2 轴进了判定**（inst、cons）。comm/stick/flow 只用于 `state5` 诊断，
    叫「五轴宏状态」名不副实，实际是二轴象限。
11. **本报告的检验比 E8 的功效高，部分来自置换单位从组换成集**（§5.4 折扣条款）。

## 10. 如果只保留一句话

**交付 static 通道，把 loop 通道标成阴性，并且不要把 static 通道当成新信号。**
在同一次运行、同一批集、对齐到同一 FA 工作点的配对比较里，static 通道相对既有最强
train-free 基线 `mob1_w8` 的**唯一净增量是时机**：把 25%–42% 的致败 static 集从「事后确认」
变成「事前报警」（McNemar 37:1 / 33:4，p ≤ 1.1e−6，两单位同向），代价是漏掉 C 能抓到的
41%–57%。它检出的是「停住」而不是「致败地停住」（4 个恢复性 static 里报了 3 个），
而且它的判别内容在一个单位上被 `mob1_w8` 完全吸收。
loop 通道输给了一条只看集长的平凡规则，唯一剩下的价值是 0/6 恢复性 loop 不报警，n 太小。
**E8 的驻留零结果在「五轴同态」这个量上被完整重现（AUC 0.53/0.65）；
它没有推广到「二轴带驻留」，原因是 E8 测错了量，外加检验族被小 n 格拖垮。**
