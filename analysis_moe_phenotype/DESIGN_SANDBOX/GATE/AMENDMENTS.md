规则见 `HOLDOUT_PROTOCOL.md` §7.2。**禁止编辑或删除已有条目**，只能在文件末尾追加。
无条目 = 冻结后零改动，这是期望状态。

条目模板（照抄，逐字段填）：

```
## AMD-<n>  <UTC 时间戳>
类型: 1（纯 bug 修复）| 2（位等价工程改动）| 3（纯报告列新增）
文件: <path>   sha256 before -> after

留出集是否已运行: 是/否（若是 -> 触发四臂全部重跑，旧结果目录保留为 results_amd<n-1>/）
校准集输出是否改变: 是/否（类型 2 必须为「否」）
签署: <agent id>
```

改任何参数值；为"让结果更好"改不等号方向；加 SPEC 未写的后处理；
以"数值稳定"为名改阈值；只重跑出问题的那一臂。

## AMD-1  2026-09-04（UTC）  增设强制对照臂 T（集长平凡对照）

类型: 协议修订（补一条本该有的对照；**不是放宽也不是收紧标准**）
文件: `HOLDOUT_PROTOCOL.md`（新增 §1.4 / §3.3b / §3.5，改写 §4.1 / §4.3 / §4.4 / §6 / §7.1 / §9）、
      `RUNNER.md`（§1.1 / §5 / §6）、`run_holdout.py`（`derive_params_T` / `materialise_clock_npz` /
      G3 / F1_T / F4 / F5 / S7）
**留出集是否已运行: 否。本修订发生在任何留出集检测器指标计算之前。**
守门人在留出集上仍然只统计规模构成（集数/事件数/组数/集长），未计算任何检测器指标。

**动机（外部事实，协调者转述）**：某原型自带的平凡对照臂显示 `n_queries` 组内配对
AUC = 0.999/1.000，且该对照在 loop 通道上打赢了它所属的方案本身；另一原型独立观察到
健康轨迹信号随 q 漂移、截断到 q≤38 后检出率近乎腰斩。
`REPORT.zh.md` §三本就写了"`pulse_count` 受集长混杂（n_queries AUC≈1.0）"——
**原版协议只把 `mob1_w8` 设为对照而没把集长设为对照，这是原版协议的漏洞。**

**改动要点**：
1. 臂 T = 同结构、同工作点对齐、一级信号换成 `__clock__`（集内 query 序号），不读任何 MoE 列；
   由执行器按 `PARAMS_T = PARAMS | {k: "__clock__" for k in ABLATION_KEYS}` 机械派生。
2. 新增硬闸 G3（`Δ_T ≥ 0.10` 且族内 maxT 显著），规格与打赢 C 完全相同。
3. 判决改为**合取**（打赢 C 且打赢 T）。**按 IUT，合取不需要跨分量多重性校正**，
   故 F1_C 与 F1_T 各自 3 格、`z_c≈2.39`、功效不变（池化格 0.92 @Δ=0.10）。
4. 通道级作废规则：`Δ_T^loop ≤ 0` 或不显著 ⇒ 该通道 MoE 载荷主张作废（`Δ_T^static` 无功效，只报符号）。
5. 新增 §1.4 集长混杂量化：**只有 97/332（29.2%）的致败 onset 早于健康长度包络 Q_g**；
   新增次端点 S7（长度匹配子集）。
6. 新增情形 7/8/9 三条负结果出口；情形 7 优先于 2–5 上头条。

## AMD-2  2026-09-04（UTC）  主端点改为「匹配视界 margin」；臂 T 升级为口径有效性校验

类型: 协议修订（**更换主端点**，比 AMD-1 更根本）
文件: `HOLDOUT_PROTOCOL.md`（新增 §3A / §5A，原 §3 降级为附录 A，改写 §4.3 / §4.4 / §6 / §7.1 / §9）、
      `RUNNER.md`（§2.1 / §6）、`run_holdout.py`（`task_horizons` / `matched_horizon` /
      `macro_type_acc` / V 闸 / F1_M / F1_MC / F_P / 前缀端点 / `select_winner` / `declare_verdict`）
**留出集是否已运行: 否。本修订同样发生在任何留出集检测器指标计算之前。**

**动机（外部事实，协调者转述自原型实测）**：
臂 T 本质是**超时探测器**——FA 0.038/0.019，det loop 1.000/0.645、static 1.000/0.855，
报警全部在 onset 之后且在几乎所有健康轨迹结束之后；前缀 q≤38 两通道两单位 det 全为 0.000。
在"全集任意时刻"的 Det 口径下某原型输给 T（loop Δdet −0.527/−0.364/−0.164、
−0.242/0.000/−0.210，全部 p<0.005），并据此自行作废其原载荷主张。
⇒ **`Det` 测的是"谁是更好的钟"。AMD-1 的"打赢 T"是必要的，但用错了尺子。**

**改动要点**：
1. **主端点改为匹配视界 margin**：把事件集与干净成功集放在**同一绝对 q** 上比较报警率之差，
   层 = `(corpus, task, scene)`，视界 = 每任务成功集 `n_queries` 的 p10..p90（9 个，**不去重**）。
   任何纯 q 报警器的 margin **构造性恒为 0**（§3A.2 证明），集长混杂被口径本身杀死。
   推论：`margin(arm) − margin(T) = margin(arm)`，**"打赢 T"已内建在主端点里**。
2. **原全集 Det 降级为附录 A**，每处引用必须附"受集长混杂支配、不可作载荷主张"。
3. **臂 T 角色升级为 run-voiding 的口径有效性校验（V 闸）**：`|MH(T)| > 0.02` ⇒ 整次运行作废重跑。
   自测确认：合规实现下 9/9 个视界 `margin_T = 0.0`（逐位精确）。
4. **新增前缀截断端点**（第二条独立证据线）：丢弃 `q > Q_g^{p90}` 的报警，分母 = 97 个可达事件，
   门槛 Δ ≥ 0.20（功效 0.82 @disc=0.40；Δ=0.10 只有 0.18–0.33，测不出）。
   截断规则**只由成功集集长分布定义**。
5. **分型端点强制宏平均**：本留出集上"恒判 loop"的**微平均是 0.819**、宏平均 0.500
   （外部实测同一现象：另一语料"恒判 static"微平均 0.747 高于真检测器）。
   **微平均结论一律作废。**
6. **功效重算**（用留出集构成算，不含任何检测器结果）：匹配视界可用层
   **全通道 108 / loop 95**，逐视界层数 100→24；组级 sign-flip 在真 margin=0.10 时功效 **0.84**
   （0.05 只有 0.24）⇒ **端点有功效支撑判决检验，不降级为描述性**；门槛 M1/M4 = 0.10 由此选定。
   static 通道（视界上事件 42→21）、S7（97）、main（57）、object（31）**明令只报不测**。
7. 新增负结果出口情形 **0**（口径失效 ⇒ 运行作废）与 **10**（margin 未显著为正）；
   顺序改为 `0 > 10 > 7 > 2–5 > 8/9`。
8. **门槛未按已知效应量调整**：协调者转述的校准集数值（A margin +0.108/+0.139，
   C +0.043/−0.014 ⇒ M4 的差在 U1 上是 +0.065 < 0.10）表明 M4 在校准集的一个单位上不过关。
   **不下调门槛**——0.10 由功效曲线选定，为迁就已知效应挪动门槛就是变相调参。

**附带修正（同一次提交，非协议改动而是实现纠错）**：
- `rows.npz` 的 `control_step` 是**整任务全局行号**（0..N−1），不是集内 query 序号；
  `events.csv` 的 onset/n_queries 全是集内坐标。已在 45/45 任务验证集内 `control_step`
  严格 +1 连续、逐集行数 == `n_queries`，故 `q = control_step − min(control_step | episode)`。
  已写入 `RUNNER.md` §2.1，新增探针 **P8** 硬检查，并修正原 P6（此前用全局行号算 n_queries，检查是空的）。
- `task_horizons` 原先对视界去重，导致位置索引不等于分位名次、跨任务错位
  （实测把 p20 的可用层数从 83 打成 39）。已改为固定 9 个、不去重，
  逐视界层数与独立核算 9/9 完全吻合。
