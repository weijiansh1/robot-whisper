## 2. 在线因果性与参照库口径（评估时的可执行定义）

检测器是"离线校准 + 在线检测"：

- **在线侧**：t 时刻的判定只能用该集 `control_step ≤ t` 的行。禁止整段轨迹、禁止未来行、
  禁止本集的 `success`。执行器用**前缀探针 P2** 机械验证（`RUNNER.md` §4）。
- **离线侧（参照库）**：允许用**同任务、其他组的成功集**统计量（留一组外，组 = `scene`）。
  这对应"部署时手上有该任务的历史成功 rollout 库"的现实假设。
  执行器用**标签探针 P1** 机械验证：把某组内的 `success` 标签随机置换后重跑，
  **该组内各集的报警必须逐位不变**（组外可以变）。变了 = 用了组内结局标签 = 违规。
- **留出集上的参照库来自留出集自身的成功集**（LOGO by scene），不是从 SCENE8 搬过来。
  这不是调参：过程与阈值定义都在 SCENE8 上冻死了，留出集只提供该任务的成功分布代入。
  但由此产生一条硬约束：**参照库构建过程本身不得含任何自由参数**（分位点 q、窗长 w 等必须已冻）。

## 3A. 主端点（AMD-2 重写）：匹配视界 margin

> **AMD-2 的动机（外部事实，协调者转述自原型实测）**：
> 臂 T（纯 query 序号）本质是**超时探测器**——FA 0.038/0.019，det loop 1.000/0.645、
> static 1.000/0.855，报警全部在 onset 之后、且在几乎所有健康轨迹结束之后；
> 前缀 q≤38 两通道两单位 det 全为 **0.000**。在"全集任意时刻"的 Det 口径下某原型**输给 T**
> （loop Δdet −0.527/−0.364/−0.164、−0.242/0.000/−0.210，全部 p<0.005），并据此**自行作废**了
> 其原载荷主张。
> **结论：`Det`（全集任意时刻的检出率）测的是"谁是更好的钟"，不能用来评判 MoE 载荷。**
> 原 §3.1–§3.4 的 Det 口径**整体降级为附录 A**，标注见 §3A.6。

### 3A.1 定义：匹配视界对角线检验（matched-horizon above-diagonal test）

把**事件集**与**干净成功集**放在**同一绝对 query 位置 q** 上评判：

- **视界网格**（每任务 9 个）：`H_task = {⌊p_d(该任务成功集 n_queries)⌋ : d = 10,20,…,90}`，去重。
  **只用成功集集长**定义，不碰失败集、不碰任何信号。
- **层（stratum）= `(corpus, task, scene)` 组**。**必须在组内配对**，见 §3A.2。
- 在层 `g`、视界 `q` 上：
  - **事件风险集** = 该层的有锚致败集中满足 `n_queries > q`（此刻还在跑）
    且 `q ≥ onset − L`（已进入 §3.1 的计入窗口左界，`L = 10`）者；
  - **干净成功风险集** = 该层的干净成功集中满足 `n_queries > q` 者；
  - `mh_det_g(q)` = 事件风险集中**在 q 之前（含）已报警**的比例（算通道 margin 时要求通道匹配）；
  - `mh_fa_g(q)` = 干净成功风险集中在 q 之前（含）已报警的比例；
  - `margin_g(q) = mh_det_g(q) − mh_fa_g(q)`；
  - 层在该视界**可用**当且仅当两个风险集都 ≥ 1。
- **逐视界汇总**：`margin(q)` = 全部可用层的**层均值**。
- **端点统计量**：`MH = median_{q∈H} margin(q)`，并同时报**符号计数 `k/9`**（margin>0 的视界数）。

### 3A.2 为什么这个口径能杀死集长混杂（构造性论证）

设某报警器只看 q（不读任何 MoE），在层 `g` 上的阈值是常数 `q*_g`
（臂 T 正是如此：阈值由该层的 LOGO 成功集长参照决定）。则在视界 `q`：
该层**所有**还活着的集——事件集与干净成功集**一视同仁**——都在 `q ≥ q*_g` 时已报警、否则都未报警。
于是

```
mh_det_g(q) ≡ mh_fa_g(q)  ∈ {0, 1}   ⇒   margin_g(q) ≡ 0   （逐层、逐视界，恒等）
```

**任何纯 q 报警器的 margin 构造性地恒为 0。**
外部实证：臂 T 在校准单位 U1 上实测 margin **0.000，9/9 个工作点一个不差**。

> **这条论证要求层必须是组级**。臂 T 的阈值是 LOGO-per-group 的，
> 若在任务级或全局池化，事件集与干净成功集的组构成不同会让 margin 偏离 0。
> **组级配对是本口径成立的前提，不是风格选择。**

**推论（重要）**：`margin(arm) − margin(T) = margin(arm) − 0 = margin(arm)`。
**"打赢 T"在新口径下等价于"margin > 0"——T 的比较已经内建在主端点里。**
AMD-1 的 G3（在全集 Det 上打赢 T）因此被结构性取代，只保留在附录 A。

### 3A.3 排序量与通道

- **排序量（唯一）= `MH_loop`**：loop 通道的 `MH`。
- **static 通道只报不判**：视界上的 static 事件风险集只有 **42（p10）→21（p90）**，
  功效不足以支撑任何判定。报 `MH_static` 与其符号计数，**明令不做显著性检验**。
- **宏平均 `MH_macro = (MH_loop + MH_static)/2`** 作声明的次端点（描述性）。
  **禁止用微平均把两个通道合并**（理由见 §5A 的分型端点）。

### 3A.5 臂 T 的新角色：口径有效性的构造性校验（run-voiding）

臂 T 仍是**强制**对照，但用途从"要被打赢的对手"升级为"**实现正确性的探针**"：

> **V 闸**：若 `|MH(T)| > 0.02`，或有 >2 个视界 `|margin_T(q)| > 0.02`，
> 则**匹配视界实现有误（层定义、风险集、alarm≤q 的比较、或组级配对被破坏）**，
> ⇒ **整次留出集运行作废，修复后四×三条曲线全部重跑**，两次运行都归档（§7.2 类型 1 程序）。

这是比"打赢 T"**更强**的检查：它不是统计上的比较，而是对口径本身的**构造性证伪**。
理论值是恒等 0；容差 0.02 只为吸收浮点与并列（tie）处理差异。
`MH(T)`、逐视界 `margin_T(q)`、以及各层风险集规模**必须全部落盘**（`results/mh_validity.json`）。

### 3A.6 原 Det 口径的处置（降级）

§3.1–§3.4 定义的全集 `Det` / `Lead50` / `Δ_C` / `Δ_T` **全部保留计算并落盘**，
但降级为**附录 A**，且每一处引用**必须逐字附带**：

> "本表为全集任意时刻口径，**受集长混杂支配**（留出集 70.8% 的致败 onset 发生在该集已长于
> 90% 成功集之后；纯 q 对照臂 T 在该口径下 det loop 可达 1.000/0.645），
> **不可作 MoE 载荷主张**，仅供运营参考。"

`Det` 仍用于：G1/G2 的可采性判定、S1–S7 的描述性端点、以及运营层面的"能抓到多少"陈述。
**不再用于排序，不再用于任何载荷主张。**

## 3. 附录 A 口径（原主端点，AMD-2 后降级为运营参考）

### 3.1 附录 A 端点 `Det` — 致败事件检出率

分母固定 = **332 个有锚致败集**（§1.1）。**任何臂都不得缩小自己的分母**：
预热期短、集太短、信号缺失一律算未检出。

某集算"检出"当且仅当存在一次报警满足**三条同时成立**：

1. **通道匹配**：报警的 `channel` == 该锚事件的类型（`loop` / `static`）。
   通道错的报警不是检出，计入描述性 `mistype_rate`。
2. **时间窗**：`onset − L ≤ alarm_step ≤ min(onset + T, n_queries − 1)`，
   **L = 10、T = 5**（冻结）。
3. **可用性**：该集属于对应通道有效的任务（§1.2）。

双通道集（45 个）：对每个通道各自用它自己的 onset 判 1–3；任一通道满足即算检出，
提前量取满足者中最早的那次报警。

**L = 10 的依据**：留出集集长中位 13、有锚 onset 中位 19（p10 = 7）。窗口再宽，短集里
"第 2 步的报警"就会被算成"检出第 12 步的 onset"，因果归属失效。L=10 已覆盖 onset 的整个 p10–p50 跨度。
防"永远报警"靠的是 G1 闸，不是 L。
**T = 5 的依据**：`REPORT.zh.md` §三——致败 loop 在 onset 后 z≈0.8–1.1 **平台不回落**（main 到 +7 升到 2.2），
恢复性 loop 到 +5 已跌到参照带之下。+5 是"还在坑里、干预还有意义"这句话在本数据上仍成立的经验边界。
**敏感性（描述性）**：同时报 L∈{5, 10, ∞} 与 T∈{0, 5} 的 Det，但**判决只用 L=10 / T=5**。

### 3.2 硬闸 G1（可采性）— 每集误报率

`FA_primary` = 在 **15,591 个干净成功集**（40 个 loop 有效任务；成功 且 无 static 事件 且 无 loop 事件）上
**触发任意通道报警的集比例**。

> **G1：`FA_primary ≤ X = 0.05`，且 6 个 (corpus,suite) 格中无一格 > 2X = 0.10。**

**X = 0.05 的依据（四条，缺一不可）**：

1. **相对既有报警器**：`z>2` 单脉冲在干净成功集的底座是 **24–81%/集**（`REPORT.zh.md` §五）。
   X=0.05 比该区间的**下界**还低 4.8 倍——过闸本身即"比现成报警器实质性地好"，不是修辞。
2. **相对既有最好的低底座特征**：pulse train 是唯一低底座特征（短套件 0.1–1.4%、main 3.0%），
   但在 long 上达 **10.6%**。把 X 定在 0.05、把逐格上限定在 0.10，意味着
   **pulse-train 特征本身会在 long 格上恰好被卡掉**。门槛设在"现成最好的东西刚好过不去"的位置才有信息量。
3. **下游干预预算**（决策论，不依赖任何留出集结果）：留出集有锚致败率 π = 332/17,648 = **1.88%**。
   若 Det = 0.5，则 TP ≈ 166、FP ≈ 0.05 × 15,591 ≈ 780，precision ≈ **17.6%**，即 **≈5.7 次干预换 1 次真拦截**。
   X=0.10 时降到 ≈8.9%（≈11 次换 1 次），对"重采 flow 噪声"级别的廉价干预已接近浪费上限，
   对"重规划"级别的干预则明确不可接受。X=0.03 时升到 ≈25%，但对一个 train-free 状态机是先验上不合理的苛刻。
   0.05 是"廉价干预可接受 / 昂贵干预需另行论证"的分界。
4. **估计精度足够**：n = 15,591 ⇒ p=0.05 处 Wilson 95% 半宽 **±0.0034**；最小的格
   main/goal（n=463）半宽 ±0.020，相对 2X=0.10 的判据仍绰绰有余。**闸用点估计判，CI 必报。**

**附加口径（只报不入闸）**：
`FA_replan = FA_primary`，另标注是否 ≤ **0.02**（"重规划级"）；
`FA_static_all` = 全 43 任务 16,897 个干净成功集上的 static 通道报警率；
`uncertain_loop_alarm` = 3 个 loop 无效任务上成功集的 loop 通道报警率（分母 1,306，其中 387 集带真值未知的 loop 标记）。

### 3.3 硬闸 G2（可采性）— 提前量

`Lead50` = 全部**被检出**集的 `alarm_step − onset` 中位（负 = 早于 onset）。

> **G2：`Lead50 ≤ +2`。**

依据：留出集集长中位 13，短套件（goal/spatial）中位 8–13。onset 之后 >2 步才响的报警，
在半数集里已经没有可用的干预窗口，那是**事后标注不是触发器**。T=5 的检出窗允许个别晚报警计入 Det，
G2 保证整体不是晚报警堆出来的。

**命名规则（不是闸，是措辞纪律）**：过闸后，
`Lead50 ≤ −1` 的臂标为 **预警型 (pre-onset)**；`Lead50 ∈ [0, +2]` 的臂标为 **同步型 (concurrent)**，
其 `calib_report` / 结论中**禁止出现"提前 / 预警 / early warning"**。

### 3.3b 硬闸 G3（可采性）— 必须打赢集长对照臂 T（AMD-1 新增）

> **G3：`Δ_T = Det(arm) − Det(T) ≥ 0.10` 且族 F1_T 内 maxT p < 0.05。**
> 与 G1、G2 并列为可采性硬闸：**不过 G3 的臂不进排序**，其 Det 只作描述。

门槛规格**与打赢 C 完全相同**（同样的 0.10、同样的 maxT 结构），依据：
T 与 C 是两条平行的证伪线（"是不是新信号" vs "要不要读 MoE"），
用两套不同的尺子会让读者以为其中一条更软。它们一样硬。

**通道级后果（逐通道判定，AMD-1 的核心条款）**：对通道 `ch ∈ {loop, static}` 另算
`Δ_T^ch = Det_ch(arm) − Det_ch(T)`。若 `Δ_T^ch ≤ 0` 或不显著 ⇒
**该通道的 MoE 载荷主张作废**，报告中该通道的一切结论必须逐字标注：

> "该通道未证明 MoE 载荷：集长对照臂 T 在本通道上不劣于本检测器
> （Δ_T^ch = …），本通道的检出可由『失败集更长』单独解释。"

`Δ_T^loop` 有功效（n=272，0.85 @ Δ=0.10/disc=0.25）；
**`Δ_T^static` 没有功效**（n=105，0.36），其判定只按效应量符号做**描述性**声明（§4.4）。

### 3.4 是否要第二个主端点

不要。**排序维度只有 Det 一个**；FA、lead、以及 AMD-1 新增的"打赢 T"都是**闸**不是排序量。
理由：三个原型 × 多目标 = 帕累托前沿 = 事后挑维度。单标量排序 + 硬闸把"挑最好那个"的自由度压成 0（§6）。

关于"是否该把主端点改成对 T 的配对差 `Det − Det(T)`"（AMD-1 讨论过并**否决**）：

- 否决理由 1：**会制造新的博弈面**。`Det − Det(T)` 越大既可能因为 arm 强，也可能因为
  **该臂的外壳让时钟信号跑得差**。排序量不该依赖对照的弱。
- 否决理由 2：**闸能达到同样效果且更严**。G3 把"打赢 T"的门槛设成与打赢 C 完全同规格
  （Δ ≥ 0.10 且族内 maxT 显著），过闸的臂已经证明了 MoE 载荷；在这些臂之间按 Det 排序，
  排的是运营有用性，不是"谁更会数步数"。
- 否决理由 3：**加 T 不花功效**（§4.4 的 IUT 论证），所以不需要为省检验而牺牲端点的可解释性。
- 但 `Det_excess_T = Det(arm) − Det(T)` **是必报列**（§1.4 后果 3），读者可以自行按它重排。

### 3.5 强制对照臂 T（集长平凡对照，AMD-1 新增）

**动机（外部事实，写入记录）**：某原型自带的平凡对照显示 `n_queries` 组内配对 AUC
= **0.999/1.000**，且该对照在 loop 通道上**打赢了它所属的方案本身**；另一原型独立观察到
健康轨迹的信号随 q 漂移、把轨迹截断到 q≤38 后检出率近乎腰斩。
⇒ "失败集更长"这条**完全不读 MoE** 的平凡事实，可以单独解释相当一部分检出。
`mob1_w8`（臂 C）本身也是带 8 步拖尾窗的 MoE 量，**它同样可能被集长解释**，
因此 T 不是 C 的替代，而是**比 C 更底层的地板**。

**T 的规范定义（冻结）**：

1. **同结构**：与被测臂**同一个 `detect` 函数、同一套参数键、同一个 `WARMUP`、
   同一套 LOGO 参照库构建过程与工作点对齐方式**。
2. **一级信号换成纯集长派生量**：把 `ABLATION_KEYS` 里的信号选择键全部指向合成列
   `__clock__`，其中 `__clock__[row] = control_step[row]`（当前已用的 query 数，float32）。
   —— 即 `PARAMS_T = PARAMS | {k: "__clock__" for k in ABLATION_KEYS}`，
   由执行器机械派生（原型无需改代码），派生失败时该臂须自行导出 `PARAMS_T`。
3. **不读任何 MoE 列**。`__clock__` 完全由 `control_step` 决定，与 routing 无关。
4. **在线因果**：`control_step` 是"已经走了多少步"，t 时刻可得；
   **`n_queries`（该集最终长度）是未来，T 不许用**。T 的强度来自
   arm 自己的 LOGO 参照库把 `__clock__` 归一到该任务成功集的长度分布上
   （这正是"同工作点对齐方式"的含义），而不是来自偷看集长。
5. **通道判定：T 的报警是通道无关的**，评分时对**任一**通道的窗口都算命中
   （即 T 免除通道匹配要求）。这是**故意给 T 的优待**：地板对照要尽可能强，
   把它做成稻草人等于自欺。该优待必须在报告中声明。
6. **每个原型有自己的 T**（`A__T`, `B__T`, `D__T`），因为 T 继承各自的外壳。
   三个 T 的 Det/FA 差异巨大本身就是发现（"打赢 T 主要取决于外壳"），须披露（§6 R-D）。

**T 也要跑在 C 上**：必报 `Det(C) − Det(T)`。若**连 `mob1_w8` 都打不过时钟**，
则"打赢 C"这个门槛本身失去意义，报告须在头条位置写明（§4.3 情形 8）。

## 4. 判据（成功 / 失败 / 零结果的判定）

记 `Δ_C = Det(arm) − Det(C)`、`Δ_T = Det(arm) − Det(T)`，逐集配对
（同一批 332 集，各臂的检出指示变量）。**判决是两条战线的合取：既要打赢 C，也要打赢 T。**

### 4.1 (a) 打赢消融臂 C 与对照臂 T 的量化门槛

**W 组（vs `mob1_w8` 臂 C）——"是不是新信号"**。一个臂**"打赢 C"**当且仅当**全部**成立：

| 编号 | 条件 | 门槛 | 依据 |
|---|---|---|---|
| **W1** | 逐集配对 `Δ_C,pooled` | **≥ 0.10** | §4.4 功效：n=332 在 Δ=0.10、不一致率 ≤0.25 时功效 0.92；Δ=0.05 只有 0.27，测不出来。且 0.10 以下（<33 个集）对干预触发器无运营意义。 |
| **W2** | 组级 sign-flip maxT p（族 **F1_C**，3 个对比） | **< 0.05** | `PROTOCOL.md` §4 口径，`stats.groupwise_signflip_maxt` |
| **W3** | 组均值 `Δ_C,group`（180 个含有锚致败集的组） | **> 0**（同号） | 防结果被少数大组带飞 |
| **W4** | 可采性 | 该臂过 G1、G2 **与 G3** | 打不赢就没有下游意义 |
| **W5** | 复现（见 §4.2） | R1 且 R2 | `PROTOCOL.md` §4"头条主张需 ≥2 独立单位" |

**T 组（vs 集长对照臂 T）——"要不要读 MoE"**（AMD-1 新增）。同时必须**全部**成立：

| 编号 | 条件 | 门槛 | 依据 |
|---|---|---|---|
| **T1** | 逐集配对 `Δ_T,pooled` | **≥ 0.10** | 与 W1 同规格（§3.3b：两条证伪线用同一把尺子） |
| **T2** | 组级 sign-flip maxT p（族 **F1_T**，3 个对比） | **< 0.05** | 与 W2 同结构；两族互不合并，见 §4.4 的 IUT 论证 |
| **T3** | 组均值 `Δ_T,group` | **> 0** | 同 W3 |
| **T4** | 通道级 `Δ_T^loop` | **> 0 且 p<0.05** ⇒ loop 通道 MoE 载荷成立；否则该通道主张作废 | n=272，功效 0.85 |
| **T5** | 通道级 `Δ_T^static` | 只报符号与效应量，**不作显著性判定** | n=105，功效 0.36，明令不测 |

**判决 = 合取**：`beats_C ∧ beats_T`。任一不成立 ⇒ §4.3 的负结果出口。

**arm C / arm T 自身是否过 G1/G2 不影响 Δ 的计算**（它们是比较基准不是候选）。
但若 `|FA(arm) − FA(C)| > 0.01` 或 `|FA(arm) − FA(T)| > 0.01`，报告中**必须逐字写入**：

> "本次 Δ 同时包含召回差与工作点差；两臂工作点不同（FA_arm=…, FA_对照=…），
> 主张只在各自冻结工作点上成立，不等价于同 FA 下的召回优势。"

若 SPEC 提供了预先声明的 `PARAM_SWEEP`（§7.2），则额外报 **S6 同-FA 对比**（描述性）。

**必报的第三个配对差**：`Det(C) − Det(T)`（描述性）。若 ≤ 0，则连既有最强 train-free 基线
`mob1_w8` 都没打过时钟，**"打赢 C"这个门槛本身失去意义**，触发 §4.3 情形 8。

### 4.2 (b) 跨套件 / 跨语料复现要求

- **R1（跨语料，硬）**：`Δ_grid > 0` **且** `Δ_main > 0`（同号）。
  **只要同号，不要求显著**——见 §4.4：main 只有 57 个事件，Δ=0.10 时功效 0.04–0.30，
  在 main 上要求 p<0.05 等于要求运气。**把功效不足伪装成复现门槛是本项目最容易犯的错，此处明令禁止。**
- **R2（跨套件，硬）**：6 个 (corpus,suite) 格中 **≥ 4 格 `Δ > 0`**。
  **R2 不是检验**：零假设下 P(≥4/6 为正) = 22/64 = **0.344**。它是叠在 W2 之上的一致性过滤器，
  报告中必须原样写出这个 0.344，防止读者误以为 R2 提供了证据。
- grid 的 4 个套件 = 4 个不同 checkpoint ⇒ R2 兼作跨 checkpoint 复现。

**AMD-2 的判决族是 F1_M + F1_MC（各 3 格）**，按下面同一条 IUT 论证各自在 α=0.05 校正，
`z_c ≈ 2.39`。附录 A 的 F1_C / F1_T 仍照算照报，但**不参与判决**。

**加一条对照臂为什么不花功效（关键论证，AMD-1）**：
判决是**合取**——"打赢 C **且** 打赢 T"。合取式假设检验是标准的
**交并检验（intersection–union test, IUT）**：只要每个分量各自在水平 α 上检验，
合取主张的整体第一类错误率就 **≤ α**，**不需要跨分量做多重性校正**。
所以 F1_C 与 F1_T 各自在族内 maxT（各 3 格、FWER 0.05），**互不合并**，
临界值仍是 `z_c ≈ 2.39`，功效表（下）与原版逐格相同。
**新增的是一道更难的闸，不是更松的显著性标准，也不是被稀释的功效。**

**F4 的特殊处理**：通道级 T4/T5 是**作废判定**（判定某通道的主张*不*成立），
方向上是"更容易否定主张"。对否定方向放宽 = 对主张方向收紧，
故 F4 **不做 maxT，逐格 α=0.05**，并在报告中声明这是**有意的自由**（liberal voiding）。

三个判决族与三个描述族**各自族内**校正、**不跨族合并**，
族成员在运行前逐条写死于 `run_holdout.py::FAMILIES`。
语料拆分、L/T 敏感性、FA 工作点变体**都不进 F1_C / F1_T**——
它们如果进去，族会膨胀到 ~100 格，把唯一有功效的检验也一起校正没了。
代价是：**它们永远不能升级成主张**，只能是描述。这条交换是有意的。

### 5A.2 分型端点 `TypeAcc`：**强制宏平均**

分型准确率 = 两个通道**逐通道召回的宏平均（macro-average）**：

> **禁止微平均。** 留出集的分型人群是 loop-only 227 / static-only 60 / 双通道 45（共 332）。

> **微平均在本任务上奖励猜多数类，任何用微平均得出的分型结论一律作废。**

    > 本评估集在结构上无法把这部分检出与『看钟』分开。"

### 5.1 S1 的特殊地位（要说清楚，但不给它改判的权力）

`REPORT.zh.md` §三把"**差别在能否离开**"列为全项目最有价值的正面发现，
同时诚实写了"统计上尚未达复现红线（无一格在两语料同时存活）"。S1 是它在检测器上的兑现。

**规则**：S1 是次端点，**不参与选臂、不参与 §4.3 判定**。
但**一条强制措辞**：若某臂过了 W1–W5 却**未过 S1**（即对恢复性 loop 与致败 loop 报警率相近），
结论中必须写：

> "本检测器检出的是『进入异常区』而非『不可逆』；`REPORT.zh.md` §三的
> 『能否离开』结论未在检测器层面兑现。"

反之，若某臂过 S1 但未过 W1（打不赢 C），也必须照写 S1 的正结果——
**次端点的正结果和主端点的负结果同时存在时，两句都要写，不许只写一句。**

## 6. 多方案仲裁（防"挑最好的那个"变成变相调参）

三个原型 A / B / D 加消融臂 C，共 4 条曲线在同一批 332 + 15,591 集上跑。若不设规则，
"选最好的一个报出来"就是一次 3 选 1 的隐式调参。规则如下，**全部机械可执行**：

### R-A 单次批量执行（No-peek）

- 三个原型的 `SPEC.md` **全部冻结之后**，`run_holdout.py --run` **一次性**跑完 A、B、D、C 四臂 × 43 任务，
  产出**只有 alarm 明细**（`GATE/results/<arm>/alarms/*.csv`），**不算任何指标、不打印任何汇总**。
- 指标只能由独立的 `run_holdout.py --score` 生成，且必须 `--all-arms-present` 校验四臂明细齐全后
  **一次性**写出完整指标表。**执行器在 `--run` 阶段拒绝输出任何率值**（`RUNNER.md` §5）。
- 留出集运行**每套冻结 SPEC 只允许一次**。alarm 明细落盘即 sha256 存档（`GATE/results/MANIFEST.sha256`）。

### R-B 唯一的、预先指定的选择函数

```
# AMD-2：先查口径有效性，再按匹配视界 margin 排序
if V_gate_failed(any T):  → §4.3 情形 0，整次运行作废，不产生 winner

admissible = [arm for arm in (A, B, D)
              if passes_G1(arm) and passes_G2(arm)      # 运营可采性（附录 A 口径）
              and MH_loop(arm) >= 0.10                  # M1
              and p_maxT_F1_M(arm) < 0.05               # M2
              and sign_count(arm) >= 7]                 # M3
if not admissible:  → §4.3 情形 10（若因 M1/M2/M3 落空）或情形 1（若因 G1 落空）

winner = argmax over admissible of MH_loop                   # 唯一排序量（AMD-2）
  ties (MH_loop 完全相等) → 取 MH_loop − MH_loop(C) 更大者
  再平 → 取 FA_primary 更低者
  再平 → 按 arm id 字典序 A < B < D                          # 完全确定性
```

（AMD-1 的 G3 已被 §3A.2 结构性取代：`margin(arm) − margin(T) = MH_loop(arm)`，
M1/M2 即"打赢 T"。G3 仅在附录 A 表里继续报出。）

**没有任何自由度**：不按通道选、不按语料选、不按次端点选、不按"哪个更有故事"选。
选择函数写死在 `run_holdout.py::select_winner()`，且必须在 SPEC 冻结前提交。

### R-C 族内校正吸收 3 选 1（AMD-1 重算）

`winner` 必须**同时**通过 W2（族 **F1_C**，3 格 maxT）**与** T2（族 **F1_T**，3 格 maxT），
两族的临界值都是 `z_c ≈ 2.39`。

**3 选 1 的计价没有因为增设 T 而变化**：
选择函数是在**同一个**排序量 Det 上做的 argmax，多重性来源仍是"3 个方案"，
而不是"3 个方案 × 2 条对照"——因为**判决是合取，不是析取**。
合取按 IUT 每个分量各自控制在 α（§4.4），因此：

| | 原版 | AMD-1 后 |
|---|---|---|
| 判决族数 | 1（F1，3 格） | 2（F1_C 3 格 + F1_T 3 格） |
| 每族格数 / 临界值 | 3 / `z_c≈2.39` | 3 / `z_c≈2.39`（**不变**） |
| 合取主张的 FWER | ≤0.05 | **≤0.05（IUT，不变）** |
| 池化格功效 @Δ=0.10,disc=0.25 | 0.92 | **0.92（不变）** |
| 通过判决所需条件 | W1–W5 | W1–W5 **且** T1–T4 |

**净效果：门槛更严，功效不变，第一类错误率不变。**
若把 F1_C 与 F1_T 合并成 6 格 maxT（`z_c≈2.5+`），才会白白损失功效——
那是**错误**的做法（合取不需要跨分量校正），本协议明令不这么做。

### R-D 全员披露（AMD-1 扩展）

无论输赢，**九条曲线的完整指标行全部进最终表**
（3 原型 × {主臂, C, T}）：Det / FA / Lead50 / Δ_C / Δ_T / `Det_excess_T` /
p(F1_C) / p(F1_T) / 通道级 Δ_T / 6 格符号 / S1–S7。
赢家不得单独成文。报告须显式写出**第二名**的数值与
"argmax over 3 的效应量存在向上偏倚，maxT 处理了推断但没有处理效应量偏倚"这句话。
S5（交叉拟合）作为该偏倚的无偏读数一并报出。

**三个 T 之间的差异必须单独讨论**：若 `Det(A__T)`、`Det(B__T)`、`Det(D__T)` 相差悬殊，
说明"能不能打赢时钟"在很大程度上取决于外壳而非一级信号，这一点必须点出
（与三个 C 的同类披露规则一致，见 `RUNNER.md` §5 注）。

### R-E 禁止事后组合

## 9. 一页速查（AMD-2 后）
