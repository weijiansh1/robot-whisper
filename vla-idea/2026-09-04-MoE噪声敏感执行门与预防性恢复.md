# MoE 噪声敏感执行门：从失败检测到预防性恢复

> 日期：2026-09-04  
> 状态：**想法已记录，暂不进入当前检测主线，可交由其他人继续。**  
> 当前证据等级：单个失败抓取案例的机制证据，不是已验证的 recovery method。

## 一句话想法

当相同观测下仅更换 flow-matching 初始 action noise，就导致 action-token MoE routing 大幅变化，而真实新观测引起的变化反而更小时，不应无条件执行完整 action chunk；应缩短执行、尽快重新观测和规划。

这把 MoE 从“失败标签预测器”改成一个 **action commitment gate**：它不负责指出正确动作，只判断当前单次生成的长 chunk 是否足够受观测约束、值得被执行。

## 现有证据

同噪声输入版本反事实固定指令、图像、8 维机器人状态，只改变初始 action latent：

\[
R(V_t,\xi_1),\ldots,R(V_t,\xi_M).
\]

定义：

\[
d_{\mathrm{noise}}
=
\operatorname{median}_{i<j}
H(R(V_t,\xi_i),R(V_t,\xi_j)),
\]

\[
d_{\mathrm{input}}
=
\operatorname{median}_m
H(R(V_{t-1},\xi_m),R(V_t,\xi_m)),
\]

\[
C_t=\frac{d_{\mathrm{input}}}{d_{\mathrm{noise}}}.
\]

在失败抓取前一个 query：

| 量 | 数值 |
|---|---:|
| 输入版本造成的后层 action-route 变化 | 0.01067 |
| 仅更换 action noise 造成的变化 | 0.01980 |
| `C` | **0.539** |
| 7 条同 snapshot 成功对照的 `C` | 1.593--2.132 |

该点位于错误闭爪前一轮，说明存在预防性干预窗口。但原始图像和状态在该轮也比全部成功对照更静止，action-only 反事实同样明显。因此现有证据只支持“外部反馈相对内部采样噪声较弱”，不支持 MoE 独有的 belief 解码能力。

抓空后的 `q+1/q+2` 中，新图像和新状态都强烈改变后层 action routing；所以恢复问题不是反馈没有进入 MoE，而是网络没有把已进入的反馈转化成正确的重抓行为。

- `himoe-vla_trap/results/input_version_counterfactual/`

## 控制策略草案

使用三个量：

\[
N_t=d_{\mathrm{noise}},\qquad
F_t=d_{\mathrm{input}},\qquad
C_t=F_t/(N_t+\epsilon).
\]

风险分数可以保持 train-free：

\[
S_t=
\mathbf 1[N_t>\epsilon_N]
\max(0,\log(N_t/(F_t+\epsilon))).
\]

其中 `C=1` 是无量纲的自然边界；`epsilon_N` 只是防止两个极小量形成无意义比值，应由数值精度或健康数据确认，而不是训练分类器。

建议的执行逻辑：

```text
生成 nominal 10-step action chunk
计算当前输入下的多 noise 路由敏感度
计算相邻输入版本的 same-noise 路由响应

if noise 不主导:
    正常执行 10 steps
else:
    只执行 0--1 step
    立即重新获取图像和机器人状态
    重新生成并复查
    若连续高风险，则 stop / retract / 请求额外观测
```

在线实现可以缓存上一输入在固定 probe-noise bank 下的 routes。实验采集为独立计算每个版本对，需 `2M=8` 次推理；流式部署在 warm-up 后理论上只需为当前版本新增 `M=4` 次 shadow inference，但该优化尚未验证。

## 它与 Trap recovery 的关系

这是 recovery pipeline 的前半段：

\[
\text{detect unreliable commitment}
\rightarrow
\text{interrupt long chunk}
\rightarrow
\text{reobserve/replan}.
\]

- 在 Trap 之前触发：Trap avoidance / preventive recovery。
- 在 Trap 刚形成时触发：Trap interruption。
- 已经深陷后触发：仍需要额外 actuator 才构成完整 recovery。

MoE gate 只提供 intervention timing，不提供 escape direction。已有 fresh-seed Snapshot-Fork 在 `-4/-2/0` 三个窗口均为 `0/8`，已有 route-based candidate ranker 也不优于随机。因此不能把“多抽一个 seed”当作默认救援动作。

## 最小验证实验

必须使用同一个 simulator snapshot 分叉，避免把不同物理状态误当作干预效果。建议至少四个 arm：

| arm | 干预 |
|---|---|
| A | 原样执行完整 10-step chunk |
| B | 风险触发后只执行第 1 step，立即重规划 |
| C | 风险触发后不执行该 chunk，直接用新观测重规划 |
| D | 固定每个 query 都只执行 1 step 的 compute-matched control |

可选第五个 arm 是多 noise 候选的 action medoid/consensus；不要按“路由最不同”或“某专家 ID”选候选，因为现有证据不支持这类 value interpretation。

主要指标：

- 最终任务成功率；
- 是否避免目标 missed-grasp/loop onset；
- 从报警到恢复有效进展的 action 数；
- 额外推理调用与真实执行动作数；
- 成功轨迹被不必要中断的比例。

公平性要求：所有 arm 从相同 snapshot、相同后续环境随机性开始；报告每个 snapshot 的配对结果，不能把共享 snapshot 的 forks 当成完全独立样本。

## 成功判据

该想法只有在下面两项同时成立时才值得称为 recovery：

1. MoE-triggered short execution 相比完整 chunk 显著提高同状态分叉的成功或 escape rate；
2. 它优于不看 MoE、固定始终 short-chunk 的控制组，而不只是“更频繁反馈通常更好”。

如果只满足第一项，应表述为 adaptive chunking 的工程收益；如果两项都不满足，则 MoE noise sensitivity 仍可保留为机制诊断量，但不能成为 controller。

## 明确不能声称的内容

- `C<1` 不等于失败，多解任务可能合法地对 action noise 敏感；
- routing 变化不等于 expert 输出语义变化；
- 该量不能证明模型“相信已经抓住物体”；
- 当前只有 1 个失败对 7 个成功 sibling 的 same-noise 机制实验；
- action-only 在该案例中也有强信号，尚未证明 MoE 更早、更准或更便宜；
- 现有 530 条失败 cache 没有相邻输入的配对同噪声 shadow inference，不能直接用来诚实评价这一规则。

## 与当前工作的边界

当前主线继续做 **train-free MoE failure detection**：扩大失败类型与任务覆盖，验证报警时序、召回和误报，不实施本文件的执行策略。本文件作为独立 handoff，后续 recovery 负责人可直接从已保存的 snapshot-fork 框架和 input-version counterfactual collector 开始。
