# v4 在线报警位置统计

## 统计口径

首次报警相位定义为：

```text
报警相位(%) = 100 * first_alarm_query(从0计数) / (轨迹query数 - 1)
```

因此 0% 表示第一个 query，100% 表示轨迹最后一个 query。报告中的“首次
报警 query”改用从 1 开始计数，便于阅读。轨迹总长度只用于事后统计，在线
报警器不读取最终长度或相位。

| 数据集 | 报警数 | TP / FP | 首报 query 中位数 | 相位 Q25 | 相位中位数 | 相位 Q75 |
|---|---:|---:|---:|---:|---:|---:|
| development 14,800 | 439 | 372 / 67 | 25 | 64.17% | 72.55% | 86.21% |
| external 8B 15,600 | 491 | 410 / 81 | 24 | 62.50% | 71.43% | 86.21% |
| cache right-16x32 2,560 | 242 | 229 / 13 | 35 | 68.63% | 70.59% | 82.76% |

外部 8B 的报警位置分布为：

- 0%-25%：5.70%；
- 25%-50%：4.68%；
- 50%-75%：45.42%；
- 75%-100%：44.20%。

所以该报警器的典型行为是运行到约 70% 时报警，约 89.6% 的报警发生在后
半程。正确报警相位中位数为 71.43%，成功误报为 74.07%；仅靠报警时间本身
不能进一步可靠地区分 TP 与 FP。

- `LIVING_ROOM_SCENE1 ... alphabet_soup_and_cream_cheese`：17.65%；

`results/episode_alarm_timing.csv`。

## 对干预的含义

总体风险识别召回是 72.70%，但至少提前 4 个 query 的外部风险召回只有
58.51%，至少提前 8 个 query 为 40.60%。因此当前 v4 已适合做风险识别和
报警实验，但若后续修正需要较长动作窗口，不能直接把 72.70% 当作可干预
召回。long 任务的干预余量相对充足；许多 spatial 任务需要更早的 precursor
头，而不是继续依赖当前 lock-in 确认。
