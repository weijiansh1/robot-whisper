# 原生 LIBERO-Long: 固定 v8 与 v8.2 报警比较

日期: 2026-09-09。

后续状态: [v8.2 实际干预已完成](NATIVE_LONG_V82_INTERVENTION.zh.md)。本文记录此前的离线报警回放，检测与实际恢复结果分别报告。

本次在上一轮完整的 100 条未干预主轨迹上回放原版固定 v8.2。v8.2 多检出 1 条失败，另外 1 条失败提前一个 query 报警，误报仍为 2 条。**本次没有执行 v8.2 干预，其救回率、误干预损害和推理开销尚未实测。** 上一轮执行的是 v8。

## 数据与统计口径

- 原生 LIBERO `libero_10`，10 个任务各 10 个官方初始状态；不是 Pro 或 Plus。
- 共 100 条完整主轨迹、2,911 个实际策略 query，84 条最终成功、16 条最终失败。
- 每条主轨迹只统计一次，以未干预轨迹最终失败为正类；没有按报警与否筛选样本。
- 使用已冻结的参考数据和参数，本批没有重新拟合或校准。
- 本次仅用 CPU 读取已有 MoE routing 概率，无新增模型推理或仿真步骤，无 hidden 激活采集，无 GPU 占用。

所有报警都还存在下一 query，按原协议从 q+1 开始干预时，可用触发的统计与上表相同。只统计截至 q30 的报警时，三个版本均只命中 1 条失败、误报 2 条；截至 q40，v8 命中 7 条失败，v8.2 命中 8 条，均误报 2 条。本批改善集中在较晚的位置，尚未解决早期漏检。

## v8.2 的具体变化

v8.2 是报警规则版本，不需要新的模型 checkpoint。输入仍为每个 query 的 `hb_router_probs[8,10,11,32]`。v7 的三个分支不变，仅对 v8 新增的前后层流动反转和三点曲率两个分支使用固定时间斜率。

将两个分数都表示为越高越异常后:

```text
tau_inversion(q) = 0.0                - 0.0015 * q
tau_curvature(q) = 0.3890000581741333 - 0.0015 * q
```

`q` 从 0 开始，是已执行策略 query 的序号。曲率基线仍为 q1..q4，平滑窗口仍为因果 W6，两个新增分支从 q6 开始检查，连续两次越阈值确认。斜率 `-0.0015` 沿用原版冻结值；阈值随 q 的确定性变化不构成本批重新校准。

## 两条变化轨迹

两条均属于 `LIVING_ROOM_SCENE2_put_both_the_cream_cheese_box_and_the_butter_in_the_basket`，未干预最终都失败。

| 主轨迹 ID | 初始状态索引 | v8 首报 | v8.2 首报 | 变化 |
|---|---:|---:|---:|---|
| `6759f4eeff7dd7f31abc4d34` | 1 | 未报警 | q39 | 新增命中 |
| `b33f744e1932d63bed46d59e` | 5 | q43 | q42 | 提前 1 个 chunk，即 10 个动作步 |

两处变化均由曲率分支触发。第一条在 q38/q39 的曲率分数约为 0.335684/0.334742，分别超过 v8.2 的 0.332000/0.330500 阈值，满足连续两次确认；它们未超过 v8 的固定 0.389000 阈值。

这提供了一个新增恢复入口和一个较早的入口。仅 16 条失败中的一个新增命中不足以证明稳定的泛化提升，更不能据此推断动作恢复有效。此前固定 v8 干预的成功率不代表 v8.2 的干预成功率。

后续干预应首先固定恢复模块、候选预算和随机数流，仅改变 v8/v8.2 的触发时机，以测量报警时机的作用。候选评分也改为 v8.2 应作为另外一个实验因素；这时报警阈值与“远低于阈值”的目标必须使用同一个 `tau(q)`，同一物理状态下的候选共享 q，预览候选不得推进时间或污染已执行历史。上述两组实验现已执行，结果见 [实际干预报告](NATIVE_LONG_V82_INTERVENTION.zh.md)。

## 验证与产物

输入主轨迹清单、分块文件及冻结参数的哈希验证通过。全部 2,911 个 query 的独立特征提取通过比对；v7/v8 首报与上一轮在线审计完全一致；200 次标量 v8/v8.2 回放与向量实现一致。对全部 100 条轨迹分别截断至 q7、q13、q20、q30、q40 后的回放通过因果前缀检查，反转轨迹顺序结果一致，v8.2 保留全部 v8 报警且不延迟。
