# 原生 LIBERO-Long: v8.2 实际干预实验

日期: 2026-09-09。完整运行: `/tmp/himoe_native_long_v82_20260909_r3`。

**实际干预与验证均已完成。本批没有救回原始失败。** 仅更换报警时机、同时更换候选评分这两种设置下，IID 和 guided 信号选择组均保持 84/100 成功；四个随机选择对照均为 83/100。完整 v8.2 选择器增加约 58%-60% 的部署策略前向，未增加成功数。

## 数据与范围

复用此前预先声明并完整审计的 100 条原生 Long 主轨迹: `libero_10` 的 10 个任务，每个任务使用官方初始状态索引 0..9。未干预结局为 84 成功、16 失败。本次没有新增独立主轨迹，也没有使用 Pro 或 Plus。

完整主轨迹上有 14 个可用 v8.2 首报，覆盖 12 条原始失败、2 条原始成功。全部 14 个状态进入实验，没有按干预结果筛选；每个状态重新完成一次完整精确 C0，然后运行 9 个分支，共 140 个作业、126 条后缀。86 条未触发轨迹在整体成功率与部署成本计算中保留原始结局与成本。

原生 LIBERO 提交为 `8f1084e3132a39270c3a13ebe37270a43ece2a01`，运行前后源码均干净。Long checkpoint SHA-256 为 `cdc2b21f9ef657ab31049cfd2b1e2086ceb193a1b8c16af0cd6688925491a256`。仅使用物理卡 0-3，渲染使用 0、3；卡 6 未参与。没有采集 neural hidden 激活、训练模型或重新校准报警参数。

## 随机对照的定义

本轮的随机化发生在**最终候选索引的选择**。所有干预分支均从同一个 v8.2 首报后的 q+1 状态开始，原样执行报警 query 的 chunk 后才分叉。

| 项目 | 随机选择对照 | 信号选择组 |
|---|---|---|
| 触发与恢复状态 | 相同 v8.2 报警与完整快照 | 相同 |
| 每次搜索预算 | 16 组模型生成的动作 chunk | 相同 |
| 候选生成 | IID 或 guided，同组配对 | 相同生成规则和额外随机数流 |
| 最终候选选择 | 从全部 16 个候选等概率抽取，每个概率 1/16 | 选择内部风险 R 最低者，并列取较小索引 |
| 实际执行 | 选中候选的完整 chunk，最多 10 步 | 相同 |
| 退出规则与预算上限 | 全候选低风险连续 3 次，或最多 12 个恢复 query | 相同规则和上限 |

第一次搜索的配对候选池已逐项验证相同；执行不同动作后，后续状态、候选及实际总开销可以不同。随机控制使用模型生成的动作，不直接随机生成机器人动作向量。

`iid_random` 使用 IID flow noise 生成候选。`guided_random` 仍使用风险分数从第一批 8 个候选中选 4 个精英，做一次平滑的对角 CEM 更新，产生第二批 8 个候选，只在最后选择执行项时随机。因此，随机对照仍使用信号触发、退出，guided 对照还使用信号生成候选；它检验最终风险排序选择的额外作用，不是完全移除 MoE 信号的消融，也不是随机触发时机实验。

## 两个实验因素

第一组从 v8.2 的报警位置开始，保留原固定 v8 候选评分与退出目标。与上一轮 v8 触发的同一恢复模块比较，只改变触发时机。

第二组也由 v8.2 触发，同时将候选评分和退出目标改为 v8.2。两个新增分支的高异常方向阈值为:

```text
tau_inversion(q) = 0.0                - 0.0015*q
tau_curvature(q) = 0.3890000581741333 - 0.0015*q
r_i = (score_i - tau_i(q)) / margin_i
R = max(r_freeze, min(r_acceleration, r_periodicity), r_inversion, r_curvature)
```

v7 分支使用原固定阈值。绝对 margin 沿用原设置，前 3 个为相应阈值的 20%，inversion 为 0.1，curvature 为 0.1890000581741333。第二组的低风险目标也随阈值平移，即 R <= -1；数值确认采用 R <= -1-1e-6。

q 为从 0 开始的实际执行 query 序号。同一状态的 16 个候选共享 q，分别在独立的历史副本上评分，仅将最终执行项写入真实历史。候选预览不推进计数。每次最多 16 个候选；若没有达到目标的候选，仍执行最低 R 的候选；最多搜索 12 个实际 query，不延长总 520 步预算。退出后回到原策略并记录风险是否再次超过 0，不启动第二轮恢复。

## 整体结果

除原样对照外，下面所有分支都使用 v8.2 触发。救回的分母为 12 条触发的原始失败，误伤的分母为 2 条触发的原始成功。总体成功数的分母为完整 100 条主轨迹。

| 分支 | 候选评分版本 | 成功/100 | 救回/12 | 误伤/2 | 完整部署前向数 | 相对原策略 |
|---|---|---:|---:|---:|---:|---:|
| native | 原样 | 84 | 0 | 0 | 2,911 | 1.000x |
| iid_random_v8 | 固定 v8，随机选 | 83 | 0 | 1 | 4,710 | 1.618x |
| iid_v8 | 固定 v8，最低 R | 84 | 0 | 0 | 4,447 | 1.528x |
| guided_random_v8 | 固定 v8，随机选 | 83 | 0 | 1 | 4,663 | 1.602x |
| guided_v8 | 固定 v8，最低 R | 84 | 0 | 0 | 4,403 | 1.513x |
| iid_random_v82 | v8.2，随机选 | 83 | 0 | 1 | 4,845 | 1.664x |
| iid_v82 | v8.2，最低 R | 84 | 0 | 0 | 4,657 | 1.600x |
| guided_random_v82 | v8.2，随机选 | 83 | 0 | 1 | 4,813 | 1.653x |
| guided_v82 | v8.2，最低 R | 84 | 0 | 0 | 4,598 | 1.580x |

部署前向数包括一个策略自己的主轨迹前缀和实际候选搜索，排除研究用 C0、其他实验分支及模型启动检查。实际采样总计 16,128 次前向，其中 C0 为 696 次，126 条分支合计 15,432 次。922 个完整候选池共保存 14,752 个候选；候选数已经包含各池的原生候选，不能再与总前向数相加。

四个随机对照误伤的是同一条原始成功轨迹 `b92c3d7e25fbe93b35edbfcc`，任务为将黑碗放入底部抽屉并关好。四个信号选择组均保住这条轨迹，相对各自随机对照均为 1 胜、0 负。这里是避免随机选择引入的损害，没有发生从原始失败到成功的救回；仅 2 个原始成功触发状态，也不足以证明普遍安全。

仅改变触发时机时，各分支与上一轮的成功结局相同；固定和移动候选阈值之间也没有任何成功结局改变。12 个报警时间未改变的状态，其 4 个固定 v8 干预分支共 48 条后缀、629 个 query，动作、路由、噪声、状态及选择风险与上一轮完全一致。

本批没有达到正净救回的继续扩样条件。数据支持 v8.2 增加了一个检测入口，却没有证明本恢复模块能利用它提高成功率。后续应单独验证候选风险降低是否对应可恢复的任务进展，不能将内部风险压低本身作为恢复成功的判据。
