# 基于内部信号的免训练动作选择器

日期：2026-09-09。协议：`moe_control.internal_pareto_selector.v1`。

已经实现候选动作选择原型，并完成已有完整候选池的历史回放。它可以根据内部信号改变实际执行的动作，但本次尚未观察到比配对候选 0 更高的成功率。没有启动新的 GPU 采集。

## 1. free 的含义与干预位置

这里的 free 指免训练、无需额外 critic、无需 hidden 或空间探针。它复用已有的冻结成功参考库，所以不是 data-free 或 reference-free；生成额外候选也需要额外模型推理。

干预发生在动作分发前：同一观测下生成若干完整 action chunk，读取各自的 MoE 路由概率，再决定执行其中哪一个。当前版本不改变模型权重或 gate logits，也不平均不同候选的动作。

这将两个问题分开：外部冻结报警器决定是否进入选择流程；选择器判断候选是否满足内部信号与动作约束。内部信号下降只作为启发式接受条件，不解释成成功概率增加。

## 2. 信号、阈值和候选

输入使用已有 `collection/hb_probs`：8 个 HB 层 × 10 个去噪步 × 11 个 token × 32 个专家。存储为 FP16，特征计算沿用现有实现。没有记录 hidden；4 个候选的这部分原始概率约占 220 KiB，不含其他账本字段和模型自身显存。

所有候选共享真实已执行的历史。对每个候选都复制一次监测器，追加当前候选的路由概率，计算下表信号。拒绝的候选不会推进真实监测历史。

| 信号 | 方向 | 沿用的冻结阈值 |
| --- | --- | ---: |
| v7 freeze | 大于阈值为超限 | 0.5740630626678467 |
| v7 persistent acceleration | 大于阈值为超限 | 0.10750749707221985 |
| v7 persistent periodicity | 大于阈值为超限 | 0.3749159276485443 |
| v8 front/back flow-path inversion | 大于阈值为超限 | 0 |
| v8 relative curvature | 大于阈值为超限 | 0.3890000581741333 |
| Euclidean kNN-20 | 大于阈值为超限 | 2.38411808013916 |
| cosine kNN-20 | 大于阈值为超限 | 0.38846355676651 |

v8 的曲率和 flow path 描述去噪过程中的路由变化，不是机械臂在物理空间中的轨迹曲率。选择器使用各连续信号作为约束，不把它们的简单并集当成新报警器，也不修改原有报警的窗口、确认次数或首次触发时刻。

候选 0 是默认动作，其余 3 个候选通过独立高斯噪声生成，全部 batch=1，图像、状态、指令摘要必须相同。报警后先生成默认候选；只有它具备完整的 7 项证据且至少有一项当前超限，才扩展其他候选。

## 3. 选择规则

设候选 i 的第 j 项分数为 s_ij，冻结阈值为 T_j，定义超限量：

```text
e_ij = max(s_ij - T_j, 0)
```

接受替代候选需要同时满足：

1. 每项超限量均不增加，至少一个默认动作已超限的信号严格改善。低于阈值的信号允许波动，只要不产生新的超限。
2. 整个计划执行前缀的夹爪符号与默认候选一致，不仅检查第一步。
3. 前 6 维连续动作相对默认候选的 RMS 改变量，不超过当前有限候选池的中位数；中位数包含候选 0 的零距离。
4. 动作改变量超过浮点数值容差，排除只有路由变化、动作实质相同的候选。
5. 候选动作和 7 项证据全部有限。

合格候选按“剩余超限项更少、动作 RMS 改动更小、候选编号更小”依次选择。没有合格替代就执行候选 0；没有报警、没有当前超限或历史不足，也执行候选 0。

比较容差固定为 `64 * float32_eps * max(1, abs(s_0j), abs(T_j))`，动作容差采用同样的数值尺度规则。没有拟合加权风险分数或新的报警阈值，但候选数量、约束和排序仍属于设计选择，不能称为无参数方法。

动作 RMS 使用策略命令的前 6 维，不是米制位移上限，也不构成碰撞安全证明。夹爪一致性约束可能拒绝真正需要释放或重新抓取的恢复动作。本版本适用于保留当前抓取模式的保守替换。

从控制的角度看，这是带可行性约束和弃权的离散监督选择器。现有信号尚未被证明是 Lyapunov 函数，选择规则也没有证明任务稳定性或成功率单调增加。

## 4. 与主轨迹及采集接口的关系

本次沿用历史实验的时序：先完成不干预的主轨迹，完成精确 C0 复现，再从首次 Euclidean kNN 报警 q 的下一次查询 q+1 状态分叉。报警查询本身按原动作执行。只替换 q+1 的一个原生 chunk，随后恢复普通策略，保持原 520 步总预算。

原型入口为 `InternalActionSelector.observe / needs_candidates / propose`。接入现有 worker 时的逻辑如下，函数名称中的推理和执行部分由现有采集器提供：

```python
# Restore the fork state and replay only the executed routing prefix first.
pool = [infer_once(observation, native_noise)]
if selector.needs_candidates(pool[0].probabilities, frozen_trigger):
    pool += [infer_once(observation, noise) for noise in independent_extra_noises]

decision, scores = selector.propose(
    [item.probabilities for item in pool],
    [item.actions for item in pool],
    [item.input_sha256 for item in pool],
    triggered=frozen_trigger,
    execute_count=min(10, remaining_action_budget),
)
chosen = pool[decision["candidate"]]
execute(chosen.actions, min(10, remaining_action_budget))
selector.observe(chosen.probabilities)
```

额外候选使用独立随机流，不能消耗默认策略后续的随机流。`execute_count` 由已知剩余预算决定，不能使用执行后才知道的成功停止位置。监测历史只在选中动作确实被分发后提交一次。线上分发尚未接入 worker，本次验证仅覆盖选择模块和已有完整分支的单次选择。

成本：通常 1 次完整 forward；扩展时总计 4 次。若所有查询中有比例 p 扩展，在不考虑轨迹长度变化时，模型查询量约为原来的 `1 + 3p`。延迟、显存和功率不能直接由这个比例推算，批处理改变路由的风险仍按原 batch=1 规范处理。

## 5. 历史回放结果

来源为 `adaptive_control_validation_audit_20260908.json`，旧审计已通过，包含 120 条主轨迹、55 个报警状态、每状态 4 次重复、每重复 4 个完整候选后缀。当前选择规则及代码哈希在本次回放前保存；这些历史成败标签之前已经被分析过，因此本次不是盲测或新的独立验证。

主分析保留全部 113 条扰动轨迹：Pro 43 条、Plus 70 条，其中 54 条触发可分叉报警，共 216 个候选池。另 7 条对照轨迹单独统计。未报警轨迹保留原始结果，重复先在主轨迹内平均，描述性区间按 base task 聚类。

| 方法 | 原失败后缀救回 / 188 | 原成功后缀破坏 / 28 | 主轨迹平均成功率 | 相对候选 0 净变化 |
| --- | ---: | ---: | ---: | ---: |
| 配对候选 0 | 1 | 0 | 56.86% | 0 pp |
| 本次内部 Pareto 选择器 | 1 | 0 | 56.86% | 0 pp |
| noise center | 2 | 0 | 57.08% | +0.22 pp |
| routing center | 2 | 0 | 57.08% | +0.22 pp |
| routing edge | 3 | 1 | 57.08% | +0.22 pp |
| 最小 Euclidean kNN | 0 | 1 | 56.42% | -0.44 pp |
| 旧 guarded kNN | 1 | 0 | 56.86% | 0 pp |
| 四候选事后 oracle | 4 | 0 | 57.52% | +0.66 pp |

候选 0 采用分支的新噪声流，不等于原主轨迹记录的动作。新选择器的 1 次救回也是候选 0 已经救回的同一次，不能归因于新规则。相对候选 0，逐重复的新增成功和新增失败均为 0；这不证明二者总体等效。原主轨迹平均成功率为 56.64%。

216 个主分析候选池中，187 个扩展，73 个实际换动作，143 个保留默认。其中 114 个没有合格替代、25 个没有当前超限、4 个默认证据不完整。按现有后缀长度估算，总部署模型查询量相对候选 0 增加 3.38%；此次 CPU 回放实际新增 GPU forward 为 0。

Pro 换动作 37/116 次、救回 1/116 个失败后缀；Plus 换动作 36/100 次、救回 0/72 个失败后缀，破坏 0/28 个原成功后缀。Pro 的可干预原成功样本为 0，不能据此判断其误干预风险。这里的分母是重复后缀，不是独立主轨迹数量。

候选覆盖是一个明确限制：188 个原失败的候选池中只有 4 个含成功后缀，涉及 2 条 Pro 主轨迹；Plus 的 72 个失败池全部四候选均失败。这仅限制这个固定噪声候选池及其原生后续策略，不是这些物理状态的普遍可恢复性上限。

新规则也有自身损失：4 个成功的非默认候选没有被选中，其中 1 个仅因动作半径被排除，其余存在信号超限恶化或缺少当前超限改善等原因。这说明“内部信号改善”和“真实恢复成功”还不能互相替代；不能把结果全部归因于候选覆盖。此次没有按这些已知结果放宽约束再选最优版本。

## 6. 下一组实验应验证什么

先固定本次选择器，改变候选池的来源，单独衡量候选生成能否提供真实成功分支，再检验内部信号能否选中它。

一个免训练的后续方向是有限差分引导的内部扰动：在同一输入下产生一对受限的正负噪声或 gate 扰动，观察当前超限信号及动作如何变化。它不需要训练恢复网络，但仍需模型推理；直接改变 gate 后再用同一个被操纵的路由量评分，容易获得虚假的“改善”，因此不能作为有效性证据。gate 候选应单独作为新实验臂，不能与本次原生噪声候选的结果混用。

具体比较应保持相同触发、候选生成器、K=4、恢复时长和原总步数预算，只更换候选选择规则：配对默认候选、随机候选、旧 kNN、当前 Pareto 选择器。四个候选都跑完整后缀以统计池内可恢复率；同时采集原成功轨迹，报告救回、破坏、额外查询和再次陷入停滞的比例。候选 0 必须保留默认噪声流。

连续多次选择或执行 1 至 2 步后再选属于另一种控制策略，会改变后续观测与内部历史，不能用本次单次选择的历史标签推出效果。需要新的主轨迹和真实分支验证。暂不把本版本作为已验证有效的恢复控制器大规模部署。
