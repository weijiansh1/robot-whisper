# MoE 路由恢复控制探索

2026-09-08。状态：试采、开发、验证全部完成并通过独立审计。144 条既有主轨迹、103 个恢复状态、2,252 条完整后缀，实际采集推理 68,531 次。只使用物理 GPU 0/1/2/3，渲染限定 0/3；原预加载服务保留。不保存 hidden，不修改模型参数，不重新拟合报警阈值或成功参考库。

**本次 Long 验证尚无稳定胜出的控制。按样本中的净收益、破坏和推理成本，单次纯噪声中心最划算；MoE 路由中心与其净收益相同，边缘噪声救回最多但有一次破坏，三者均只比随机对照高 0.221 个百分点。** 纯噪声中心与路由中心属于预先定义的次要比较，不替换验证前已冻结的主要方法。提前窗口中的受限 kNN 是开发诊断线索，不能作为在线效果。

## 实验问题

1. 当前报警之后是否还有可恢复状态？开发集将首次欧氏 kNN 报警 q 的 q+1 状态与 max(0,q-5) 状态配对。提前状态使用了事后报警时刻，只作为恢复窗口诊断，不算可部署策略。
2. 四个噪声候选中是否存在更好的续跑？全部四个候选都完整续跑，比较随机候选、路由中心、路由外围、冻结 kNN 距离最小、受限 kNN 选择。事后最优候选仅提供诊断上限。
3. 连续控制能否优于单次干预？执行长度为 2 或 5 的 chunk，持续 1、5 或 20 次 query；噪声选择与短 chunk 结合时持续五次 query，随后恢复原生十步执行。

## 控制定义

路由分数沿用冻结 4096 点成功参考库、10D 动力学、欧氏 k=20。候选评分只读取当前输入的路由和已执行历史。每个候选在独立历史副本上评分，只有执行的候选写回历史。缩短 chunk 后，该分数仅用于同状态候选排序，不解释为已校准失败概率。

受限选择要求候选的首动作夹爪方向与候选 0 相同，且前七维动作相对候选 0 的 RMS 不超过本候选池中位数。候选 0 始终保留。这是减少扰动的约束，不保证物理安全或任务收益。

所有初始噪声均为四个独立标准高斯数组，形状 [10,24]。模型始终 batch=1，每个候选完整前向，推理成本全部计数。候选第一次前向在相关后缀之间共享；未选候选不写入实际执行历史。

策略噪声按主轨迹、重复、分支相对 query 和候选 ID 配对，跨时刻和干预方法使用相同随机流。模拟器随机性按绝对环境步配对。短 chunk 仍会改变观测与推理的物理时间，所有方法使用原 520 步剩余预算。

原生主轨迹与恢复分支的未来策略/环境随机流不同。纯控制增量以共享随机流的 candidate0 分支为主要对照；相对原生结果的差值另外报告，包含重新采样带来的变化。只看噪声中心的负控不需要候选模型前向，部署推理成本按一次选中候选计算。

## 采集与评估

主轨迹必须已提交且未经干预。完整 C0 精确匹配全部输入、噪声、动作、HB/AS 路由、物理状态和终止结果后，才派发其分支。每个状态与重复独立入全局队列，避免父轨迹绑定大量后缀造成长尾。每块八个 query，最多两个待写块；保留 8 GiB 工作盘余量。

开发集从此前 120 条 Long 主轨迹中，按 benchmark/category 固定哈希选取有可干预报警的父轨迹，不按原生结局选样。开发阶段进行候选比较。验证集取自另外 830 条 Long 父轨迹，ID 不重叠，包含无报警轨迹；选择器必须在验证前冻结。两者基础任务可能相同，因此验证不宣称未见任务泛化。

开发分析报告条件救回、破坏及时间窗口。验证分析以全部选定父轨迹的策略成功率为主，无报警父轨迹保持原生结果；状态内重复先平均，按原始任务聚类计算探索性区间。另报告额外 query、动作步、候选池上限和实际资源消耗。成功参考库和报警工作点在全过程保持不变。

## 开发结果

[开发独立审计](design/adaptive_control_development_audit_20260908.json) 全部通过。与试采合并后为 24 条父轨迹、48 个状态、1,152 条完整后缀；主要扰动口径为 23 条，原生失败 16 条、成功 7 条，另 1 条原场景对照单列。每状态两次重复，以下救回分母为 32 次失败续跑、破坏分母为 14 次成功续跑，不是独立主轨迹数。

[完整开发分析](design/adaptive_control_development_analysis_20260908/summary.json) 表明，报警后所有控制均未救回失败。单次两步 chunk 破坏 2/14 次，持续五次或二十次的两步 chunk 分别破坏 1/14 次，连续路由中心和单次路由中心分别破坏 1/14 次；随机对照、五步 chunk 持续五次、单次边缘及 kNN 等方案没有观察到破坏。没有正的配对净收益。

按事先固定的选择规则，冻结为 [short5_5 和 edge_once](design/adaptive_control_development_analysis_20260908/selection.json)：前者持续五次 query 每次执行五步，后者仅第一条 query 在四个候选中选路由外围，随后均恢复十步原生执行。二者开发效果均与随机持平，部署 query 成本分别增加 5.39% 和 6.76%；入选表示同一家族内的收益、破坏及成本排序结果，不表示已经有效。

### 提前窗口诊断

| 报警前五个 query 的方法 | 失败救回 | 成功破坏 | 相对随机净增益 |
|---|---:|---:|---:|
| 随机候选 | 0/32 | 0/14 | 0 pp |
| 单次路由中心 | 2/32 | 0/14 | +4.35 pp |
| 单次受限 kNN | 2/32 | 0/14 | +4.35 pp |
| 两步 chunk 持续二十次 | 2/32 | 0/14 | +4.35 pp |
| 单次 kNN | 1/32 | 0/14 | +2.17 pp |

| 单次边缘噪声 | 0/32 | 0/14 | 0 pp |

上述两次救回全部来自同一条 Plus Objects Layout 主轨迹 `8a9b5def886801b8b2a5d2df` 的两次重复：将黄白杯放入微波炉并关门。它首次报警 q12，提前分支从 q7/环境步 70 开始，报警后分支从 q13/环境步 130 开始。两处相隔 60 个环境动作。在提前状态，每次四候选中有两个续跑成功；报警后四候选全部失败，持续控制也未救回。原生失败样本在报警后的四候选诊断上限为 0/32，提前为 2/32。

这是恢复窗口与候选覆盖的线索，不能用于部署效果声明：提前点需要事后知道报警时刻，且全部收益集中在一条父轨迹。单次受限 kNN 在三个并列救回方案中平均推理成本最低，平均 46.35 query，路由中心为 46.48，持续两步 chunk 为 59.89；本批没有证明它优于路由中心或能泛化到其他任务。三个方案的任务聚类探索性区间均为 [0, 13.64] pp，包含零。报警后的四候选全部失败也不代表所有可能动作均不可恢复。

该轨迹的 [原始模型输入对照图](design/adaptive_control_case_images_20260908/plus_microwave_rescue.png) 已核验输入哈希。提前状态的重复 1 中，普通 kNN 选择距离 0.88181 的候选 3，续跑失败；受限 kNN 选择距离 0.89364 的候选 2，续跑成功。这个单案例表明最小距离不必对应成功动作，不能将候选评分当成动作成功概率。图像只能展示当时场景，不能据此断言后一个状态物理上不可恢复。

相同噪声池跨前后状态的选中候选一致次数：中心 39/46、外围 42/46、kNN 13/46、受限 kNN 23/46。中心与纯噪声中心的选择一致为 30/92。前两个选择器对状态变化较不敏感是描述性现象，不能仅据一致率认定因果机制。

## 验证结果

[验证独立审计](design/adaptive_control_validation_audit_20260908.json) 全部通过，包括 120 条完整 C0、55 个状态、1,100 条后缀的每个 query、全部四候选标签及冻结 kNN 分数。分析器与开发时哈希一致，未在验证集重新选择主要方法或调整参数。[完整分析](design/adaptive_control_validation_analysis_20260908/summary.json)、[指标 CSV](design/adaptive_control_validation_analysis_20260908/metrics.csv)、[比较图](design/adaptive_control_validation_analysis_20260908/interventions.png) 均已输出，图像已检查。

这里的纯噪声中心是在四个初始高斯噪声中，选择平均两两 RMS 距离最小的一个，再只执行一次模型前向。它沿用共同的 MoE kNN 报警触发器，但候选排序不使用 MoE 路由，也不需要额外三个候选前向。表中成本只计模型 query，不把 CPU 排序称为完全免费。

原生不干预成功率为 56.637%。随机续跑相对原生增加 0.221 pp，三个最高点估计相对原生增加 0.442 pp；扣除随机续跑增量后，控制净收益仅为 0.221 pp。两种参照的未来随机流不同，不能混用。

按十个 base task 聚类，边缘相对随机的 95% 探索性区间为 [-0.636, +1.304] pp；路由中心及纯噪声中心为 [0, +0.694] pp，均包含零，且没有多重比较校正。路由中心及纯噪声中心相对随机的均值变化都只出现在一条父轨迹。冻结的两项主要方法中，边缘点估计较好，持续短 chunk 未显示收益；不能看完验证结果后将次要方法改称预先验证的赢家。

### Pro 与 Plus

Pro 主要扰动为 43 条、Plus 为 70 条，另 7 条 Pro 原场景对照单列。Pro 的随机救回为 1/116，路由中心和纯噪声中心各 2/116，边缘 3/116；本批 Pro 没有原生成功且可干预的状态，无法估计该子集的破坏率。

Plus 的所有方法均为 0/72 次失败救回。边缘及普通 kNN 各破坏 1/28 次，持续短 chunk 破坏 2/28 次；随机、路由中心、纯噪声中心和受限 kNN 均未观察到破坏。本次收益集中在 Pro，未观察到 Pro/Plus 一致改善。

四候选的事后最优上限为 4/188 次失败救回，涉及两条 Pro 主轨迹：`51d28cdddd8a5c69f33028d5`（把两个摩卡壶放到炉上）和 `b0ab5dfc8f6009e5505ca6d1`（把汤罐和番茄酱放进篮子）。188 个失败候选池中只有 4 个包含成功续跑；Plus 的 72 个池全部四候选失败。这个上限只约束当前四候选、当前时刻和续跑协议，不是环境的理论可恢复上限。

## 判断与后续方向

1. 当前样本的收益与成本折中以纯噪声中心为优先基线。MoE 路由中心未超过这个不使用路由做候选评分的负控，不能将小幅增益归因于 MoE 排序。
2. 报警后，候选覆盖本身有限；四候选全部失败时，更换这些候选的排序规则不能救回。后续应同时研究可恢复动作的覆盖和基于当前及过去信息的更早干预。
3. 提前状态的受限 kNN 和路由中心值得保留为假设，但目前只有一条开发轨迹支持。提前 q-5 使用了未来报警时间，下一轮必须先冻结可因果执行的触发规则，并用新的父轨迹验证，不能直接部署这个诊断规则。
4. 不据本轮提高 chunk 干预强度。两步控制在开发集、五步连续控制在验证集均损伤了原本成功的续跑，增加重规划频率没有表现出稳定收益。
