# 固定一套参数的报警比较

日期：2026-09-08。按本次要求，每种方法在全部轨迹上使用同一份全局配置，不按任务、套件、checkpoint 或折切换参数。v7/v8/v8.2 直接使用原版冻结参数；本轮没有重新确认或调整它们的工作点。

此前的分折重校准是额外的泛化实验，改变了原版报警器的尺度和阈值，不能用其 3%..4% 的误报率代表原版。本轮原版整体误报率仍为 **0.489%、0.544%、0.589%**。

后续补充：[余弦与欧氏 KNN 组合检查](KNN_COMBINATIONS.zh.md)，复用本报告配置计算 OR/AND 和交叉选点打分；本报告中的参数与结果未因此调整。

## 数据与口径

完整计算 HUB 中 A/B 两批的 **32,000 条轨迹、508,023 次真实 query**：1,096 条最终失败，30,904 条最终成功，覆盖 Goal、Long、Object、Spatial 四个套件、40 个任务。

`FPR = FP / (FP + TN) = 结束前至少报警一次的成功轨迹数 / 全部成功轨迹数`。同一轨迹重复报警只计一次；只评价真实 query，不计结束后的 padding；不会因为报警较晚而剔除 FP。召回率为 `TP / 全部失败轨迹数`，报警精确率为 `TP / (TP + FP)`。

“一套参数”指每种算法的配置始终固定，不是让不同量纲的分数共用同一个数字阈值。v8.2 的时间斜率仍固定为 `-0.0015`，有效门槛按原公式随 q 变化；每条轨迹开头的基线计算也沿用原算法。

## B 批单列

B 有 16,000 条：564 失败、15,436 成功。B 没有参与本轮全局参考库、归一化或阈值拟合。A 使用噪声种子 1000..1007，B 使用 1008..1015，但任务和初态与 A 重复，因此这是已知任务/初态上的新噪声重复，不是未见任务测试；这些数据也已被此前研究查看过。

固定配置下，KNN 比 v8.2 净多检出 42 条 B 失败，也多出 116 条成功误报；C32 最近簇半径比 v8.2 净多检出 3 条失败、多出 62 条误报。C4 的完整轨迹工作点并不优于 KNN；此前分折实验中的排序不能搬到此处。这是各自固定工作点的比较，没有对齐实际 FPR，也没有在 B 上扫阈值。

不同套件仍有差异，例如 B 的 Long 上，v8.2、KNN、C4 的 FPR 分别为 2.067%、4.026%、6.924%。逐套件结果只用于观察，没有据此换参数。

## 实际冻结的参数

v7 原参数：`periodicity_scale=0.020707666873931885`，冻结头阈值 `0.5740630626678467`，加速度头阈值 `0.10750749707221985`，周期头阈值 `0.3749159276485443`。布尔逻辑仍为 `freeze OR (latched_acceleration AND latched_periodicity)`。

v8 新头阈值仍为 `frontback_flowpath=0.0`、`curvature_3step=0.3890000581741333`，平滑宽度 6、确认次数 2；v8.2 额外沿用固定斜率 `-0.0015`。没有运行 padding 修正后的阈值版本。

KNN/KMeans 此前只有分折、分 checkpoint 的参考库，没有现成的单个全局版本。本轮保留既有 10D 特征、k=20、C=4/32 等设置，从 A 一次性创建并冻结全局版本：

- 固定种子 `20260908`，将 50 个初态分为 30 个参考、10 个定标、10 个 A 留出；同一划分用于全部任务。
- 9,600 条 A 参考轨迹计算统一尺度；成功的 9,275 条中按既有取点规则形成 4,096 点参考库。所有 checkpoint 共用这一个 10D 动力学库，未混合原始专家 ID。
- 3,200 条 A 定标轨迹中的 3,103 条成功轨迹形成 399 个 task/init 组。沿用名义 5% 组峰值预算，每种方法一次取第 380 个顺序统计量，随后冻结。没有预算扫描或按 B 的结果调整。
- 3,200 条 A 留出轨迹另列为 `A_geometry_holdout`；该名称只表示未参与本轮几何方法拟合，不表示它们未参与历史 v7/v8 开发。

| 几何方法 | 唯一全局阈值，分数严格大于时报警 |
|---|---:|
| 欧氏 KNN-20 | 2.38411808013916 |
| KMeans C4，最近簇半径 | 1.7257059812545776 |
| KMeans C32，最近簇半径 | 1.6854066848754883 |
| KMeans C32，簇并集半径 | 1.5784103870391846 |
| 仅 10D 范数 | 7.9633941650390625 |

名义 5% 是成功 task/init 组峰值的定标规则，不是测试轨迹 FPR 必须等于 5%。C4 也是此前探索过的候选，不应描述成新的盲选配置。

全部数值、参考成员、簇中心/半径和源文件哈希见 [冻结配置目录](design/frozen_alarm_comparison_20260908/profiles) 及 [parameters.json](design/frozen_alarm_comparison_20260908/profiles/parameters.json)。参数文件 SHA-256：`f4e65d359411309756b008423d14d8f3e5d6bf604ee71b63ae8a7e510c5f8216`。

## 报警时机与采集数量

完整轨迹的检出不能直接解释为能及时救回。在同一套参数下，截至 q13，B 的 v7/v8/v8.2 分别检出 20/26/29 条失败；KNN、C4、C32 最近簇半径分别检出 75/115/63 条失败，对应 FP 为 58/139/54。q 从 0 开始，这批记录每次 query 通常执行 10 个动作，q13 约对应已执行 130 个动作，不含初始化静置。

若后续同时记录 v7、v8.2、KNN、C4 每种方法的首次报警，按 `(main_id, query_id)` 去重，本轮 32,000 条主轨迹共有 1,814 条发生至少一种报警，共 3,306 个不同报警状态。每状态展开 C0 x1、C1 x4、T1 x4，则为 29,754 条后缀。B 对应 918 条主轨迹、1,684 个状态、15,156 条后缀。这个预算只适用于所列四方法和当前 LIBERO 数据。

主轨迹不干预、报警保存状态、主轨迹结束后再展开分支的顺序不变，chunk 边界不重置报警历史。本轮没有新增 Pro/Plus rollout，其报警率和干预收益不在这些表中；后续可以直接加载这份冻结配置采样。

## 验证与复现

完成 288,000 个轨迹级判断核验，其中原版 v7/v8/v8.2 的 96,000 个首次报警与历史记录逐条一致。核验所有有效 query 掩码、六个全局阈值、参考/定标成员及 B 未参与拟合；另外直接用距离公式检查 32 个真实点，验证 32 条轨迹的批次顺序与前缀因果性。

第二次通过 `--profiles` 直接加载同一份配置，未调用建库或阈值拟合步骤，全部分数、阈值、首次报警和指标 CSV 完全一致。参数文件及参考文件在计算前后哈希不变。全程 CPU 离线处理，未加载模型、未采集 hidden、未占用物理 GPU 6。

复现命令，输出目录必须尚不存在：

```bash
python compare_frozen_alarm_methods.py \
  --profiles design/frozen_alarm_comparison_20260908/profiles \
  --output design/frozen_alarm_comparison_reproduction
```
