# 一次推理内 flow 去噪走不走直线 / 动作猜测变不变

> 2026-09-03。纯离线，无新 rollout、无 GPU 占用。数据是两批已有的完整 11 点 flow 轨迹捕获。
> 复现：`OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 python3 analysis_flow_straightness/run.py`

## 结论

**是直线，而且非常直。动作在第一次前向之后就基本定了，后面 9 轮只是把 7% 的误差磨到 0。**

但有一条不能顺推：**不能直接早停输出当前潜变量 `x_m`**。动作信息在第 1 轮就存在，可它藏在
**速度**里而不在**位置**里 —— 必须做一跳外推 `x̂ = x_m − t_m·v_m` 才能读出来。裸 `x_m` 到第 9 轮
仍差 14.5%（A）/ 16.4%（B）。

## 口径

采样器是固定步长 Euler：`x_{m+1} = x_m − dt·v_m`，`dt = 0.1`，`t_m = 1 − 0.1m`，共 10 轮。
因此速度场可由相邻两点**精确**还原：`v_m = (x_m − x_{m+1})/dt`，不需要重跑模型、不是近似。

只用前 7 个"活"维；`dim 7–23` 是 padding（末点 std≈1.0–1.1，仍在噪声尺度）。相对量分母统一取
`‖x_10‖`，与 2026-08-22 的 `audit_flow_stop_gate.py` 同口径，可直接对表。动作单位换算用末点到
可执行 chunk 的逐维仿射（拟合 `r ≥ 0.9999`），量程是 LIBERO 的归一化命令 ±1，**不是米/弧度**。

## 三、为什么应该是直的

上游训练用的是标准线性（rectified）flow matching：

```python
# src/moevla/models/moevla.py:343
x_t = time_expanded * noise + (1 - time_expanded) * actions
u_t = noise - actions
```

目标速度 `u_t` 沿每条条件路径是**常数、与 t 无关**。把它代入本文的外推式：

```
x_t − t·u_t = [t·noise + (1−t)·action] − t·[noise − action] = action
```

也就是说 `x̂ = x_m − t_m·v_m` 不是启发式，而是这个训练目标的**精确代数反解**；而"直线"正是目标
本身要求的形状。所以本文测的不是"意外发现模型走直线"，而是**这个学到的边缘场在实际推理中做到
了多直** —— 答案是路径超长仅 0.2%、方向 cos 到三位小数为 1.000。

## 四、和已有结论的接口

块内谱那篇（`vla-idea/2026-09-03-块内路由网格谱结构.md`）测到方差分解为
**token 主效应 72% / 去噪 12% / 交互 15%**，且 12 组 layer-pair 的 cascade 最大相关延迟全部为 0。
本文给出了机械解释：**轨迹是直的、速度几乎不变，所以 10 轮里每轮看到的 `x_t` 方向几乎相同，
沿去噪轴本来就没有多少新信息可读**。"逐层传播找不到"和"去噪轴只占 12%"是同一件事的两个侧面。

## 五、边界

- 两批共 885 行、**2 个任务 / 2 个 checkpoint**（A 是 CPU 位确定，B 是 GPU），任务覆盖窄。
  效应量极大且两批同向同量级，但这不能替代跨全部四个套件的确认。
- 本文只回答几何/表示问题。**行为后果没有验证**：截断到 r=5–6 会不会掉成功率，取决于
  `runs-trunc-pilot/`，而该先导的 `arm-r6` 只跑到 **19/128** 就停了（2026-08-22 20:48）。
  按其预注册"不中途窥视、两臂全部完成后一次分析"的冻结条款，这里不读中期结果。
- 直线性是在模型内部潜空间的 7 个活维上测的；padding 维（7–23）也在动（位移约活维的 0.57 倍）
  但始终停在噪声尺度，不进入动作。
- `x̂` 与最终动作的差异是否行为无关，只有换 seed 的 4.94% 这一个锚；该锚"不改变成功率"的证据
  来自既有候选实验，不是本文重测的。
