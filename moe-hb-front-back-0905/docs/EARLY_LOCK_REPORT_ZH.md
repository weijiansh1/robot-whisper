# 换目标函数重选 lock 头：L2 单层在提前区间优于全层中位

日期：2026-09-05
前置：`SURVIVAL_BASELINE_ADDENDUM_ZH.md`

## 1. 结论

附录显示，v4 只有 18.5% 的检出落在存活先验仍低的区间，其余大部分重复了"跑得久"已经知道的事。
说明**整体精度是错误的选择目标**——它奖励报得晚。

本实验保留 v4 的全部机器（同样的 mobility 表征、同样的因果滑窗、同样的连续确认、同样的
outcome-blind 同任务分位阈值、同样的 `lock OR L5 instability` 结构），只把网格的**排序目标**
换成"最大化低先验区间的提前检出"。9,240 个开发集候选，约束为 v4 同级的 `timely FPR ≤ 0.5%`。

结果：**HB 第一层 L2 单独作为 lock 表征，在提前区间上明显优于 v4 的全八层中位。**

| 规则 | 总 TP / FP | 低先验 TP / FP | 低先验精度 | 总召回 |
|---|---|---|---:|---:|
| v4（all_median q0.75 OR L5） | 410 / 81 | 76 / 54 | 0.585 | 0.727 |
| 目标 A 选中：L2 q0.60 OR L5 | 307 / 99 | **87** / 80 | 0.521 | 0.544 |
| 目标 B 选中：L2 q0.80 OR L5 | 270 / 42 | 72 / **27** | **0.727** | 0.479 |
| 入围未选中：L2 q0.75 OR L5 | 288 / 50 | **81 / 36** | 0.692 | 0.511 |

L2 的三个操作点构成一条**整体位于 v4 外侧的前沿**：同样或更多的提前检出，更少的提前误报。

## 2. 增益来自哪里

低先验区间（先验 < 0.25）分 suite：

| 规则 | goal | long | object | spatial | 合计 |
|---|---|---|---|---|---|
| v4 | 32 / 1 | 37 / **51** | 7 / 1 | 0 / 1 | 76 / 54 |
| L2 q0.70 | 39 / 3 | 38 / 33 | 6 / 2 | 0 / 7 | 83 / 45 |
| L2 q0.75 | 38 / 3 | 37 / **28** | 6 / 1 | 0 / 4 | 81 / 36 |
| L2 q0.80 | 37 / 3 | 29 / 20 | 6 / 1 | 0 / 3 | 72 / 27 |

两处来源：

1. **`libero_long`：同样的 37 个提前检出，误报从 51 降到 28。** v4 在 long 上的提前误报占它
   全部 54 个提前误报的 94%，L2 把这一项砍掉近一半。
2. **`libero_goal`：38 vs 32 个提前检出**，代价只有 2 个误报。

`libero_spatial` 在两者下都是 **0 个提前检出**。附录已指出五条层规则在 spatial 上提升全部
≈ 1.00；这里进一步确认：不是阈值问题，spatial 在 mobility 表征下根本没有可提前读出的信号，
换表征、换分位数都不产生任何低先验检出。

## 3. 代价：放弃晚期检出

L2 q0.75 的总召回是 0.511，v4 是 0.727——少了 122 个检出。这 122 个几乎全在高先验区间，
按附录的测量那里的提升倍数只有 1.00–1.02，即"存活即已判死"时才报的那些。

所以这笔交易是：**用 122 个近乎无信息的晚期检出，换 5 个提前检出加 18 个更少的提前误报。**
是否划算取决于报警拿来做什么。要做干预决策，L2 更好；要做事后统计覆盖，v4 的总召回更高。

## 4. 为什么是 L2

L2 是八个 HB 路由层里的第一层。`REPORT_ZH` 的结构分析给出前/后层跨 query 条件图响应比为
7.35，并把前层解释为"输入反馈通道"——对 observation 变化更敏感。本实验是这条结构结论在
检测侧的直接对应：**最靠前的层最早看到问题**。

需要注意这不是附录的结论。附录按**逐报警信息量**排序时前层组整体最高（front lock 提升 6.03
vs back 3.76），本实验进一步定位到具体是 L2 而非整个前四层的聚合——`front_median` 与
`front_mean` 的对应点都不如 L2 单层（见 `results/early_lock/external_shortlist.csv`）。

## 5. 选择纪律

必须说清楚，本实验用了两个目标函数：

- **目标 A（运行前预注册）**：`low_prior_tp → low_prior_precision → risk_recall`。它完全不惩罚
  提前误报，选出 L2 q0.60，用多 8 个开发集提前 TP 换了多 35 个提前 FP。**这个目标定错了。**
- **目标 B（看到 A 的结果后声明）**：在 `low_prior_tp ≥ v4 的开发集值(45)` 约束下，按
  `low_prior_precision` 排序。选出 L2 q0.80。

**目标 B 是对同一开发集的第二次审视，不是独立确认。** 两个目标都写进了脚本并各自回放，
`selection.json` 中 `objective_B_declared_after_objective_A: true`。

还要说明：严格支配 v4 的那个点（L2 q0.75，81/36）**没有被任何一个目标选中**，它只是出现在
两个目标的开发集入围名单里。它在开发集上也支配 v4（50/13 vs 45/40），因此不是只在 external
上才好看，但把它单独拎出来引用属于事后挑选，本报告不把它当作选定结果。

## 6. 限制

- external 8B 在 v3–v6 及本 bundle 前序工作中已被反复查看，不是全新盲测。
- 存活先验在被评分的同一 cohort 上估计，与附录同一限制。
- 低先验阈值 0.25 是人为切点。前沿形状对该切点的敏感性未做扫描。
- 阈值仍是**同任务经验分位数**，需要运行时 task ID。与 `moe-v7-0905` 的任务无关设定不同，
  两边数字不可直接比较；本结论也未在未见任务/未见 suite 下验证。
- `libero_object` 的提前检出只有 6–7 个，该 suite 的比较无统计意义。
- 本实验只换了选择目标，没有改进检测量本身。spatial 的 0 提前检出说明表征层面仍有硬限制。
