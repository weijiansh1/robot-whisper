# MoE 动作 token 的路由几何：形状、稳定性，以及失败前是否形变

目录：`moe-token-geometry-0906/`　日期：2026-09-06　设备：仅 CPU（八张 GPU 当时 139/143 GB 占用、79–100% 利用率）

## 0. 结论速览

**一、几何形状是确定的：十个动作 token 在路由空间里是一条一维有序弧线（arc），不是团、不是环。**
在合并的 development 模板上，第一主轴与 token 序号的相关系数为 0.958–0.998，第二主轴与 token 序号的平方相关 −0.912 到 −0.999（典型的 horseshoe/arch 特征）。八层的模板距离矩阵全部满足 Robinson 性质（每行每列的 d(i,j) 随 |i−j| 单调递增）。在 632 个（任务 × 层）组合中，有 630 个同时满足 Robinson 性质、且点云直径恰好是 token 1 与 token 10 这一对。形状谱（去中心化后）的有效维数（participation ratio）后层 2.50–2.63、前层 3.10–3.72；覆盖 90% 形状方差需要后层 4 维、前层 6–7 维。

**二、这条弧线极其稳定，而且几乎与任务无关。**
任务级模板到合并模板的 full Procrustes disparity 中位数 0.0021–0.0064（≈2.6°–4.6° 的 Procrustes 角）；同一任务在 development 与 external 两套采样设计之间只有 0.00015–0.00075；同一任务内奇偶 flow seed 对半切分只有 0.00027–0.00136。也就是说**跨采样设计/跨种子的差异，比任务之间的差异小 11–27 倍**。45 条 token 距离在 dev 与 ext 同任务之间的 Spearman 中位数 0.9976–0.9991、最小 0.9920，与既有的 0.9990 结论一致。

**三、单次 query 的形状抖动，比任务之间的差异大 20–30 倍；而"知道是哪个任务"对单次 query 几乎没有帮助。**
单 query 到合并模板的 Procrustes disparity 中位数 0.060（L13）–0.089（L3）。若换成该 query 自己任务的模板，中位数只下降 2.7%–7.4%。这直接支持用 global（不含任务身份）阈值，也说明这套几何是模型级的、不是任务级的。

**四、后层更刚性、更有序、更低维——在 37/37 个 development 任务和 39/39 个 external 任务上方向完全一致。**
后层单 query 到模板的 Procrustes 距离更小（中位 0.061 vs 前层 0.085）、bandedness 更高（0.904 vs 0.793）、形状有效维数更低（2.23 vs 2.70）、第一主轴占比更高（0.629 vs 0.560）。这与"后层相对 token 结构分化更强"的既有结论方向一致（本目录用同一份缓存复算的 partial 相对边散度 back/front = 6.00，37/37 任务同向；已发表值 6.17）。

**五、失败前几何确实会形变，效应可复现，但方向是"弧线的一维秩序退化"，而不是"整体崩塌"。**
在"chunk q 时仍在运行"的条件下做任务内 AUC（这一条件精确抵消了生存基率），用 development 选定层、external 只读一次：`bandedness`（距离-滞后相关，衡量弧线有多"一维"）在 chunk 8–24 的 8 个点上外部 AUC 全部 < 0.5（0.361–0.449，平均 |AUC−0.5| = 0.086），与 development 的符号 8/8 一致；`size`（构型尺度）全部 > 0.5（0.538–0.626，平均 0.076）；`procrustes_layer`（到语料模板的形状距离）全部 > 0.5（0.549–0.576，平均 0.063）。作为锚点，`mobility` 在它自己的 development 选定层上，同样 8 个 chunk 的平均 |AUC−0.5| 只有 0.038，且 dev/ext 符号只有 4/8 一致。

**六、但是——作为报警器，几何量没有打败已有基线。这是本次的主要阴性结果。**
在完全冻结、与已发表 frame survey 逐字一致的报警流程下（控制量精确复现了已发表的 `conditional_effective_rank` 与 `mobility` 计数），external 上最好的几何量：
- global 阈值：`procrustes_prev`(L13, high, 0.975) → 61 TP / 10 FP，precision 0.859，匹配先验 0.489，**lift 1.755**，recall 0.108。基线 L12 mobility 是 195 TP / 17 FP、precision 0.920、lift 1.764。lift 打平，但真阳性只有 1/3。
- per_task 阈值：`lam1_share`(all_median, low, 0.850) → 226 TP / 65 FP，precision 0.777，lift 1.455，recall 0.401。基线 expert-load 有效秩是 370 TP / 93 FP、lift 1.548。
- development 上限（未看 external 时）：per_task 下 mobility 在 FPR≤0.005 时最多 355 TP，最好的几何量 `bandedness` 244 TP；global 下 mobility 235 TP，最好的几何量 `procrustes_prev` 170 TP。几何量在这套报警器结构下**确实弱一档**，不是被选择规则卡住的假象。

## 1. 构造与正确性检查

对每次 query、每个 HB 层，取最后一步去噪的 `hb_router_probs`，归一化后开平方得到 11×32 的单位向量组，做 Gram 矩阵后对 state token 取 Schur 补：

```
conditional = gram[1:,1:] − gram[0,1:] gram[0,1:]^T        (10×10)
```

因为 `gram[0,0] = 1`（实测 0.9999999–1.0000001），这正是 state token 的 Schur 补，因而 PSD。实测最小特征值 ~1.2e-5 > 0，秩为 10。于是 d²(i,j) = K_ii + K_jj − 2K_ij 是真正的欧氏平方距离。

- 与参考实现 `moe-hb-front-back-0905/experiments/extract_layer_graphs_gpu.py::compute_batch` 的 55 维 conditional 向量逐元素最大绝对误差 **2.4e-7**（float32 舍入量级）。
- **形状**用去中心化 Gram `B = J K J`（J = I − 11ᵀ/10）的谱，与已发表的 `conditional_effective_rank`（用未中心化的 K 的谱）是**不同的量**：两者在 development 全部 221,781 个 query 上的 |Pearson| 最大只有 0.27（shape_pr）/0.34（shape_erank）。
- 形状距离一律用 full Procrustes disparity `1 − (Σσᵢ(XᵀY))²/(tr B_X · tr B_Y)`，对平移、旋转、反射、整体缩放都不变，取值 [0,1]，等于 Procrustes 角的 sin²。

**报警流程的接线检查**：把已发表的 `conditional_effective_rank` 与 `mobility` 当作对照量塞进本目录的流程，external 结果必须逐个数字对上，否则脚本直接报错：

|---|---|---|---|---|
| kernel_erank (= conditional_effective_rank) | per_task | L13 / low / 0.900 | 103 / 10 | 103 / 10 |
| kernel_erank | global | L3 / high / 0.925 | 88 / 158 | 88 / 158 |

## 5. 为什么没有做持续同调

拓扑摘要在这里没有信息可加，理由是构造性的而非偷懒：
- 632 个（任务 × 层）组合中 **630 个**的距离矩阵是 Robinson 矩阵，**且**点云直径恰是 (token 1, token 10) 这一对（两个例外都在 development_main 的 L3）。
- 直径落在两个端点上 + 行列单调 ⇒ 这是一条**开弧**，不是环。10 个点的开弧其 H1 恒为平凡，H0 的持续图完全由近邻距离决定，而近邻距离已由 §2 的 lag profile 给出。
- 谱几何已经把问题回答完了：λ₁ + λ₂ ≈ 0.70–0.80，PC1/PC2 与序号的一次/二次关系 |r| ≥ 0.91。

因此本目录只用谱几何 + Procrustes，不引入持续同调。

形状谱与一维有序性是新量；`size`（构型尺度 √tr B）与已有的 `conditional_effective_rank` / `partial_edge_std` 重叠明显，它在 §6 里的效应不应被当作全新发现。

## 9. 局限（照实说）

1. **没有做任何子采样。** 三个 cohort 的全部 valid query 都进了流程：development_main 221,781、development_extra 31,941、external_8b 248,255。所有 external 结论都在完整 external cohort 上评估。
2. **只用了最后一步去噪**，这是题目指定的构造；中间去噪步的几何没有看。
3. **chunk ≥ 16 之后样本被 libero_long 主导**（dev chunk 16：3,554 存活中 2,719 是 long；chunk 32：515 全部是 long）。任务内 AUC 在方法上处理了这一点，但 chunk 28/32 的数字实质上只是 long 套件的结论。
4. **"每个 chunk 取最好层"的表是乐观的**（在 8 层上取最大）。§6 的表已改成"层由 development 固定、external 只读一次"，数值比逐 chunk 取最大低一档；两版都在 `results/effect/` 里。
5. **效应量本身不大**：external 上 chunk 8–24 的最大 |AUC−0.5| 是 0.139（bandedness, L5, chunk 16）。它可复现，但不足以单独支撑一个高精度报警器。
6. **AUC 与报警性能测的不是一回事**：AUC 看的是中心秩分离，首次穿越报警器吃的是极端尾部行为。mobility 在 §6 的 AUC 表现平平却是最好的报警器，正说明这一点；不能用 §6 的排序去推翻 §7 的排序。
7. **误报独立性比值不可信**（分母上的期望重叠 < 1），只报了原始共同误报数。
8. **事后（post-hoc）标注**：`build_manifest.py` 与 `development_ceiling.csv` 是在看过 external 表之后补写的**汇总/复算**产物，不改变任何选择；§6 的"固定层"读数方式是在看过"逐 chunk 取最好层"的表之后决定的，属于对同一 development cohort 的第二次审视，已按此定性，不作为独立确认。§7 的检测器选择规则在跑之前就是冻结的（直接从 `moe-hb-front-back-0905` 引入常量）。

## 11. 下一步建议

1. **把弧线退化做成一个复合量再评一次**。`bandedness` ↓、`lam1_share` ↓、`procrustes_layer` ↑ 在 external 上是三个符号 8/8 一致、彼此机制相通的信号。本次只逐个评了标量；一个预先声明的复合（例如三者的秩平均）值得在 development 上选、在一个**新的**外部 cohort 上评（不能再用 external_8b，它已被读过）。
2. **换报警器结构**。现在的"首次穿越 + 连续确认"吃的是极端尾部，而几何信号是中心分布的整体漂移。CUSUM 或"相对自身早期 k 个 chunk 的累计形状漂移"更匹配 §6 的效应形态，而且仍然是因果、无任务身份的。
3. **看中间去噪步**。本次只用了第 10 步。弧线在去噪过程中如何形成（token 顺序是一开始就有，还是逐步析出）可能比终点形状本身更能区分失败。
4. **long 套件之外的早期段**。chunk 8–14 是 goal/object/spatial 还大量存活的窗口，也是先验最低（0.036–0.101）、最值钱的窗口；目前几何量在那里的 |AUC−0.5| 只有 0.05–0.09，需要专门为这个窗口设计量，而不是复用同一批标量。
