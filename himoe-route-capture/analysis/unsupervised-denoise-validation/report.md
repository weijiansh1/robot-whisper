# 无监督逐次推理早停：现有结果与验证清单

日期：2026-08-22

## 研究口径

- 每个 policy query 独立判断是否提前结束本次 10 轮去噪，下一控制步重新从第 1 轮开始。
- 不要求环境真的执行动作块里的每一个动作；分析对象是本次推理内部的 10 轮状态、MoE 激活和最终输出动作块。
- “有信息”只表示信号与第 10 轮动作的差异有关，不自动等于能提高在线任务成功率。
- 成功率只能由同任务、同场景、同 seed 的在线配对 A/B 给出；离线 endpoint 只能作准入门。
- 真正的 routed 激活定义为
  `RMS_hidden(sum_e normalized_topk_weight_e * expert_e(h))`，先向量求和再算 RMS，包含专家输出之间的抵消；路由概率或 top-k 权重大小不能冒充这个量。

## 先说结论

1. 旧的 Long 第 8 轮“28.2% 不安全”结论使用了不合适的 7 维相对 L2：它把夹爪连续幅度变化也当成了物理动作误差。PandaGripper 实际只使用符号。改成前 6 维物理尺度误差、夹爪只看符号后，固定第 8 轮在 Long 上只有 `7/181 = 3.9%` 超过 Goal 的经验参考带，夹爪符号翻转为 `0`。
2. 固定轮数目前仍是最强基线。固定第 9 轮在 Long 上节省 `10%` 且 `0/181` 超经验带；最佳冻结动态规则只节省 `6.1%`，同样 `0/181`，被固定第 9 轮严格支配。
3. 在约 `20%` 的匹配节省下，最佳动态信号有 `34/704` 个 Goal 样本超经验带，固定第 8 轮为 `36/704`。只少 2 个样本且计算量略低，证据不足，不能说动态规则胜出。
4. 真实专家激活幅度能稳定触发早停，但目前不能证明触发是正确的。`0.85 x 连续两轮` 平均理论节省 `20.78%`，然而 `86.8%` 的幅度变异仅由去噪轮次解释，它首先是一个“轮次时钟”。
5. 已补齐“真实激活 + 同一次推理 x_traj”的联合采集管线。下一次小采集可以直接检验激活是否含有超过固定轮次的剩余信息，不再靠不同归档间对齐。
6. 当前 t08 的固定 r6 在线配对先导仍在按预注册运行。它回答固定截断是否影响真实成功率，不中途读取结果，也不能替代激活动态停止的后续 A/B。

## 为什么原始激活幅度不够

原始幅度同时混合了三样东西：去噪轮次、层本身的尺度、当前样本真正的剩余困难度。前两项很强，第三项即使存在也会被淹没。因此下一步不是继续枚举更多阈值，而是先消掉共同模板，再问剩余量是否预测动作误差。

同样约 `20%` 节省的 level 与 flat 规则，逐 query 停止轮只 `23.0%` 完全一致，停止轮相关为 `-0.277`。这说明“它们都能省 20%”不代表它们抓住了同一种收敛机制；没有同次推理的动作标签就无法裁决。

## 可验证想法全集

### P0：先用现有数据完成或固定的检查

1. **Controller-aware 主尺度**：前 3 维平移、后 3 维旋转分别乘 action std；夹爪只看符号。报告 RMS、max/P95 和符号翻转，不再使用混合 7D 相对 L2。
2. **固定轮数基线**：任何动态规则都必须在相同平均去噪轮数下，配对比较固定第 9/8/7 轮，不能只与完整 10 轮比。
3. **外推器基线**：裸 `x_m`、常速度、常加速度分别报告。当前证据表明裸状态不可用，常速度/常加速度才是有效输出器。
4. **候选信息成本核算**：K=16 候选云 spread 虽然 oracle 信息较强，但 K=1 无法使用；若为了停止额外生成候选，其算力必须计入，否则“节省”是假的。
5. **同 checkpoint 迁移**：Goal 和 Long 来自不同 checkpoint，只能叫 checkpoint+任务迁移。真正的新任务验证必须在同一个 Libero-10 checkpoint 内按 task/scene 留出。
6. **相关查询聚类**：一个 rollout 内有很多 control query，但它们不是独立样本。置信区间和分割必须按 rollout/scene/task 聚类，不能按 query 随机切分。
7. **initial-noise-only 免费下界**：只用初始噪声范数、token/dim 离散度或固定 seed 模板做同预算选择。任何 MoE 内部信号必须先显著胜过它，否则只是重新编码了噪声模板。

### P1：真实激活与动作轨迹联合小实验

联合采集每个 query 的：

- `x_traj`: `[11 flow states, 10 action tokens, 24 dims]`；
- 8 个 HB 层、10 轮、10 个 action token 的 `routed/shared/total_mlp RMS`；
- top-k 权重和误差，作为归一化正确性的运行时断言；
- rollout、control step 和任务标识。

先验证这些无监督信号：

1. **query 内 level**：当前幅度除以本 query 第 1 轮幅度。
2. **下降速度**：一阶差分、相对斜率、连续两轮稳定。
3. **曲率与回升**：二阶差分、局部最低点、最低点后回升。局部最低点需要看到下一轮，因此天然少省一轮。
4. **去轮次模板残差**：每层先减去训练 rollout 的 round 中位模板，再看残差是否预测同 query 的剩余动作误差。这是最关键的“弱信号放大”。
5. **跨层一致性**：所有关键层都稳定才停；也测试末层 veto，避免平均值掩盖仍在变化的层。
6. **逐 token 尖峰**：mean、P90、max 和最大 token 的连续稳定；防止动作块中某一个未来 token 尚未收敛。
7. **routed/shared 比值**：只作为消融，不用 `routed+shared` 原始和；后者被 shared 分支尺度支配。
8. **幅度与 endpoint 一致性交集**：激活残差小且 `CV vs CA` 分歧小才停，检查两种弱信号是否互补。
9. **夹爪 veto**：外推夹爪符号不一致，或终点夹爪 margin 接近 0 时强制跑满 10 轮。
10. **阶段条件化**：episode 开头、中段、接触前后分别分析，检验停止信号是否只在某一控制阶段成立。

联合实验的第一个 oracle gate 只问：在固定 round、task 和 phase 后，信号能否给同轮的剩余 controller-aware endpoint 误差排序。若条件相关接近 0，就停止开发该信号，不做在线控制器。

### P2：比幅度更接近“实际影响”的内部信号

1. **方向变化**：记录 routed 向量跨轮 cosine，而不是只看 RMS。幅度小但方向剧烈变化时不应停止。
2. **固定随机投影 sketch**：为每层保存少量固定投影，近似方向、抵消和跨轮变化，不保存完整 1024 维 hidden。
3. **下游影响加权幅度**：估计 `||J_action * routed_output||`。raw RMS 可能很大但落在下游 null direction，也可能很小却对动作敏感。
4. **动作流自一致性**：速度变化、加速度、jerk、CV/CA 终点分歧、translation/rotation 分解。现有结果中这类信号比纯路由更稳定。
5. **专家集合变化与贡献变化联合**：分别记录专家 ID 是否换、权重是否换、真实输出向量是否换；“路由没换”与“贡献没变”是两件事。
6. **去重后贡献量**：对 10 个 action token 的专家集合去重，再比较独立专家贡献的增减，避免 token 重复计数把激活规模放大。

### P3：因果验证

1. **单轮 routed 缩放**：同 observation、同初始噪声，在某一去噪轮把 routed 分支乘 `0 / 0.5 / 1`，只比较最终动作块变化。
2. **低幅度与高幅度配对**：在相同 round、layer、task 下做上面的干预。如果低幅度轮的因果影响确实更小，幅度才有停止语义。
3. **逐层/逐 token 干预**：定位是否只有末层或未来 token 的 routed 分支仍有实际影响。
4. **短时程 fork + CRN**：从同一仿真快照执行候选动作块，再接共同未来噪声，量短时程进展和成功；这是真值标签，但只在离线门通过后做。
5. **分支尺度扫描**：结合已有 routed-off/shared-off/block-off，补中间尺度和更大样本，区分“网络鲁棒”与“分支无作用”。

### P4：最后的在线实验

只保留一个冻结动态规则，做同场景同 seed 的四臂配对：

- 完整 10 轮；
- 固定第 8 轮 + 冻结外推器；
- 动作自一致性动态停止；
- 真实激活残差 + 动作一致性联合停止。

主端点是成功率的配对差；次端点是平均去噪轮数、真实 wall-clock、控制步数和失败类型。GPU 同步、标量回传与 hook 的时间全部计入，因为少一次 forward 不一定等于真实延迟同比下降。

### P5：不以早停为目的的底层可解释性

已有全控制步结果覆盖 30 个任务、1500 条 rollout、18384 个 control query：相邻控制步的路由距离为 `0.0242`，rollout 内随机配对为 `0.0280`，连续性比 `0.8659`；后段/前段速度比 `0.9052`。同一 query 内，不同 control query 的差异从 denoise-0 的 `0.0184` 放大到 denoise-9 的 `0.0344`。这说明路由带有连续潜在状态，但还没有解释这个状态是什么。

可继续做以下完全无监督验证：

1. **路由变化点分段**：只用连续 control query 的路由/真实贡献速度做 change-point detection，检查同任务不同 rollout 是否出现可对齐的阶段数和转移顺序。
2. **跨 rollout 轨迹对齐**：用 DTW/最优传输对齐同任务的路由序列，测阶段原型能否在未见 scene 重现；不使用 success 标签。
3. **方差分解**：同 observation 多噪声、同噪声多 observation、不同 denoise round 分别占多少 routed contribution 方差，分清状态、噪声和 round template。
4. **专家功能谱**：按图像遮挡、语言 token 去除、proprio 扰动分别测专家真实贡献变化，建立视觉/语言/状态敏感性，而不是按专家 ID 猜功能。
5. **无监督专家因果图**：逐专家或专家组缩放，记录最终动作方向和幅度的响应矩阵；对响应矩阵聚类，寻找冗余组和互补组。
6. **route-to-flow 耦合**：比较贡献向量变化与 flow 速度、加速度和转向的滞后相关；控制 round 后仍存在的耦合才算内部机制证据。
7. **贡献子空间**：对固定随机投影或完整小样本向量做 PCA/CCA，测有效秩、跨层共享方向和跨任务稳定性；RMS 看不到这些结构。
8. **潜在有限状态机**：对连续路由残差聚类并估计状态转移图，检查转移是否近似单向、是否能预测下一 control query 的 cluster。
9. **新颖度/OOD veto**：以训练任务的阶段原型为参照，未见任务若路由残差距离过大就禁止早停。这里的用途是保守拒绝，不是拿 OOD 分数预测成功。
10. **阶段条件因果消融**：在无监督发现的阶段内分别做 routed/shared/expert-group 干预，验证某个阶段原型是否真的对应不同计算功能。

### SVD 补充实验结果

- 在 30 个任务、1500 条 rollout、18384 个 control query 上，路由 SVD 的前 64 维解释 `61.6%` 变异。只用训练 rollout 的先后顺序构造时间箭头，两个 15-task 留出集的 episode 中位 Spearman 为 `0.659 / 0.818`，两边均 15/15 任务同号。这提供了一个可重复的无监督内部控制进度轴。
- 该轴不等于物理任务进度：全局 PC1 的 task eta 为 `0.832`，前 32 维由 task 解释 `19.7%`，由粗阶段只解释 `5.1%`。
- 真实 routed 向量去掉 round 模板后，前 16 维解释 `50.2%`；但 scene/noise 主效应仍解释前 32 维的 `48.8% / 20.1%`。早轮到最终轮 CKA 在去掉 scene+noise 后仅从 `0.030` 缓慢升至第 9 轮的 `0.159`。
- 成功率事后扫描出现 `|r|=0.178`、FWER `p=0.036` 的弱峰，但冻结到另一半 scene 后为 `0.025 / -0.020`，没有复制。
- denoise SVD 不去模板时几乎完美读出轮次；去模板后平均 rho 只有约 `0.15`。前 64 个 query-route PC 也只保留 `53.3%` 的相邻变化能量。因此 SVD 适合做阶段对齐与变化点，不足以单独作为逐 query 早停器。

## 建议的小样本顺序

1. 等当前 CPU 在线先导结束，不抢占其资源。
2. 在同一 Libero-10 checkpoint 选至少 4 个任务，每任务先跑 2--4 条 rollout，但保存其中所有 control query。这样采集量不大，却覆盖任务和控制阶段。
3. 先跑联合 oracle gate 和固定轮数 matched-saving；未胜固定 round 就停止，不进入在线 A/B。
4. 只有一个预先冻结的规则进入新 seed 在线先导；不把 48,992 条规则里的事后最优值当结果。

## 准入与停止标准

- **管线门**：top-k 权重和误差接近 0；捕获的 routed 输出与上游 `HBMoE.moe_infer` 直接重算一致；state token 确实被排除；flow Euler 残差通过。
- **信息门**：在控制 round/task/phase 后仍有同方向的留出任务相关，并且不是只靠 round template。
- **选择门**：在相同平均计算量下，动态规则必须稳定优于固定 round；只少 1--2 个离线坏样本不算通过。
- **迁移门**：按任务/scene/rollout 留出，至少大多数任务同号；不同 checkpoint 的迁移只作附加压力测试。
- **上线门**：新 seed 配对在线 A/B 的成功率不过预设非劣界就关闭，不用 endpoint 结果替代成功率。

## 暂时不值得继续投入的方向

- 单独使用路由专家 ID、top-k 权重幅度或层间 Hellinger 作为停止器；已有跨任务翻转。
- 为可预测的“稳定性”训练自监督 head；稳定性不是真实任务价值，且此前 head 平均下降约 1.1 个百分点。
- 用 K=16 候选云结果声称 K=1 在线可用。
- 继续在没有 oracle gate、没有固定轮数 matched-saving、没有独立确认 seed 的情况下扫更多阈值。
- 把 endpoint 接近直接写成任务成功率不变。
