# 基于 MoE 路由变化的在线去噪停止实验

## 实验思路

- 每次 policy query 独立判断，不跨控制步，也不读取动作值、奖励、成功标签或仿真状态。
- 每轮去噪后，取 8 个 HB-MoE 层中 10 个 action token 的完整 32 专家概率；逐 token 归一化后取均值，再计算相邻轮之间的 RMS-Hellinger 变化。
- 冻结停止规则：至少完成 8 轮；最近连续两次路由变化都不超过 `0.0047` 时，立即输出当前动作块；否则完成全部 10 轮。
- 阈值只用此前完整路由轨迹校准，不使用任务结果。在线指标严格复现旧数据的 `float16` 存储和归一化尺度。
- 在线 A/B 使用 `LIBERO-Goal task 0 / init state 24 / flow seed 2000`。两臂都从同一初始状态重新开始：基线固定 10 轮，adaptive 在真实闭环中逐 query 决定 8 或 10 轮。

## 结果

| 方法 | 完成任务 | 环境动作数 | policy query | 早停 query | 平均去噪轮数 | 总去噪 pass |
|---|---:|---:|---:|---:|---:|---:|
| 固定 10 轮 | 是 | 107 | 11 | 0 | 10.00 | 110 |
| 路由停止器 | 是 | 110 | 11 | 4 | 9.27 | 102 |

- adaptive 的轮数序列为 `[10, 8, 8, 8, 8, 10, 10, 10, 10, 10, 10]`，真实减少 `8/110 = 7.3%` 的 suffix 去噪 pass。
- 第一次早停发生在 query 1，此后环境观测与基线自然分叉；因此结果来自真实在线闭环，不是完成 10 轮后再截断日志。
- 两臂都完成了任务，但 adaptive 多执行了 3 个环境动作。单条 rollout 不能说明成功率或控制质量不下降，只能说明这个停止机制能够在线触发，并在这一次运行中保留任务成功。
- 当前 CPU 实现为了在线得到完整 32 专家概率，会额外重算 router logits；所以 `7.3%` 是 suffix pass 数量的节省，不是已经证实的墙钟加速。

## 正确性检查

- 禁用停止时，新采样循环与上游原始 10 轮采样器的最终动作最大逐元素差异为 `0.000e+00`。
- 11 个 adaptive query 的停止决策离线逐条重放，全部与在线记录一致。
- 首个尚未分叉且都执行 10 轮的 query，两臂动作最大差异为 `0.000e+00`。
- 单元测试 `11 passed`，静态检查通过。

结论：纯 MoE 路由变化可以充当一个无需任务标签的在线停止信号；这个单次 pilot 实际节省了 7.3% 去噪 pass 并完成任务，但尚不足以证明它在新任务上稳定、无损或真正降低 GPU 延迟。
