# 全控制步 MoE 路由变化速度

## 实验思路

- 将每条 rollout 表示为完整的 policy-query 序列 `q0...q(T-1)`，控制步是唯一时间单位；不使用 action、robot state、reward、success 或 simulator progress。
- 使用每个 query 的 8 个 HB 层 x 10 个 denoise round；先逐 site 归一化完整 32 路概率，再平均 10 个 action token。相邻控制步速度定义为对齐 site 上的 RMS Hellinger 距离。
- 覆盖 30 个任务、1500 条完整 rollout 和全部 18384 个控制步；比较真实相邻顺序、episode 内随机顺序期望、1-8 步 lag、归一化早中晚阶段、逐层和逐 denoise round。任务是统计独立簇。

## 结果

共 `16884` 个相邻控制步转移。按任务等权后，真实相邻速度为 `0.0242`；rollout 内随机打乱顺序的期望为 `0.0280`，连续性比值为 `0.8659`（越小表示相邻路由越连续），差值 95% CI `0.0033` 到 `0.0043`，task-level sign-flip `p<0.0001`。

| rollout 归一化阶段 | 相邻路由速度 |
|---|---:|
| 前 1/3 | 0.0247 |
| 中 1/3 | 0.0254 |
| 后 1/3 | 0.0224 |

后段/前段速度比为 `0.9052`，差值 `-0.0023`；95% CI `-0.0037` 到 `-0.0010`，task-level sign-flip `p=0.0020`。

同一次 query 内，跨控制步变化从 denoise-0 的 `0.0184` 单调增至 denoise-9 的 `0.0344`（`1.8749` 倍）；不同 control query 的路由差异主要在后半段 denoise 被放大。

任务间绝对速度范围为 `0.0137-0.0367`：最快 `spatial/t00__pick_up_the_black_bowl_between_the_plate_and_the_ramekin_and_place_it_on_the_plate`，最慢 `goal/t05__push_the_plate_to_the_front_of_the_stove`。该差异只描述路由时间序列，不解释为物理执行快慢。

结论：路由不是每个 query 独立重置的白噪声；真实相邻控制步明显比任意两个 episode 内控制步更接近，距离随 control lag 增加后逐渐饱和。早中晚速度是否系统变快或变慢由上表的 task-cluster 检验给出，不借助任何物理动作或成败信息。
