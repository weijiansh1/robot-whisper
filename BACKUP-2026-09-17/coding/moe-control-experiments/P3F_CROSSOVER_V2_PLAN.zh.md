# P3f v2: 完整 MoE 输出边界的交叉对照

本协议继承 P3F_CROSSOVER_PLAN.zh.md 的 15 个固定输入、四个主对照和九次调用顺序，仅修订输出隔离范围与失败留存方式。

## 修订原因

初始 run p3f-crossover-20260915-w40v879v 完成了 5 次真实前向后停止。native/joint 精确复现 P3e，两次 identity replay 通过，但 action-token-only 的 route_only 在 mechanism/input 精确匹配处失败。前四次原始输出和第五次失败记录保留；第五次前向已完成，但旧收集器在断言后才保存，故该次完整张量没有落盘。不掩盖或删除这次失败，也不把这 5 次算作正式完整交叉矩阵。

HBMoE.moe_infer 将 token 按专家汇集后批量计算。改变动作 token 分派时，不能预先假定状态 token 的有限精度计算必然逐位不变。此为待定位的解释，不是已确认结论。

## 冻结修订

1. 先补两次 action-token-only 定位调用，分别为首个状态的 route_only 与 output_only。供体来自已精确复现的 P3e native/combo。只描述差异首次出现的位置，不据此搜索偏置或样本。
2. 随后仍按原协议执行 15 x 9 = 135 次正式调用。gate 偏置仍仅 L12-15、10 个动作 token、10 个去噪步。回填范围改为这四层的完整 MoE total 输出，包括状态 token，共 11 个 token。未改原门控函数、共享专家、残差路径或任何权重。
3. 这是诊断用输出钳制，不是额外设计的在线控制器。状态 token 回填用于隔离完整计算边界，不能将其描述为只动动作 token。
4. 每次先保存原始输出与回填后输出，再检查结构不变量。任何失败都保留原始响应，禁止静默放宽精度。
5. 主对照、两个原样回填、两个重复、撤销、旧供体复现仍要求逐元素完全一致。实际路由 ID 只在同一输入、同一门控规则下比较。
6. 新 run 固定 137 次调用: 2 次范围诊断 + 135 次正式交叉。加上原失败批次 5 次，本次用户请求的总调用预算为 142。无物理环境调用、无新增动作、无新强度搜索。

只有正式 135 次组成完整的 15 状态四组分析。范围诊断和初始失败单列报告。两版协议、代码与失败批次均保留哈希。其余检查、分数定义、开发样本局限和解释边界保持原协议不变。
