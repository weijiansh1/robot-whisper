# P1b：MoE gate 可控性探针

日期：2026-09-14。应用户再次要求“进行第一步实验”，独立执行最初提出的 gate 因果探针。P1a 的阴性判定及文件保持不变，本轮不把 P1a 改判为通过。

## 研究问题

固定模型、观测、初始噪声，仅改变 HB gate 的小幅偏置，哪些层、token 和去噪时段的变化真正传递到最终动作？

本轮不训练任何模型、不使用成功标签选择方向、不输入物体真值、不执行模拟器动作。可控性不等于正确的恢复方向，更不等于救回成功。

## 运行条件

- 保留原 9500 服务与 PID，不修改上游方法或运行环境。
- 独立进程加载同一个 Long checkpoint，原 FP32 参数、BF16 autocast 计算，禁用该进程的 autocast 权重缓存，参数设为不求梯度。
- PyTorch 显存分配器上限 16384 MiB；加载前确认额外余量。该上限不包含 CUDA 上下文等非 PyTorch 分配，另外保留余量。
- 原服务、独立裸推理、带全路由捕获、零偏置和移除偏置后的动作与 wire top-4 必须完全一致；不满足则停止。
- 复用上游 `ScopeBiasCapture` 实际 gate 干预 hook。只在本地适配响应审计，使概率归一化按实际 BF16/FP32 运算精度逐项核对，不改变 gate 运算。
- 在 BF16 下，先转 FP32 再重新归一化会与实际 BF16 权重不同。兼容测试已复现旧审计误报；本地审计要求原运算精度下权重完全相等，不放宽为任意误差容忍。

## 预检记录

预检配置固定为 Pro task00、init47、q8，仅做零偏置检查，不探索非零方向。

- `runs/gate-preflight-gb59_ywi`：独立模型成功加载，占用约 15551 MiB；因直接对象缺少 WebSocket 元数据字段而提前停止，模型调用 0。
- 修复使用原 `server_metadata()` 构造接口身份；另以 CPU/BF16 单元测试验证审计适配。
- 后续成功预检目录和哈希由正式 run 的 `config.json` 引用，所有预检开销单独计数，不隐去失败尝试。

## 样本

- 从 2026-09-14 本地 Plus / Pro 批次各选基础任务 0、3、6、9 的 `episode_index=1, init_state_id=47`，共 8 条父轨迹。
- 固定查询 q8，从零计数。缺失则记录、不按结局替换。
- 与 P1a 的 init26 父轨迹不重叠；基础任务仍为既有任务，本轮全部属于开发诊断，不宣称未见任务泛化。
- 完整 trace 与模型身份、源动作、观测/噪声和文件哈希必须验证。采集前冻结配置与实现哈希。

## 干预因子

| 因子 | 两个水平 |
|---|---|
| HB 层 | 前四层 2/3/4/5；后四层 12/13/14/15 |
| suffix token | 状态 token 0；动作 token 1..10 |
| 去噪时间 | 早期 0..2；后期 7..9 |

三因子产生 8 个互斥 scope，中间去噪步 3..6 不干预。

- 两个固定随机方向，所有父状态共用。每位置的 32 个专家中随机 16 个 +1、16 个 -1，严格中心化，不假定专家语义。
- 每个 scope 以 per-site RMS 0.05 和 0.10 施加正负扰动。绝对值最大 0.10，低于总安全边界 0.30。
- 同一方向的正负严格相反，两档幅度严格为两倍关系；未选中的位置偏置恒为 0。
- 每状态 8 scope x 2 方向 x 2 幅度 x 2 符号 = 64 个非零请求。
- 状态 scope 涉及 12 个路由位置，动作 scope 涉及 120 个。不能仅按相同 per-site RMS 宣称总干预能量相同；另外报告每单位偏置 L2 的动作响应。

## 配对与预算

每父状态按固定顺序执行：独立裸推理、全路由 native、全零 gate、64 个非零探针、两个固定探针的完全重复、最后全路由 native。

- 每状态 70 次独立模型前向，最多 560 次。
- 每状态向原服务发送 1 次合法固定噪声请求作交叉核对，结束后再用第一个状态检查原服务，共最多 9 次。
- 正式实验最多 569 次模型前向；其中 512 次为不同非零探针，另 16 次非零重复，不将它们算成独立父状态。
- 预检前向另记。所有模型前向，包括失败尝试，按日志核算。
- 每个请求独立安装并移除 hook；非选中和试验请求不写入任何在线控制历史。原服务请求只追加带独立 ID 的记录，不改配置。
- 不启动其他 GPU 模型；本进程结束即释放自己的资源。

## 记录与审计

- 保存每个请求的动作、完整 native/effective HB 概率和实际 top-4 ID/权重，以及独立 wire 捕获；同时保留 AS 路由。
- “native”概率是本次前向在当前位置加偏置前的概率，可能已受更早 gate 干预影响，不将它冒充完整未干预轨迹。
- 校验有效专家和权重等于真正返回给 MoE dispatch 的值；未选位置的即时 native/effective ID 和权重必须相等。
- 保存完整输入、bias 的可复算身份、随机流、每次调用时长、显存峰值、请求/响应账本和文件哈希。
- 零偏置及末尾 native 与开头 native 的路由和动作完全一致；两个非零重复的动作与全路由也必须完全一致。

## 预先指定的分析

主要表格按 scope 报告 amplitude=0.10 下的 6D 标准化动作 RMS 差异，先在每父状态平均方向/符号，再等权汇总父状态。0.05 幅度完整附报。

另外报告：

1. 位置与旋转的原始动作 RMS、夹爪符号变化。
2. 本地被干预位置的即时专家集合变化，以及相对完整 native 的下游路由变化。
3. 正负差分 `RMS((a_plus-a_minus)/action_std)/(2*amplitude)`；同时报告除以总 bias L2 的标准化动作 L2 响应。
4. 两档幅度响应比例、正负差分方向余弦与非线性偏移。无响应或零分母记为空，不强行解释为线性 Jacobian。
5. 每父状态明细、跨四个基础任务一致性和响应重复底线。不把 512 个非零请求当成 512 个独立样本。

所有 scope 一并报告，不根据结果隐藏弱效应。若所有完整性审计通过且出现可重复非零动作响应，可确认在这些状态和幅度下存在 gate 到动作的局部因果作用；不自动推出实际恢复收益。
