# P3d：多机制筛查控制器真实续跑协议

2026-09-15。用户同意继续验证 P3c 的“解冻＋平衡”候选。本协议在新增模型调用和环境后缀执行前冻结。

## 目标与边界

验证定向 gate 干预能否从指标可控转化为任务救回，并检查误伤、拒绝介入和额外成本。
这是五个已查看开发父轨迹的配对试验，不是独立留出评估；不重选状态、调阈值或依据本轮终局换参数。
只修改本次前向的 gate logits，不训练、不改原模型权重或结构、不修改共享 9500 服务。
MoE 路由决定干预方向和指标筛查；预测动作差与夹爪符号仅作继承的限幅检查，不使用奖励、未来状态或图像判断选择。

## 固定样本与实验臂

复用 P3c `p3c-response-matrix-20260915-463ir6kj` 的全部五个父状态，顺序不变：

| 父轨迹 | 报警后查询 | 首报头 | 原结局 |
|---|---:|---|---|
| plus-task00-init026 | 21 | curvature | 失败 |
| pro-task03-init039 | 18 | freeze | 失败 |
| plus-task06-init026 | 30 | turbulence | 失败 |
| plus-task03-init026 | 34 | inversion | 失败 |
| plus-task03-init039 | 23 | curvature | 成功，误报 |

每状态按 native、mobility、mobility_balance、random_balance 顺序运行四条独立仿真分支，共 20 条。
random_balance 是 mobility_balance 的逐位置专家维随机排列，不是单独 balance。
共同初态与报警前动作逐步精确重放；每条分支重新 reset，所有物理动作、奖励、成功标志和视频保存。
native 分支的全部输入、路由、动作、物理状态、视频帧与原轨迹精确复现，否则停止。
不省略拒绝介入后恰好与 native 相同的分支，也不把相同分支当独立父样本。

## 在线规则

保留 10 步动作块和最多 520 个动作步。首次报警发生于 q，介入从 q+1 开始，最多覆盖 12 个查询机会；
拒绝候选也消耗一次机会，不延长窗口；成功立即结束，窗口之后完全原生闭环。

每个非原生分支在窗口内：

1. 当前真实观测和原生 query-index 噪声进行一次 native shadow 前向。
2. 用 shadow 的完整 FP16 HB 概率和上一条实际执行响应的有效 FP16 HB，调用 P3c 冻结方向和能量公式。
3. 高档正向 mobility 或 mobility_balance 生成一个候选；random_balance 用组合的同能量排列方向。
4. 同观测、同噪声进行一次带请求级偏置的实际模型前向，记录真实 BF16 logits、概率、专家 dispatch 和动作。
5. 两个响应都在同一个已执行历史的副本上评分；按下述即时筛查选择候选或 shadow。
6. 决策先落盘，再把被选响应的原生 10 步动作块执行到环境。只有被选有效路由进入在线监测历史。

没有虚拟环境 rollout、奖励打分、候选之间的历史串扰或报警锁存重置。第一次候选必须精确复现 P3c 同标签响应。
方向退化时记录原因并回退 native，不发明替代方向，不重抽随机数。

## 方向、能量和筛查

复用 P3c 全五个单位方向计算共同能量，即 E=min(0.10*sqrt(12800), 0.30/最大方向峰值)。
只运行三个非原生实验臂，但保留五方向共同限幅，确保首查询与 P3c 高档探针完全一致。
后四个 HB 层、全部十个去噪步、动作 token 施加偏置，前四层和状态 token 直接偏置为零。
随机排列种子完全继承 P3c，把 query 更新为当前查询；不增加 run ID 或新的随机流。
同一个状态和观测下请求 L2 匹配；分支分叉后观测和能量可以不同，不宣称跨分支实际能量严格相等。
实际 BF16 舍入后的能量也单独记录。

执行条件完全继承 P3c 的即时筛查，所有条件同时满足：

- mobility 的目标为 freeze；两个组合方向的目标为 freeze 和 inversion。
- 每个目标的即时分量相对同观测 native 至少下降 0.05 个原 margin。
- 每个非目标即时分量恶化不超过 0.05 margin。
- 归一化六维预测动作 RMS 不超过 0.05，预测夹爪符号不变。

这不是已校准安全保证。保留原 v8.2 正式分数、移动阈值和平滑锁存，正式筛查仅记录而不作为第二重选择条件。
FP16 是冻结决策精度；FP32 复算作为敏感性分析，不事后翻转决策。
随机对照使用与 mobility_balance 完全相同的目标和筛查，但实际通过数可以不同。
本轮比较完整筛查控制器，不是“相同实际介入次数下仅换方向”的纯因果分解；必须报告拒绝理由、候选数和接受次数。

## 预算与质量控制

20 条环境轨迹，最多 10,400 个动作步，另有 200 个初始稳定步。
五个 native 首查询各追加 zero 与 post 两个零效应检查；五个组合首查询各追加一次预定非零重复，共 15 次额外前向。
各分支后缀最多合计 536 次基础前向，候选最多 180 次，故全部上限 731 次。
报警前物理重放不调用模型，单独计数，不能漏报环境步或混入部署控制器推理成本。
预估 35--45 分钟，独立模型沿用 16,384 MiB 分配上限；显存不足只停止本次加载，不停止其他用户进程。
采集失败保留已完成数据和失败标记，不覆盖续写，不从失败终局重新抽样。

新旧单元测试在采集前通过。配置和实现哈希提前冻结，源输入、P3c 产物及共享服务身份均只读检查。
独立审计不调用新控制协议来重建选择；从原始响应复算方向、筛查、历史、实际动作、终局与视频帧数。
采集完退出独立模型，再封存新 run 并确认旧六轮产物与源文件未变。

## 报告与停止点

主结果是每臂四个原失败状态的救回数、一个原成功状态的误伤数和每个父状态的实际终局步数。
同时报告按父状态的预测筛查通过、实际介入、拒绝理由、动作变化、分量轨迹、额外推理和仿真成本。
报告分叉前精确对照，不能拿分叉后的不同观测响应当成同观测处理效应。
保留 inversion 冲突状态；不得把即时下降当成功，也不得用报警精确率或召回率冒充控制收益。
五个开发样本不支持总体有效性或安全性结论。无论结果正负，本轮完整报告后停止，不自动扩展样本或搜索阈值。
