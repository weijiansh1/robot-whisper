# P3e: 路由到任务的传递链诊断

本轮按用户要求诊断“低于阈值仍失败”。不修改权重，不训练，不改共享服务，不改已封存的 P3d。

## 固定问题与样本

- 复用 P3d 的五个开发场景，不声称留出泛化。
- 每个场景取三个状态: 原生报警前五个查询、组合首次实际接受、组合最后一次实际接受。后两者使用组合分支当时的真实观测、噪声、实际历史和原偏置。
- 首次/末次按接受时间选取，不按分数最低、动作最大或任务收益挑选。原成功场景仍为负面对照。
- 报警前状态用原 P3d proposal 规则生成组合方向，不额外寻找方向。

## 同状态干预

每个状态依次 native、zero、combo、opposite、random、repeat、post，共 105 次模型前向。
opposite 是 combo 的负方向; random 使用原随机规则对 combo 的专家维排列。三者请求偏置 L2、范围及 max_abs<=0.30 相同。
本轮不接受/拒绝候选来选择环境动作，所有方向只做诊断前向。即时筛查仅记录，不用任务状态筛选。
每状态 zero/post 与 native、repeat 与 combo 的路由/动作/新增激活必须逐值一致。
两个已介入状态的 native/combo 必须与 P3d 原始响应逐值一致; 报警前 native 必须与原始 trace 一致。

## 新增测量

临时只读 hooks 采集 HB 八层全部十个去噪步骤的归一化 MoE 输入、共享专家输出、MoE 总输出、MLP 残差输入和 block 输出，以及动作投影输入/输出。
CPU 保存 FP32 数值，不将 BF16 模型改为 FP32 模型。routed 输出用 total-shared 推导，注明包含 FP32 加法舍入误差，不伪称独立捕获单专家输出。
核对 block_output=residual+moe_total，并检查每个请求结束后 hooks 清理。
同状态比较相对 L2、绝对 RMS、共享/路由输出与残差的尺度、投影速度及最终六维动作标准化 RMS。
第一去噪步的 L12 输入及共享输出应相同，提供固定局部输入的直接 gate 干预对照; 后续层包含传播反馈，不当作固定局部输入。
这些量不能单独证明专家语义相同或“残差导致失败”。

## 物理轨迹诊断

恢复 P3d native 与 mobility_balance 共十条已保存轨迹的每步仿真状态，读取原 BDDL 目标谓词、物体位置、关节、夹爪末端位置及双指接触判据。
这是状态重建，不是新环境续跑: 不调用 environment.step，不报告新增救回率。
每步重新判定 success 必须与保存的 success 完全一致; 几何与接触只作离线诊断，不输入模型。
记录目标条件首次满足、丢失和最终状态，实际夹持的对象及失去接触时点。目标条件不单调，不能把初始未满足当作首次失误。
用保存的图像制作时间序列，辅助人工判读; 无足够证据时不指定“不可逆失误”时刻。

## 验证、边界与停止

- 配对前向 105 次，新增环境动作 0; 独立模型保持原 16384 MiB 显存上限。
- 所有原始数组、配置与来源哈希保存到新目录; 写前独占创建，异常保留，不覆盖失败结果。
- 单元测试、原响应一致性、零效应/非零重复、残差重建、源产物/源码不变与服务身份检查全部记录。
- 先完成本轮测量再分析，不自动扩大幅度、放松动作限制或改用任务奖励控制器。
- 结果区分已测事实、机制假说和需要下一轮干预才能回答的问题。
