# MoE-only Control 实验计划

创建日期：2026-09-14。这是新的本地实验，不是上游 0909 结果的复述。

## 目标与边界

研究问题：冻结 HiMoE-VLA 后，仅凭 MoE 路由及其因果历史，能否生成、识别和执行比默认策略更有恢复价值的候选？

- 在线控制器仅使用 MoE 路由；图像、语言、本体状态仍是原 VLA 的正常输入，不额外输入选择器。
- 动作由冻结策略产生。暂不引入物体真值、目标坐标、手写抬升/侧绕控制器、hidden 激活或外部视觉模型。
- 离线允许用策略输出检查动作响应，用模拟器最终成功标签评价和拟合小选择器；这不属于 training-free，必须单列说明。
- 不修改、重启或终止现有 9500 服务，不改其他采集进程及其输出。新程序和产物仅写入本目录。
- 推理重放不等于环境续跑；噪声响应不等于 gate 因果干预；动作改变不等于恢复；指标降低不等于成功。

## 已知证据

1. 上游四候选实验：路由中心救回 2/188，随机候选 1/188，纯噪声中心 2/188；四候选池事后上限仅 4/188。这些是相关重复，不是 188 条独立父轨迹。
2. 上游直接 gate 偏置能大幅改变路由而动作变化很小。更敏感的位置也不代表存在正确的恢复方向。
3. 低风险搜索和成功密度改善均出现“内部指标改善但最终仍失败”的反例。
4. 现有本地三条 signal pilot 只证明捕获、重放与计算一致，不足以估计控制收益。

来源：`../robot-whisper-0909/moe-trap-control/ADAPTIVE_CONTROL_EXPLORATION.zh.md`、`V8_FEATURE_CONTROL_EXPERIMENT.zh.md`、`MOE_OUTCOME_MODELS_RESULTS.zh.md`。

## P0：身份与数据审计

- 源仓库：`/data/coding/robot-whisper-0909`，分支 `backup/2026-09-09`，记录 commit 和工作区状态，不修改上游文件。
- 模型：现有 `127.0.0.1:9500`；checkpoint SHA-256 必须为 `cdc2b21f9ef657ab31049cfd2b1e2086ceb193a1b8c16af0cd6688925491a256`。
- 当前服务只有 fixed-noise 与 top-k wire capture，没有 scope-bias / 全概率即时响应接口。完整 HB 从既有磁盘 recorder 的 durable rows 只读复制。
- 旧批次的 `episode_id=0` 行可能交错，禁止按行段猜测父轨迹。本轮每次请求使用新的独立负整数 ID，源 trace 的观测、噪声、动作和文件哈希另外保存。
- 源 trace 必须通过既有 `load_episode_trace` 的完整性和哈希校验；请求响应噪声摘要、模型身份、层顺序逐项检查。
- 不使用已看过的旧验证结果选择新实验阈值。P1a 是新预留任务的表示诊断，不宣称整个研究从未接触这些任务。

## P1a：首轮冻结协议

### 样本与预算

- 数据来源为本地 2026-09-14 Plus / Pro 的两个 30 条批次；仅选择 `episode_index=0, init_state_id=26`，每个基础任务各一条。
- 目标 10 个基础任务 x 2 个 benchmark，共 20 条父轨迹。准备时尚未完成的源轨迹记为缺失，不用别的结局替换。
- 固定查询位置 q8、q20，均为从零计数。源轨迹没有该查询则记录缺失，不补到其他时刻。晚时刻因此存在存活者选择，结果仅解释为已存在查询的同状态诊断。
- 任务 2、5、8 为预留验证，其余为拟合任务。相同基础任务的两个 benchmark 必须进入同一侧；同父轨迹所有查询、候选、候选对不得跨侧。
- 每状态候选 0 使用源噪声，候选 1..7 使用固定 SeedSequence 派生的独立标准高斯噪声。额外重放一次候选 0 检查非干预一致性。
- 最多 40 状态 x 9 次 + 32 次 capture-on/off 尾部对照 = 392 次模型调用，新增环境动作 0。串行客户端，不另加载 GPU 模型。输出预计低于 150 MiB。
- 尾部 32 次调用用于使主实验行越过旧 recorder 的 32-call 缓冲；全部计入研究开销，不当作新的父轨迹。

### 记录与特征

- 保存每次候选的实际动作、初始噪声、wire top-4 ID/权重，以及完整 HB `[8 layer, 10 denoise, 11 token, 32 expert]`。
- 主实验完整概率行必须与 wire 实际 top-4 对齐，不能从 float16 全概率重新排序来冒充实际执行专家。
- 分层表示：8 层 x 状态/动作 token 两组 x 去噪早期 0..2 / 后期 7..9 两组，共 32 个 Hellinger 距离特征，另有对应 32 个实际 top-4 集合差异特征。
- 保留层身份，不把不同层的同编号专家当作同一个专家。中间去噪步不进入结构化主特征，但完整 HB 保存并用于全局距离基线。
- 每状态 8 候选产生 28 个无序候选对。预测目标为 6 维动作差异除以 checkpoint action std 后的 RMS；夹爪符号变化另报，不混入回归目标。
- 拟合只使用动作差异标签，不使用最终成功/失败标签。它是诊断校准模型，不是已经能恢复任务的控制器。

### 预先冻结的分析

使用非负 ridge 回归，按父轨迹等权，训练侧 RMS 缩放，正则系数 0.01，无截距。系数和缩放仅由拟合任务决定。

比较：纯噪声距离、全 HB Hellinger 距离、旧路由中心所用的后四层/前三去噪步/动作 token 距离、结构化 MoE 距离、噪声加结构化 MoE 距离。

主诊断：纯 MoE 的结构化表示是否比纯噪声更准确预测动作差异。噪声加路由仅用于增量信息诊断，不作为仅路由输入的部署选择器。

另外报告：每个预留基础任务的误差、25 次按整个状态块置换路由后的误差、候选动作多样性，以及纯噪声中心/旧路由中心是否选中不同候选。所有候选对是相关样本，不以候选对数量报告独立样本量或统计显著性。

探索性继续门槛，必须同时满足：

1. 所有采集审计通过，至少 3 个预留基础任务、4 条预留父轨迹。
2. 结构化 MoE 在预留父轨迹等权 RMSE 上比纯噪声低至少 10%。
3. 至少 2/3 的预留基础任务 MAE 改善；真实路由的 RMSE 低于状态块置换后的中位数。
4. 至少一半预留状态中，候选相对默认的最大归一化 6D 动作 RMS 差异超过 0.02。

这些阈值只决定是否值得投入后续探针，不是恢复有效性的门槛。不通过则保留阴性结果，不在验证集重新选层、窗口、正则或阈值；修订须新建协议和独立数据。

## P1b：真正的 gate 因果探针

- 需要独立、可回滚的干预服务。当前 9500 不支持，不发送未声明的 gate 字段，不临时改共享服务。
- 固定同状态、同初始噪声，分别对前/后层、状态/动作 token、早/晚去噪位置施加中心化随机正负 gate bias；从 RMS 0.05、0.10 起步，绝对值上限 0.30。
- 每个请求结束无条件移除 bias，零偏置与未干预动作、路由必须一致；记录真正执行的 top-k，而不只是修改后的分数。
- 先验证重复噪声底线和输出响应，再确定后续候选生成的少量位置与幅度。探针本身不优化 v8 风险或“成功密度”。
- P1a 即使通过也不能替代这一因果实验。需要切换共享服务或增加 GPU 资源时，先报告运行条件并取得用户明确安排。

## P2：候选覆盖和物理可恢复性

- 在新的开发父轨迹中冻结因果触发器，起步保持 v8.2 首报后的 q+1；更早触发作为单独实验，不使用事后 q-5。
- 初始预算 20 条独立报警父轨迹，每状态 2 个配对随机流、每个生成器 4 个候选，全部执行单次替换后的完整剩余后缀。样本包含原成功轨迹，不仅收失败。
- 对照 IID 噪声候选与 P1b 冻结的 MoE 引导候选；模型前向总预算匹配，额外筛选的候选也计入成本。默认候选始终保留。
- 从完整前缀重建环境和控制器状态；分叉前先做 C0 的观测、动作、物理状态一致性检查，失败则不采收益。
- 所有候选使用配对未来策略随机流，原 520 步总预算不延长。非选中候选不得写入在线路由历史。
- 报告候选池事后上限、相对 candidate0 的救回/误伤、唯一父轨迹数量、总步数和前向数。不把 oracle 当在线控制结果。
- 若生成器未在至少 3 条独立父轨迹产生额外可救候选，暂停扩大选择器训练；20 条只做开发诊断，不宣称统计功效充分。

## P3：候选净收益选择

- 标签为同状态配对的 `Y(candidate)-Y(default)`，不是将失败轨迹所有早期窗口标成坏状态。
- 输入为因果路由历史和候选相对默认的结构化路由差异；不输入任务 ID、最终长度、物体真值。时间单列消融，默认不输入。
- 使用小型正则化选择器，保留默认候选和拒绝替换机制。先与旧中心、噪声中心、随机及状态置换对照比较，再考虑复杂模型。
- 训练/调参/确认按独立父轨迹分组；跨基础任务泛化另行分组报告。候选和重复不能拆到不同集合。
- 当前没有足够新配对恢复标签时不拟合成功率模型，不拿动作差异预测器替代收益选择器。

## P4：前瞻闭环与交付

- 冻结触发、生成、排序、退出与再干预规则，在未参与开发的新轨迹上实际闭环执行。
- 主终点为全部父轨迹的成功率净增益，包含未报警轨迹；另报条件救回、误伤、部署前向开销、延迟与反复失败。
- 重复先在父轨迹内平均，区间按基础任务聚类；小任务数时明确不确定性，不把零观察误伤称为零风险。
- 根据 P2 的父轨迹配对差异估计扩大样本量；不预先承诺小样本可确认 1 pp 收益。
- 保存协议、代码与输入哈希、原始候选、实际动作、完整后缀和独立审计。报告所有已冻结方法，不事后挑最佳方法替代主结果。

## 首轮执行命令

```bash
/data/venv311/bin/python -m unittest discover -s /data/coding/moe-control-experiments -p 'test_*.py' -v
/data/venv311/bin/python /data/coding/moe-control-experiments/run_experiment.py prepare
/data/venv311/bin/python /data/coding/moe-control-experiments/run_experiment.py collect --run <prepare 输出目录>
/data/venv311/bin/python /data/coding/moe-control-experiments/run_experiment.py analyze --run <同一目录>
/data/venv311/bin/python /data/coding/moe-control-experiments/run_experiment.py verify --run <同一目录>
```

`prepare` 冻结配置和代码哈希；`collect` 不重复使用已启动的 run，也不在异常后自动补采。异常后保留部分日志，修复并记录偏差后另开 run。
