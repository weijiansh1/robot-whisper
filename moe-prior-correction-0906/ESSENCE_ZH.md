# `expert_load_effective_rank` 到底是什么，以及它的本质形式

`moe-prior-correction-0906` · 2026-09-06 · 纯 CPU

## 0. 结论

**它是两个方向相反的信号之和，在前层正好抵消到零。** 本质量是其中一半：
**L3 层、去噪最后一步、10 个 action token 的平均路由熵**。低 → 会超时。

## 1. 定义拆解

`extract_layer_graphs_gpu.py:125-137`：

```python
expert_load = probability[:, :, -1, 1:, :].mean(dim=-2)   # 最后去噪步、10个action token 的平均路由
entropy_effective_rank(expert_load, 32) = exp(H(expert_load)) / 32
```

而 `moe-flow-semantics-0906` 的逐步缓存里已有精确的加性分解：

| 名字 | 定义 | 含义 |
|---|---|---|
| **A** `token_entropy` | mean_t H(p_t) | 每个 action token 各自的路由有多不确定 |
| **B** `token_differentiation` | H(mean_t p_t) − mean_t H(p_t) = **I(token; expert)** | 10 个 token 路由到不同专家的程度 |
| **A+B** `load_entropy` | H(mean_t p_t) | 聚合负载的集中度 |

`expert_load_effective_rank = exp(A+B)/32`，是 `load_entropy` 的单调变换。**所以它测的是 A+B。**

## 2. A 与 B 方向相反，和抵消掉

libero_long，chunk 32，任务内、固定 chunk、负例限定为再跑 ≥5 chunk（去掉"快结束了"）：

| 层 | **A** | **B** | **A+B（就是 eler）** |
|---|---:|---:|---:|
| **L2** (ext) | 0.252 | 0.823 | **0.514 ← 什么都没有** |
| L2 (dev) | 0.286 | 0.814 | **0.502** |
| **L4** (ext) | 0.280 | 0.786 | **0.452** |
| L4 (dev) | 0.310 | 0.750 | **0.440** |
| L3 (ext) | **0.155** | 0.680 | 0.151 |
| L5 (ext) | 0.240 | 0.782 | 0.274 |

AUC < 0.5 表示低值预示超时。**L2 上两半都是强信号（|AUC−0.5| 0.248 与 0.323），加起来是 0.014——几乎精确的抵消点。** 两个独立 cohort 逐层复现。

`eler` 只在 L3 有效，因为那里 A 占绝对主导（0.155 vs 和的 0.151）——即 **L3 的 eler 本来就等于 A**。

用差代替和能取回被抵消的部分：L2 的 `B−A` 是 0.772（|d| 0.272，对比和的 0.014）。

## 3. 前后层符号翻转

同一个 A：

| 层 | A (ext) | 方向 |
|---|---:|---|
| L3 | **0.155** | 低 → 风险 |
| L5 | 0.240 | 低 → 风险 |
| L13 | **0.730** | **高 → 风险** |
| L14 | 0.732 | **高 → 风险** |

**前层结晶（每个 token 硬性锁定一个专家），后层糊化（路由变得更不确定）。** 这是可描述的机制，不只是相关。

## 4. 组合无用（负结果）

以 A@L3 为基准，试了 16 种前后对比、B−A、任务内标准化的四合一：

| 特征 | dev | ext |
|---|---:|---:|
| **单一：A@L3** | 0.8422 | **0.8453** |
| B@L2 − B@L13 | 0.8301 | 0.8122 |
| A@L13 − A@L3 | 0.7910 | 0.8014 |
| 四合一 | 0.8141 | 0.8001 |

（此表已翻向，越高越好。）**没有一个组合胜过单独的 A@L3。**

## 5. 加上任务聚类置信区间后，最强的窗口不在末尾

按任务做 bootstrap（400 次）后，我先前看好的末段被否掉了：

| suite | chunk | 阶段 | ext AUC [95% CI] | dev AUC [95% CI] | 结论 |
|---|---:|---:|---|---|---|
| **long** | **14** | **27%** | **0.352 [0.235, 0.425]** | **0.348 [0.321, 0.372]** | **两个 cohort 都排除 0.5** |
| long | 32 | 62% | 0.155 [0.153, **0.448**] | 0.158 [0.156, **0.568**] | dev 含 0.5，仅 3–5 个任务，**不成立** |
| object | 6 | 21% | — | 0.297 [0.185, 0.360] | 排除 0.5，n⁻=3935 |
| spatial | 7 | 32% | — | 0.303 [0.282, 0.422] | 排除 0.5 |
| spatial | 6 | 27% | 0.360 [0.346, 0.432] | 0.415 [0.388, 0.517] | ext 成立，dev 勉强含 0.5 |
| goal | 7 | 23% | — | **0.657** [0.515, 0.750] | **方向相反且显著——goal 不可声称** |

chunk 32 那个 0.155 的点估计看着最漂亮，但只有 3–5 个任务贡献，重采样任务后能升到 0.45–0.57。**点估计不带任务聚类不确定性时会骗人。**

## 6. 本质形式

**在 L3 层、去噪最后一步，对 10 个 action token 各自的 32 维路由分布求 Shannon 熵再取平均。这个值偏低，预示该 episode 会跑到超时。**

- 稳健窗口：**horizon 的 21–32%**（比 50–65% 的目标还早）
- 效应量：AUC 0.30–0.36，即 |AUC−0.5| = 0.14–0.20 —— **真实但不大**
- 不需要专家身份（置换对称）、不需要任务身份、不需要跨层组合

## 7. 限制

1. 效应量只有 0.14–0.20。单独用它拿不到低误报下的 80% 召回。
2. **libero_goal 方向不一致**（chunk 7 上显著地反向），不应纳入任何统一规则。
3. 短 horizon 的三个 suite 在窗口末段**无法**区分"失败前兆"与"没有完成信号"——那里所有非风险的存活者都在 3 个 chunk 内结束（spatial chunk 13 的 lead+3 负例数为 0）。这是数据的结构性限制，不是分析选择。
4. 全部数字取自逐 chunk 的横截面 AUC，不是报警器。转成检测器还需要在线阈值与确认逻辑。
5. (layer, step) 在 §4 中于 development 上选、在 external 上报；§2/§5 逐层全列，未做选择。
