# ST/AC 确认支路固定协议

2026-09-09。现有 A/B 数据此前已经分析过，本次为回溯实验，不是盲测。
在本次 ST 分数和 B 评价结果计算前固定以下规则。只使用现有路由数据，
不训练分类器、不搜索融合权重、不根据 B 的结果选择层、方向或阈值。

## 特征

- 输入仍为当前查询的 HB 路由 `[8 layers, 10 denoise, 11 tokens, 32 experts]`。
- AC 保留当前编码器定义：最后去噪步、对应 action token 的跨查询
  Hellinger 距离，再对 10 个 token 求均值。不得替换为 action 质心的距离。
- 新增 ST 为 token 0 的最后去噪步跨查询 Hellinger 距离。
  复用已保存的 `state-action-mobility/state_move`，逐源、逐 episode、逐 query
  核对轴。其数值实现为 `sqrt(clip(1-sum(sqrt(p)*sqrt(p_prev)),0,1))`；
  在线使用相同 float32 实现并用原始 Zarr 抽样复核。该缓存的 action_move 不使用。
- ST、AC 各层分别以前四个有效跨查询变化（q1..4）的中位数为参考，
  当前值为最近三次查询均值。q 从 0 开始，首次即时特征为 q7。
- `r_ac = log((current_ac+1e-6)/(reference_ac+1e-6))`，ST 同理。
- 主关系量 `g = median_L12..15(r_ac-r_st)`，正值表示 ST 相对 AC 变弱。
  两次相邻的平滑分数取最小值进行确认，最早 q8。重叠平滑窗不是独立证据。
- 诊断量为低 ST 绝对 mobility、低 ST 相对 mobility、低原始 ST-AC 差值。
  不把它们另行加到报警中，不增加 ST 去噪加速度，不使用全轨迹相关系数。
- 初始自参照可能吸收从开头即存在的异常。归一化关系不是旧原始差值的等价改写。

## 校准与组合

沿用五折 `(task, init_state_id)` 分组：B 的 init%5=f 为测试；A 的
init%5=(f+1)%5 为校准；A 其余三个余数为参考。每条 B 仅评价一次。
不使用任务身份作为在线输入。AC 的两个成功轨迹峰值校准库和阈值从
`routing_guard_20260908/fold_*_profile.json` 原样复用。

ST 关系分数只用 A 校准成功轨迹的全程峰值建经验尾部库。episode 和 task_init
两种校准均报告；后者先对同一 `(task, init)` 的成功噪声种子取峰值最大值。
没有达到暖机长度的成功轨迹以峰值 -inf 保留。尾部公式：
`p=(1+count(calibration_peak>=score))/(N+1)`，包含相等值。

- `p_ac = min(1, 2*min(p_acceleration, p_decoupling))`，沿用原 AC 支路。
- ST 确认条件：当前已确认的 g>0 且 `p_gap<=0.10`。
- 新支路触发：同一查询 `p_ac<=alpha` 且 ST 确认条件成立。
- 最终首次报警：原冻结 v8.2 的首次报警与新支路首次报警的较早者。
- 主设置 task_init、alpha=0.01；补充 episode 及既有 alpha 网格
  0.005/0.01/0.02/0.05。gate_alpha 固定 0.10，不做扫参。

保持 AC 阈值使确认支路的触发查询严格是 AC 支路的子集。该门控实验测试
ST 能过滤多少 AC 报警及其检出代价，不宣称优化后的完整性能前沿。
不在旧 v8.2 与新支路之间重新分摊预算，不用 ST 撤回原报警。
原 v8.2 的 `.0015*q` 阈值放宽项也原样继承；新 ST 支路没有时长/进度项。
不计算仅时长或时钟基线，不读取未来观测或以最终成功与否驱动在线规则。
原方法加新支路的整体名义误报预算不是 alpha；实际 FPR 单独报告。
ST/AC 不假定独立，不把二者尾部概率相乘。

## 评价

对比冻结 v8.2、冻结 v8.2+AC、冻结 v8.2+AC/ST 确认。
报告 40 任务共 16000 条 B（564 失败、15436 成功）的 TP、FP、召回、FPR，
相对原方法新增 TP/FP，相对 AC 组合过滤的 FP 与损失的新增 TP，提前/延迟。
逐任务和逐 suite 报告；重点列出 S05 及成功 episode 174/190。
正常恢复后的历史成功报警仍为 FP，不以最后状态抹除。

AUROC 在同任务、同查询、相同有限观测支持上配对计算，然后先按任务内查询平均、
再跨任务平均；同时报告 q8..13 与全程可比查询，及去除 S05 的结果。
AC 排序用未截断 `-log(2*min(p_acc,p_decoupling))`，避免将正常分数全部截为零。
门控排序使用与主判定相符的连续裕量：
`min(log(alpha/(2*min(p_acc,p_decoupling))), log(.10/p_gap_effective))`，
其中 g<=0 时 p_gap_effective=1。该排序依赖固定 alpha=.01，不能冒称通用融合分数。
旧 v8.2 的 AUROC 使用既有 A 校准路由分数作参照，不把二值冻结报警称为连续分数。
诊断量只报告固定方向的 AUROC，不依据它们改主规则。按 suite 内任务 bootstrap
给出配对差值区间。有限观测条件和任务/阶段异质性限制解释。

## 验证

检查原 AC 缓存/校准库复用和所有预算下原结果一致；确认新增支路为 AC 查询级子集；
所有原 v8.2 首次报警保留且不延后。测试前缀因果性、padding、reset、零参考和缺失值。
对每个任务的成功/失败代表及阈值邻近轨迹进行原始路由回放，核对 ST、AC、
关系分数、在线首次报警与离线缓存的一致性。独立重算指标并保存来源校验和。
