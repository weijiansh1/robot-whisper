# 路由报警在各任务中的位置

2026-09-08。完整 B 批 16,000 条轨迹，564 失败、15,436 成功，40 个任务。
本报告主表使用原冻结 v7、v8、v8.2 阈值下的首次报警，不重新调整阈值。

## 位置定义

报警位置 = 报警前已执行动作数 / 任务配置的最大动作预算。
query 从零开始，q 时已执行 10*q 个动作。Goal、Long、Object、Spatial 的预算分别为
300、520、280、220 个动作。百分比仅用于离线描述触发位置，不输入检测分数；
它不表示物理任务已经完成了相应百分比，也不表示剩余预算内一定可以恢复。

下列中位数和四分位范围只针对已经报警的失败轨迹；全部失败数及未检出数同时保留。
每个具体任务的首次报警分布、检出数和误报数见 [40 任务明细](TASKS.md)。

## 对方法的判断

此前全程 AUROC 使用标准化连续路由分数，v7、v8、v8.2 分别为 0.9285、0.9772、0.9826。
它支持路由分数与最终成败存在较强排序关联；本报告原冻结报警进一步说明触发位置具有明显
任务差异。Long 有较多预算中段的检出，部分任务更早；Spatial 的原工作点则明显偏晚。
现有证据适合支持“执行过程中的序贯异常检出”，不能由这些百分比直接推断 trap 起点、
不可逆失败时刻或干预后的恢复收益。

AUROC 的标准化分数族与原冻结多阈值报警不能混写为完全相同的配置。为便于对照，
本报告 CSV 还保留 `standardized_task_init_1pct`：采用此前 AUROC 对应分数及封存的
task/init 名义 1% 阈值。该 v8.2 工作点为 274 TP / 27 FP，失败报警中位位置同为 67.3%；
Goal、Long、Object、Spatial 分别为 76.7%、63.5%、75.0%、90.9%。它不是本报告主表的原冻结版本。
