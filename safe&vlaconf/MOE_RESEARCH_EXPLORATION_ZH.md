# 从 SAFE / VLAConf 出发的无训练 MoE 失败检测

日期：2026-09-06。状态：本文保留实验前的文献阅读与研究假设；后续首轮实测已完成，见 [MoE 实验报告](moe_trainfree/results/round1/REPORT_ZH.md)。研究范围已明确为：用 MoE 信号替换内部特征读出，构造无训练的在线失败检测器。

阅读对象是本目录两份 v2 源码包，同时核对了 arXiv 正文和仓库已有报告。下文的“论文事实”“已有实验”“研究建议”分别标明；已有实验数字仅经报告、部分实现和汇总文件核对，本轮没有重跑。本文不修改现有检测器或实验协议。

## 1. 初步判断

值得优先研究的问题是：**能否利用预训练 MoE 已有的路由与计算结构，直接构造有用的失败分数，从而省去额外检测器的训练？**

SAFE 用内部特征训练失败探针，VLAConf 用内部特征训练成功支持度头。本方向同时改变输入和评分方法：以 MoE 的路由分布、跨 token 分工、跨 flow 与执行时间的变化替代通用 embedding，再用固定公式和因果统计生成风险分数。不会额外训练 MLP、LSTM、CFN、HMM 或其他风险预测模型。

当前优先把 **无训练 MoE 监测** 做清楚。专家实际输出可作为同样不训练的扩展输入，因果定位和恢复控制不作为当前阶段的完成条件。仅发现更好的失败分数，也可以构成独立研究结果。

本轮默认允许对无标签历史 MoE 数据计算参考统计和报警阈值，但不使用失败标签选择部署阈值。需要分别声明“没有预测模型训练”“没有失败标签参与校准”和“完全没有参考数据”：这是三个不同约束。现有方法曾受结果反馈影响的事实保留，不因换用无标签阈值而消失。

## 2. 两篇工作分别解决什么

| 维度 | SAFE | VLAConf |
| --- | --- | --- |
| 主要目标 | 执行过程中的失败检测，重点是未见任务 | 当前前缀下的最终任务成功置信度 |
| 内部输入 | VLA 最后层特征，对 token / action horizon / flow step 做聚合 | 冻结 VLA 的视觉、语言特征与机器人状态，再加入 step 条件 |
| 分数学习 | 用成功和失败 rollout 的轨迹级标签训练 MLP / LSTM | 用成功示范训练 Coin-Flip Network，输出逆成功支持度 |
| 时间处理 | MLP 输出累加，或 LSTM 处理因果前缀 | step 条件，加前缀 mean / max 聚合 |
| 校准 | 用成功 rollout 校准 functional conformal band | 用成功和失败 rollout 拟合两个 Platt 参数 |
| 泛化实验 | 检测器训练任务与测试任务分离 | 包含分布偏移，但偏移套件仍做目标套件校准 |
| 下游行为 | 报警；恢复策略留待后续研究 | 低置信时短时交给外部 expert policy |

来源：[SAFE v2](https://arxiv.org/html/2506.09937v2)，[VLAConf v2](https://arxiv.org/html/2605.29605v2)。本地精确依据为 SAFE 的 `sections/3-method.tex`、`sections/4-exp.tex`、`sections/a-appendix.tex`，以及 VLAConf 的 `approach.tex`、`exp.tex`、`appendix.tex`。

### 2.1 SAFE 的贡献与边界

**论文事实。** SAFE-MLP 对每步特征做 sigmoid 映射并累加；SAFE-LSTM 直接处理前缀。二者使用轨迹级成功/失败标签，不要求训练时标注故障发生时刻。它已支持 flow-matching 的 pi0，报告的一个 LSTM 配置额外推理约 0.73 ms。因此，“能用于 flow VLA”“单次前向复用内部特征”“很便宜”“能跨任务”都不能单独作为我们的新意。

SAFE 的 conformal band 面向的是成功轨迹上的整段误报控制。在相应交换性条件下，可以讨论：

\[
P(\text{成功轨迹中至少报警一次}\mid Y=1)\leq\alpha.
\]

这不等于 `P(失败 | 已报警) >= 1-alpha`，也不是任务成功概率校准。附录明确承认，未见任务可能破坏校准与测试分布的假设，实际 TNR 会偏离名义值。

它也注意到了“失败跑满时长、成功提前结束”的混淆，并在 LIBERO 的一项 AUC 评估中按每个任务的最短 rollout 长度统一截断。不能把长度混淆写成对方完全忽略的问题。其 failure-zone 可视化也并非所有模型和实机任务都统一成立。

**研究推论。** 用最终标签监督所有前缀，可以学习风险，但不会自动区分“已经发生物理故障”“容易最终失败”“需要马上介入”。这三个目标值得分别评估。

### 2.2 VLAConf 的关键机制与边界

**论文事实。** CFN 用成功示范上的固定随机正负向量作为回归目标。理想化地，同一表示模式出现 n 次时，随机目标均值的平方范数期望与 `1/n` 成正比。论文把这一关系推广为连续表示中的 pseudocount，再假设“相同任务与阶段下，成功支持度越高，继续成功的概率越高”。

它的实际 step 输入是绝对步数 embedding 和按固定 `K=256` 归一化的标量。这是可在线获得的时间条件，不是已经识别出的抓取、搬运、放置等语义阶段。

三个实验细节会直接影响我们的对比设计：

1. **并非完全不使用失败标签。** CFN 的分数学自成功示范，但概率校准使用成功和失败 rollout。偏移实验也用目标套件做 Platt calibration。
2. **部分“在线”指标是事后对齐。** 附录说明 pi0.5 主标量结果在 50% 执行检查点评估；成功轨迹以首次成功时间归一化，所以作者明确将其称为 retrospective。这个问题属于评估取点，不代表其分数计算本身必须读取未来。
3. **求助覆盖率也用了完整轨迹。** 其求助实验按完整被动测试轨迹的最大风险分数排序，确定 10% / 20% / 30% 的经验覆盖率。未使用测试结果标签，但使用了未来前缀；正文明确承认这不是严格在线部署协议。外部 expert 最多接管四个 action chunks，不能与 MoE 内部 FFN experts 混同。

在该求助协议下，10% 实际求助率对应 94.7% 成功率，无求助为 88.7%；30% 求助时成功率为 92.0%。这支持“有下游用途”，不支持求助越多越好，也没有直接证明对所有预算、所有套件均优。

**研究推论。** 成功支持度、成功概率、干预收益是不同的量。由 Bayes 公式：

\[
P(Y=1\mid z)=\frac{\pi_+ p(z\mid Y=1)}
{\pi_+p(z\mid Y=1)+(1-\pi_+)p(z\mid Y=0)}.
\]

只知道成功分布的支持度，通常不足以确定成功概率；还涉及失败分布与成功先验。两参数校准可以改善分数到概率的映射，但不能修复错误的风险排序，更不能凭空识别原始分数丢掉的信息。连续 CFN 的泛化也不能直接由“完全相同模式重复 n 次”的等式保证。

另一个可检验问题是恢复后的置信度更新：max 聚合使风险峰值一直保留，SAFE-MLP 的累计分数也不下降。它们适合首次报警；如果希望决定何时恢复自主执行，需要另行检验当前状态是否好转，不能直接把历史最大风险当作当前恢复状态。

## 3. MoE 能提供的具体结构

对一个带共享专家的 MoE 层，省略 layer、token、flow-step 下标，写作：

\[
r=\sum_{e\in\mathrm{TopK}}\tilde p_e E_e(h),\qquad
s=E_{\mathrm{shared}}(h),\qquad y=r+s,
\]

其中 `p_tilde` 是归一化后的实际执行权重。

| 可观察量 | 回答的问题 | 不能直接推出的结论 |
| --- | --- | --- |
| 路由概率、margin、实际 dispatch | 当前选择了什么计算分支 | 当前动作正确与否 |
| 专家输出及其加权合成 | 不同专家是否有功能差异，贡献是否抵消 | 分歧就是 epistemic uncertainty |
| routed/shared 比例与方向 | 条件分支怎样参与当前层计算 | routed 变弱一定导致失败 |
| 跨观测、跨层、跨 flow 的变化 | 新证据如何传入动作生成 | 响应大就是响应正确 |
| 固定输入下的局部计算干预 | 哪段计算对动作有因果影响 | 改动它就会提升任务成功率 |

三个可复用的功能量是：

\[
\rho=\frac{\|r\|}{\|r\|+\|s\|+\epsilon},\qquad
\kappa=\cos(r,s),\qquad
D=\frac{\sum_e\tilde p_e\|E_e(h)-r\|^2}
{\sum_e\tilde p_e\|E_e(h)\|^2+\epsilon}.
\]

它们分别描述分支相对幅度、方向一致性和归一化输出分歧，已有 recorder 提供相应数据。它们是计算描述量，需要通过对照实验建立与执行风险的关系；范数和夹角本身也不等于对最终动作的因果影响。

应特别避免四个等同：

- Router entropy 不等于成功概率；权重很分散但专家输出接近，与权重集中且选错专家，是两类情况。
- FFN experts 不是独立训练、各自预测完整动作的策略 ensemble，不能直接套 ensemble 的不确定性解释。
- 跨层 expert ID 没有天然对应语义；低精度概率重新 TopK 还可能改变平票处的实际 dispatch。
- Routing 来自中间 hidden states，不宜笼统宣称它包含“所有 hidden states 都没有的信息”。应检验它相对可部署的末层聚合特征，是否有更有效、更便宜的风险读出。

## 4. 仓库已有证据怎样约束选题

### 4.1 继续堆路由统计的空间有限

[方法综合报告](../moe-method-synthesis-0906/REPORT_ZH.md) 将两队列共有的 419 个检测器归并为 9 个报警家族，并指出当前预算下仍未捕获的风险中，物体半途脱手占比较高。这个结论支持减少同源统计和阈值组合，转向更有针对性的数据与功能量。

但该报告只能约束已经测过的方法族。它不能证明“所有只读 MoE 的方法都不可能区分剩余失败”，也不能把预算下的漏检集合当作信息论上的不可识别集合。

[Grammar 报告](../MoE-grammar/README.md) 则区分了两件事：路由历史有可预测结构，但额外历史可预测性并未稳定转化为失败检测增量。因此，给 VLAConf 加一个 routing phase-HMM，并不能凭概念就成为有力新方向。

### 4.2 功能信号是更值得检验的候选

[功能事件 pilot](../analysis_moe_execution_signals/rich_event_analysis_report.md) 在单任务、每个 lead 23 对匹配样本中发现：失败事件前 routed authority 降低、专家分歧降低、routed/shared cosine 升高。Cosine 的匹配 AUC 在 lead -4 / -2 分别为 0.922 / 0.951，预注册主比较中 8/10 通过 maxT。

这是值得优先扩展的信号，但适用范围目前很窄：单任务、静止事件、重建状态重采集；这些功能量高度相关，也不能算多个独立机制。它没有完成跨任务检测、相对 SAFE/VLAConf 的增量检验，或严格在线报警验证。

### 4.3 检测和恢复已有明确分离

[恢复 pilot](../analysis_moe_execution_signals/horizon_recovery_report.md) 中，正常 h10 与前十个物理步采用 h2 的短 burst，在 23 个事件状态上都为 0/23 成功；健康对照则从 21/23 降到 19/23。Cosine 报警虽覆盖 19/23 事件，触发该 burst 仍未带来恢复。

因此不能默认把“报警后更频繁重规划”设为有效恢复动作。零次观测收益也不等于总体收益精确为零；报告中退化为 `[0,0]` 的 bootstrap 区间不消除小样本和单个未来噪声流的不确定性。

### 4.4 现有 v8 可以作基线，但协议需要对齐

[v8 协议](../moe-v8-0906/method/ONLINE_INTRINSIC_GUARD_V8_PROTOCOL.md) 已有仅读 routing、没有运行时 task ID 或 horizon 输入的因果监测器。它可以作为低成本基线。

对外比较时有三个口径需要单列：

- 协议承认方法选择看过结果标签、external 队列曾被探索。无梯度拟合不等于整个研究过程无标签，现有 external 不能继续当作全新盲测。
- [evaluate_full_corpus.py](../moe-v8-0906/experiments/evaluate_full_corpus.py) 第 101 行的 `score()` 同时用 `length - first_alarm >= lead` 过滤 TP 和 FP。因此 headline 的 126 FP 是满足 lead 条件的成功轨迹报警数；同一协议的 lead>=0 表报告 192 FP。两者口径不同。
- 以终止时间计算 lead 可以作为离线评估；但成功前最后几步的误报仍会触发真实干预。与 SAFE 比较时，成功轨迹的“曾报警率”应全部计入，提前量约束主要施加在失败检测收益上。

新噪声、初始状态留出、任务留出和模型留出也应分别报告，不能仅凭目录名 `external` 推断已经证明了未见任务泛化。

## 5. 方法主线：从 MoE 直接构造分数

```text
冻结的预训练 MoE-VLA
    -> 当前 query 的 MoE 张量
    -> 固定的路由 / 计算统计
    -> 当前轨迹自参照或无标签历史归一化
    -> 因果时间聚合
    -> 风险分数与首次报警
```

### 5.1 MoE 表征为何值得用于无训练评分

通用 hidden embedding 的坐标没有直接的概率意义，SAFE 和 VLAConf 通过训练头学习如何读取。MoE routing 已经具有非负、归一化、专家选择的结构，而且保留 layer、flow-step、action-token 三条轴。可以直接计算分布距离、分工和变化，不必先训练一个新的表征映射。

这里的研究假设是“预训练 MoE 的结构使固定统计更容易读出失败信息”，并非“路由概率天然就是失败概率”。已有结构是否比同样无训练的 hidden-state 统计更有效，是需要实验证明的核心。

首轮使用现有 `hb_router_probs`，形状为 `[8 layers, 10 flow steps, 11 tokens, 32 experts]`。状态 token 与十个 action tokens 分开分析，跨层只比较层内统计或同层跨时刻距离。先保留单次正常推理；多噪声推理与专家输出采集另列成本。

### 5.2 少量明确的候选统计

| 现象候选 | 无训练读数 | 需要排除的正常情况 |
| --- | --- | --- |
| 相对冻结 | 相邻 query 的 Hellinger mobility 相对自身早期水平持续收缩 | 正常稳定抓持、短暂停留、完成前静止 |
| 生成不稳定 | flow 轴曲率、路径变化及其跨 query 持续性 | 正常重新规划、多种正确动作 |
| token 分工变化 | token 内熵与 token 间路由差异分别计算 | 相邻动作本就需要相近计算 |
| 功能协作变化，扩展项 | routed/shared 幅度与方向、专家输出分歧 | 正常任务阶段切换、层尺度差异 |

这些方向在仓库中已有部分统计或实验，不能重新当作未探索的新发现。当前工作是选择可解释且必要的读数，检验无训练组合的适用范围。

一个最简相对冻结分数可以写为：

\[
m_t=\operatorname{median}_{\ell\in L_{\mathrm{back}}}
\frac1J\sum_{j=1}^J H(p_{t,\ell,K,j},p_{t-1,\ell,K,j}),
\]
\[
S_t^{\mathrm{freeze}}=
\left[\log\frac{b+\epsilon}{m_t+\epsilon}\right]_+,
\]

其中 `H` 为 Hellinger 距离，`K` 为最后 flow step，`b` 是完成 warm-up 后冻结的早期 mobility 参考值，再加固定因果窗口和持续性确认。该式是说明评分方式的候选，不等同于已发布 v7 的逐层先归一化公式，也不声称优于它。早期参考不保证健康；从一开始就错误的轨迹可能没有可检测的相对收缩，必须报告 warm-up 盲区与低分母处理。

token 分工则可以利用一个不需要训练的精确分解。令 `p_j` 是同一层、同一 flow step 的 action-token 路由，`p_bar` 是其均值：

\[
H(\bar p)=\frac1J\sum_j H(p_j)+I(\mathrm{token};\mathrm{expert}).
\]

其中 token 均匀采样，专家按对应 `p_j` 采样。第一项表示单 token 路由分散程度，第二项表示不同 token 之间的分工；相同 load entropy 可以对应很不一样的结构。因此二者应分开看。不能预设它们越大或越小就一定失败，现有 [CUSUM 报告](../moe-cusum-capfree-0906/REPORT_ZH.md) 已显示聚合和方向选择会影响结果。

### 5.3 无训练阈值如何确定

直接复用 [无标签报警预算协议](../moe-v7-0905/method/UNLABELED_BUDGET_CALIBRATION_PROTOCOL.md) 的原则：使用所有无标签历史轨迹，按操作者给定的总报警预算确定阈值。单个分数可以用历史轨迹峰值的经验分位数；多分支则计算实际报警并集，不假设分支独立。

完整历史轨迹可用于离线参考统计，当前受监测轨迹只读取已经发生的前缀。部署不按任务重新拟合，也不使用测试标签调整阈值。这是数据依赖的统计校准，但没有检测网络训练。

例如“参考集中至多 3% 的轨迹报警”是一个工作量预算，不是“成功轨迹误报率为 3%”，也不是“报警后有 97% 概率失败”。完全无参考数据的自参照版本可以作为更严格的消融，但没有理由把某个固定倍数直接解释为通用安全边界。

时间聚合先比较固定持续性和冻结的 v7 规则。若使用 CUSUM，要注意负 slack 会在无信号时仍随时间增长；该部分必须与时钟对照分开核算，不将“运行得久”全归因于 MoE。

### 5.4 最终输出与主张

主输出是可排序的失败风险分数和在线报警。把分数映射到 `[0,1]` 不会自动得到已校准的成功概率；本阶段不引入 Platt scaling 或其他结果监督概率头。

可以争取的结论是：在不训练附加预测模型的条件下，MoE 固定读数达到有用的检测性能、减少失败数据需求，并能迁移到留出的任务。是否成立、适用于哪些失效模式，都由统一评估确定。

## 6. 最小验证顺序

### 第一步：建立符合约束的基线

优先读取、核对现有 v7 无标签预算版本的结果和实现，作为直接起点。冻结的 v7/v8 保留作已有方法对照，并明确其历史规则选择曾使用结果反馈。本轮没有重跑或新增这些实验。

首先分别测量最终任务失败和物理事件发生。物理事件也要标注在最终成功但中途出错的轨迹中。成功轨迹的全部报警都计入误报；物理提前量主要约束失败检出，避免使用第 4.4 节指出的不同口径。

### 第二步：同时验证 MoE 与无训练评分

| 对照 | 要回答的问题 |
| --- | --- |
| 末层特征 + 固定距离 / 自参照变化 | 通用内部特征是否也能同样无训练地读出风险 |
| MoE routing + 固定统计 | 替换表征是否带来增益 |
| MoE routing + 因果时间聚合 | 历史是否改善预警，而不是只积累运行时间 |
| MoE 功能量 + 相同评分框架 | 专家实际输出是否补足门控信息 |
| 动作 / 机器人状态 + 相同时间窗口 | MoE 是否只是动作静止和姿态变化的代理 |
| 原版 SAFE / VLAConf | 与需要额外训练的方法相比，性能与数据、训练成本如何权衡 |

主方法及核心消融都不训练预测器。SAFE/VLAConf 作为已有学习式基线，按各自协议复现，并列明其训练数据与校准标签；不能为了统一“无训练”而删除其训练步骤后仍称为原方法。

使用同一 checkpoint 和配对 rollout，统一输入处理、终止规则、action chunk、统计参考数据、推理成本与评分取点。VLAConf 所需的成功示范特征、末层特征若缺失需补采。它的标准表主要用 Goal / Spatial / Object；long 的结果单列，不能直接比较不同套件组成的总分。

### 第三步：确认泛化和报警效用

在独立 development 数据上冻结全部公式、窗口、参考统计和部署阈值，之后才评分。相同任务、初始状态和 snapshot 的不同 noise branches 应整体划分；另外单独做任务留出。已有反复检查的 external 数据用于探索，不计为新的确认实验。

报告固定部署点的真实误报率、recall、提前量、漏检与开销，并给出 failure AUPRC/AUROC 和按任务宏平均。比较固定误报率下的性能曲线可以作离线分析，但不能按测试曲线选出部署阈值。用时钟、相同时间窗口以及适当的路由结构破坏对照检验信息来源。

判断标准是：MoE 的固定评分能否优于同样无训练的特征/行为对照，并在与学习式基线比较时体现明确的数据或训练成本收益。若只覆盖部分失效模式，就据此界定方法范围。

## 7. 补充检索与新颖性边界

少量外围检索发现，[GW-MoE](https://arxiv.org/abs/2406.12375) 已研究不确定路由与专家选择问题；[CARE](https://arxiv.org/abs/2607.26052) 提出用置信与分歧调整 MoE-LoRA 的专家预算；[VI-MoLE](https://arxiv.org/abs/2608.02528) 在摘要中明确区分不确定性与额外专家计算的收益。

本轮只核对这些外围工作的官方摘要，未完成正文与复现审计。因此这里只把它们作为后续阅读入口，不引用其实验效果。现阶段不主张“首次用 MoE 做不确定性”；更具体的候选贡献是直接利用预训练 MoE 结构构造无训练的 VLA 在线失败检测器。

## 8. 后续讨论的工作表述

可暂用以下问题组织后续研究，而不提前承诺方法有效：

> 预训练 MoE 的路由与协作结构，能否直接提供执行可靠性信号，使 VLA 无需额外训练失败检测器？

近期以无训练的路由统计、参考归一化和在线报警为主线。专家输出是可选的信息扩展，机制干预与恢复留待后续；当前不承诺已校准的成功概率或自主恢复。
