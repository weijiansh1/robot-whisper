# 预算内救回实验：设计

日期：2026-09-07
前置：`REPORT_ZH.md`、`analysis_moe_execution_signals/horizon_recovery_report.md`

## 0. 要回答的问题

检测这一侧已经到头：v7 在 **44.3%** 的失败上比"到点"更早，中位 **120 个环境步**。
再往上推很难，本 bundle 两轮都没做到。

**但没人验过那 120 步值不值钱。**

$$\boxed{\text{在报警时刻剩下的预算内，还救得回来吗？}}$$

"预算内"是硬约束：跑到**原来的 horizon 上限**为止，不延长。这与部署问题一致——
你不会因为报警就给机器人加时间。

已有的唯一证据是一次否定：`horizon_recovery` pilot 在报警点改用短 horizon 突发重规划，
**event 组 0/23**。一种策略、23 个样本、而且用的是 +10 延长而非原预算。不足以定论。

## 1. 设计

### 分叉点

v7 首报时刻 `q_a`，取风险 episode。优先取**早报**的（`q_a` 小、剩余预算大），
因为剩余预算是本实验的主自变量。

目标 **300 个分叉点**，按 suite 与剩余预算分层抽样，保证预算跨度铺开。

### 臂

| 臂 | 做什么 | 检验什么 |
|---|---|---|
| `control_same_noise` | 原样续跑，噪声种子不变 | **确定性锚点**：必须逐位复现原失败 |
| `control_new_noise` | 原样续跑，换噪声种子 | **诚实基线**：光是重掷骰子能救回多少 |
| `resample` | 同观测重采样动作 chunk | 策略自身的随机性够不够 |
| `backoff` | 末端后退+抬升固定量，再交回策略 | 改变**物理状态**而非只改采样 |
| `route_intervention` | 报警层强制换专家（Top-4 换成次优组） | **MoE 是读出还是原因** |

`control_same_noise` 不通过就停——说明分叉重建不忠实，后面全部无效。

`route_intervention` 是唯一直接检验因果的臂。v7 报告点名说这个没测过，
committor 审计也只证明了 q0 路由不能选择命运，没证明中途改路由无效。

### 预算

每条从 `q_a` 跑到**原 suite 上限**（goal 30 / long 52 / object 28 / spatial 22 chunk），
不延长。剩余预算 = 上限 − `q_a`。

### 主指标

$$\text{救回率} = P(\text{在原上限前满足 } \texttt{\_check\_success} \mid \text{臂}, q_a)$$

**主比较是每个干预臂对 `control_new_noise`**，不是对 `control_same_noise`——
否则重采样类的臂会因为"换了噪声"这一点白占便宜。

### 主分析：救回率随剩余预算的变化

这是把检测和干预连起来的那一步：

$$\text{救回率}(\text{剩余预算})$$

- 若救回率随剩余预算单调上升 → **提前量就是买到的东西**，检测的价值被量化了
- 若救回率与剩余预算无关 → 提前报警没有额外价值，检测那一侧的努力白费
- 若处处为零 → 这类失败在这个策略下不可救，问题不在检测

## 2. 规模与成本

| | |
|---|---:|
| 分叉点 | 300 |
| 臂 | 5 |
| 每格噪声种子 | 4 |
| 部分 rollout 总数 | **6,000** |
| 每条长度 | 剩余预算，中位约 27 chunk ≈ 63 s |
| 单进程墙钟 | 105 GPU-小时 |
| **32 路并发墙钟** | **约 3.3 小时** |
| 磁盘 | 只存物理状态与结局，路由可选；**< 2 GB** |

比采集计划（12.5 小时）便宜四倍，且不需要新任务。

### 功效

`control_new_noise` 的救回率未知，先验估 5–15%。300 个分叉点下，
检出 10 个百分点的臂间差异约 5 个标准误；按任务聚类后仍有余量。
若真实差异只有 3 个百分点，300 个点不够——**这种情况下结论是"效应小"，不是"不显著"**，
要如实写。

## 3. 必须做对的几件事

1. **确定性锚点先过。** `control_same_noise` 必须逐位复现原轨迹与原失败。
   不过就停，不要"差不多"。
2. **同状态分叉。** 从存储的 `sim_state` 恢复，不是重跑到 `q_a`。
3. **臂之间共享噪声种子集合**，配对比较，不是各自独立抽。
4. **只在风险 episode 上分叉。** 在及时成功上分叉是另一个问题（会不会把好的搞坏），
   可以做但要分开报，不要混进救回率。
5. **不延长预算。** 上一次 pilot 用的是 +10 延长，那测的是"再给点时间行不行"，
   不是"预算内救不救得回"。

## 4. 预注册的判读

在跑之前写死：

| 结果 | 判读 |
|---|---|
| 有臂显著优于 `control_new_noise`，且救回率随剩余预算上升 | **提前量有价值**，检测→干预闭环成立 |
| 有臂显著优于基线，但与剩余预算无关 | 干预有用但**不需要早报**，检测可以简化成到点触发 |
| 全部臂不优于基线 | 这类失败在此策略下不可救；**检测那一侧的全部工作没有下游价值** |
| `route_intervention` 单独有效 | MoE **不只是读出**，这是本项目最强的结论 |

第三行是真实可能的结果，而且它会让本 bundle 的全部结论降级为"机制分析"。
**不得因为难看而不报。**

## 5. 与已有否定结果的关系

`horizon_recovery` 那次 0/23 不被本实验推翻，也不能推翻本实验：

- 它测的是**一种**策略（h2 短突发），本实验测五种
- 它用 **+10 延长**，本实验用**原预算**
- 它是 23 个样本，本实验是 300 个分叉点

若本实验也全线为零，那两次独立否定叠加，结论就相当硬了。
