# 发现 02：pre-loop 同一时刻，路由不是冗余的，但也不比物理更强 —— 两者互补

日期 2026-09-04 · 脚本 `route_vs_physical.py` · 结果表 `runs/route_vs_physical/{summary,models,deltas,univariate}.csv` · 审计 `runs/route_vs_physical/meta.json`

## 结论（三选一）

**"路由携带增量信息"成立，但"路由优于物理"不成立。** 在语料 A 上，路由+物理的
分组 CV AUC 显著高于纯物理（matched Δ=+0.087，95% CI [0.025, 0.158]；pooled
Δ=+0.047，CI [0.026, 0.076]，两个口径的 CI 都排除 0）——所以路由不是物理特征的
冗余复述。但**镜像检验同样成立**：物理在路由之上也有增量（Δ=+0.069，CI [0.035,
0.122]，maxT p=0.0014），而两者单独对决时统计上打平（Δ=+0.017，CI [−0.064,
+0.097]，p=0.74）。两块 out-of-fold 分数在组内的 Spearman 只有 **0.31**，即它们
几乎在正交地排序同一批轨迹。**正确的立论是"路由是一个与物理观测互补的内部观测器"，
不是"路由比物理看得更准"。** 第二个语料（今天收割的 12 条 trunk）在严格口径下只有
**4 个组 / 4 个事件 / 4 个配对**，所有 AUC 都落在 0.25 的网格上，**数据不足以判定**，
既不能复现也不能否证语料 A 的结论。

## 设计（口径全部复用既有实现，未自造）

- **时刻**：每个 loop 事件出一个正样本，取 `q = loop_onset − 2`。
- **对照**：正典 `all_no_event` —— 同组（A: `snapshot_key`；harvest: `init_state`）、
  **同绝对 query q**、该事件不发生（`loop_onset < 0`）的轨迹。比较集由脚本自建后
  **逐组断言与 `analyze_trainfree_signal_matrix.matched_group_statistics` 完全一致**
  （`canonical_all_no_event_match: true`）。
- **统计单位 = 组**（snapshot / trunk），不是 candidate。所有 CI 为组自助法
  （10 000 次重采样组），置换为组内结局置换 + 组级符号翻转（10 000 次）。
- **因果性**：所有特征在 q 时刻只用下标 ≤ q 的数据。
  - 物理：直接 `import harvest_label` 的 `candidate_query_series` /
    `harvest_query_series`（语料 A 上 352/352 全等的那套抽取），并在两个语料上
    **用抽取结果重新推导 loop onset、要求与权威表逐行相等**（脚本内断言，已通过）。
  - 路由：直接 `import analyze_trainfree_signal_matrix.extract_row_features`
    （L151-235）的 `late_flow_volatility` 与 `route_acceleration`，
    再取 w∈{2,4} query 的**尾随**均值（`tf.rolling_mean`，要求窗口内全有限）。
    harvest 的路由用同一函数跑在 `runs/harvest-pilot/server/routes.zarr` 上
    （只把 `INTERMEDIATE_DIR`/`route_store` 临时指向本目录，绝不写入 trap 树）。
- **物理特征（16 个）**：eef 速度均值/方差、路径长度、迂回度、夹爪开合变化量、
  物体位移、到目标距离及其变化率、"最近接近过的历史访问点"距离，各按 w∈{2,4}。
  其中 `goal_rate_w4` = 正典 `physical_progress`，`eef_speed_mean_w4` = 正典
  `eef_motion`，`eef_tortuosity_w4` = 正典 `physical_loop_ratio`。
- **模型**：(a) 仅路由 / (b) 仅物理 / (c) 路由+物理，L2 逻辑回归（标准化在训练折内），
  **留一组交叉验证**，折内训练行剔除留出组比较集用到的全部行。同时报纯秩的单变量
  AUC。两种口径都报。

**物理特征方向**：所有强物理特征都是"低"侧预示 loop —— 在 onset−2，将要进入 loop 的
轨迹**夹爪开合更少、物体位移更小、迂回度更低**，即"操作已经脱离物体、手臂在空跑"。
路由则相反（波动/加速度更高）。两块信号的物理含义不同，这与它们只有 ρ=0.31 的
组内秩相关一致。

## 泄漏审计（重要）

三个物理特征本质上是 loop 判据的连续松弛，已在所有表里标 `leak_flagged=1`：

- `eef_tortuosity_w{2,4}` = 1 − 净位移/路径长度（正典 `physical_loop_ratio`）——
  对应 loop 判据的"路径长度 ≥ 0.12 而净位移小"这一条；
- `eef_return_dist` = min over j ≤ q−3 of ‖eef[q] − eef[j]‖ —— 对应 loop 判据的
  "非局部回返"首条款，**滞后窗口与规则完全一致（lag ≥ 3）**，只是不设阈值。

结论：**泄漏不是物理块表现的来源。** 去掉这三个特征后，纯物理模型 AUC 从 0.887 变为
0.889（matched）、0.941→0.940（pooled），路由增量从 +0.087 变为 +0.085；单变量里
`eef_return_dist` 只有 0.601、tortuosity 只有 0.70，都不及未标记的 `grip_change_w4`
(0.876) 和 `obj_disp` (0.86)。所有主结论在 clean 子集上原样成立。

## 一个方法学副产品：正典物理对照族低估了物理基线

冻结管线的物理比较项只有 `eef_motion / physical_progress / physical_loop_ratio`。
只用这三个（`phys3_canon`）时物理基线 AUC 仅 **0.695**（去泄漏后只剩 **0.538**），
于是"路由 0.925 远胜物理"看起来是压倒性的（Δ=+0.23 ~ +0.39，maxT p≤0.01）。
**把物理块扩到 16 个同样只用历史窗口的常规量后，物理基线跳到 0.887，差距塌缩到
+0.017 且不显著。** 也就是说：此前跨语料复现里"路由前兆强于物理"的印象，很大一部分
来自物理对照选得太窄。今后任何"内部信号优于物理"的声明都必须对照这个更宽的物理族。

## harvest（12 条 trunk）：数据不足以判定

- 标注：8 loop / 2 static / 2 无事件（`runs/harvest-pilot/labels.csv`），6 个 init-state
  组各 2 条流。其中 i10 与 i01 两组**两条流都 loop**，组内没有对照 →
  严格 matched 口径只剩 **4 组、4 个事件、4 个配对**。
- matched 结果全部落在 {0, 0.25, 0.5, 0.75, 1.0} 上，最大的 det AUC=1.00
  （`phys_goal_dist`，4/4）在 20 特征族里 maxT p=0.88。三模型 CV AUC 分别为
  0.25 / 0.50 / 0.25，Δ(c−b) = −0.25 [−0.75, 0.00]，p=1.00。
- pooled（放弃 init-state 配对，用全部 4 条无 loop trunk 作对照，8 事件 × 4 对照 =
  32 配对）：route4 0.563 [0.333, 0.750]、phys16 0.438 [0.219, 0.643]、
  两者合并 0.438 [0.175, 0.688]，Δ(c−b) = 0.000 [−0.083, 0.083]。所有 maxT p ≥ 0.13。
- **这不是"路由信号在新语料里消失了"**：单变量 `route_lfv_w2` 的 AUC 0.656 的 CI
  [0.333, 0.906] 同时覆盖 0.5 与语料 A 的 0.92，两种假设都无法排除。
- **也不是采集坏了**：harvest 的原始路由标量分布与语料 A 几乎重合
  （`late_flow_volatility` 均值 0.02582 vs 0.02560、sd 0.00339 vs 0.00319；
  `route_acceleration` 均值 0.007280 vs 0.007207；HB 层同为模型 12–15；
  `state_flow_max_deviation` 0.0019 vs 0.0027）。**纯粹是样本量问题。**

要在 harvest 线上做出判定，需要的是**组内既有 loop 又有非 loop 的 trunk**。按当前
命中率（每条流约 2/3 出 loop），2 条流/init 的"混合组"概率约 0.44（本批实测 4/6，
小样本偏高），4 条流/init 约 0.79。要凑到与语料 A 相当的 ≥16 个可用组：
**2 流/init 需要 ~24–36 个 init-state（48–72 条 trunk）；4 流/init 需要 ~20 个
init-state（80 条 trunk），但每组配对更多、组内 AUC 更稳。**
注意**只加流不加 init-state 不增加独立单位数**——独立单位是 init-state 组，
同组多流只是条件重复。

## 对立论的影响

1. "路由是内部观测器"**在弱义上成立**：它携带物理观测里没有的增量信息，
   两块信号近乎正交（ρ=0.31），合并后 AUC 0.974（matched）/0.988（pooled）。
2. **不能再说"路由比物理更早/更准地预示 loop"**：同一时刻单独比较时两者打平。
   E0/E6 里凡是拿"路由 vs 物理"的措辞，都要按这里的宽物理族重写。
3. **E6（MoE 触发器）的正确对照多了一个**：除了"等预算随机触发"，还必须加
   "等预算物理触发（grip_change / obj_disp 低分位）"。否则无法排除"任何一个
   在 onset−2 就变化的量都能触发"。
4. 机制上的一个诚实提醒：q 时刻的路由描述的是**即将执行的那个 chunk 的内部计算**，
   而 q 时刻的物理只描述**已经发生的历史**。路由的增量因此可能只是"动作意图的
   读出"，不必然是"对未来的观测"。要区分这两种解释，需要 E7 那种把 gate 打补丁的
   干预，而不是更多的预测性 AUC。
